## 一、先回答「底层做得怎么样」

一句话：**工程实现扎实，模型表达力偏薄**。这两件事经常被混为一谈，得分开说。

### 1.1 扎实的部分（经得起查）

| 方面 | 实测证据 |
| --- | --- |
| 数据驱动 | 核心 C 不认识任何角色；换 `forms/<形态>/rig.json` 就换一套立绘。少女 103 件 / 15 组 / 26 动作 / 78 参数，Q 版 41 件 / 9 组 / 22 动作 / 41 参数，同一份引擎 |
| 错误定位 | 配置错 → `{file,line,field,message}` 四元组，HTTP 侧回 409 带 `diag`。不是"加载失败"了事 |
| 测试 | `make -s test` = **1058 项 0 失败**；`tools/selfcheck_repo.py` 545 项；素材闸门 `check_assets` 1644 项；另有 ASan/UBSan 目标 `make asan` |
| 无外部依赖 | JSON / PNG / deflate / HTTP / TLS / 配置校验 / 状态机全自己写，第三方只有 `stb_image.h` |
| 确定性 | 多线程分块渲染与单线程**逐字节一致**（`zrig_set_render_threads` 专为对拍留的）；同一 rig 两次导出 rig.json 字节相同 |
| 物理 | `zphys2` 是真 2D 粒子摆链 + 力场（重力/风/阵风/拖动惯性），不是"落后几像素"的伪摆动 |
| 参数层 | 命名对齐 Cubism（`ParamAngleX/Y`、`ParamEyeLOpen`…），表情支持 Add/Multiply/Overwrite 三种合成 |

这些不是自夸：每一条都有命令能复现（见本节末尾）。

### 1.2 薄的部分（这才是要动手的）

| # | 缺口 | 现状证据 | 后果 |
| --- | --- | --- | --- |
| G1 | **没有部件级网格（art mesh）形变** | 部件只有 `m[6]` 仿射 + `bend_x/bend_y` 一维弯曲（`zimg_draw_warp`） | 裙摆、袖口、脸颊只会"整块弯"，做不出"局部鼓起/压扁"。Live2D 的立体感八成来自逐顶点网格 |
| G2 | **没有变形器树** | 只有两层：组（pivot/parent/rotation）→ 部件；部件不能挂自己的形变链 | 想给一缕头发加三节骨头，就得改 C。违背"全部独立部件骨骼" |
| G3 | **组上限 16，少女已用 15** | `zrig.c:22 ZRIG_MAX_GROUPS 16`；`teen` 实测 15 组 | 再加一套服装/配件就爆。这是"扩展性"的硬墙，不是建议 |
| G4 | 部件上限 192（少女 103）、动作 32（26） | 同上 | 同样的余量问题，暂时还能撑 |
| G5 | 无裁剪遮罩 / 无通用混合栈 | 有 `zimg_draw_warp_blend`，但没有 Live2D 的 clipping mask 与乘算阴影层管理 | 发丝压脸、阴影随头动这类效果做不了或不自然 |
| G6 | 素材线可重跑性不足 | Q 版 66 件旧贴图长期是坏的（洋红/白边/内部黑点），直到这轮才有可重跑的配准工具 | "素材坏了没人发现"是这条线的结构性问题，比任何单个缺陷都严重 |

## 二、Live2D 工序 ↔ 本项目对位

用户描述的流程是对的，完整版是七步（官方向：`docs/REFERENCE_NOTES.md` 已收录条目）：

| 步 | Live2D 官方做法 | 本项目现状 | 差距 / 下一步 |
| --- | --- | --- | --- |
| 1 | **全身设定稿**（正/侧/背 + 表情差分），确定头身比与比例 | 有 `design_sheet_*.png`（少女）+ Q 版底图；形态级 `form_art.json` 这轮才建立 | 四形态（少女/萝莉/青年/Q）**只完成 2 个**；侧背视图没有；萝莉/青年无稿 |
| 2 | 按 PSD 分层拆件，一件一 mesh | 脚本拆件（`make_*_parts.py` 30+ 支），有几何/颜色判据 | 拆件靠阈值，缺"拆完自动叠图比对原画"的常驻闸（这轮给配准补了 sidecar） |
| 3 | **每个部件独立 mesh + 挂进变形器树** | 部件有仿射 + 弯曲；组有 pivot/parent | **G1/G2**：这是与用户"全部独立部件骨骼"要求差距最大的一步 |
| 4 | 参数化（ParamAngleX…）+ 三态关键帧 | 78 参数，命名对齐；动作/表情/pose/xfade 都有 | 缺"参数 → 网格顶点"的绑定层（因为 G1） |
| 5 | 物理（摆链、风、惯性） | `zphys2` 5 条链，风/阵风/惯性齐全 | 够用；缺"衣物参与物理"（裙子只有整体摆） |
| 6 | 动作 / 表情 / 口型 / 眨眼 / 视线 | 26 动作、16 表情、viseme、眨眼五态、microsaccade | 动作层已较好；T63.3 表情与身体错时未做 |
| 7 | 导出 runtime（Cubism Core 闭源） | **自己写的 C 引擎**（`zrig.c` 6018 行） | 不能也不许用 Cubism Core；等价能力要自己补（G1–G5） |

**关于"像 Neuro-sama"**：Neuro-sama 的观感来自四条叠加 —— ①逐顶点网格带来的面部体积感
②大量的次级运动（发/裙/耳/尾的延迟与过冲）③输入插值到 60fps ④表情与口型分层的时序错开。
本项目 ②③ 有基础（`zphys2`、T63.1 头身错时），①完全没有，④差 T63.3。**所以第一优先级是 ①**。

## 三、优化清单（按"对观感的贡献 ÷ 改动成本"排序）

### P0（不补就永远做不出"真人互动感"）

1. **部件级网格形变**：部件增加可选 `mesh: {cols, rows, verts: [...]}`；
   顶点位置 = 仿射后的基线 + 逐顶点偏移，偏移由参数曲线驱动（每参数一条 `mesh_offsets`）。
   采样沿用现有的逐像素 `zimg_draw_warp`，改成"按三角形重心插值"。
2. **变形器树**：`deformers[]` 已有骨架（当前是一维量），扩成节点树
   `part → warp → rotate → rotate → root`，每个节点有自己的 pivot 与参数绑定。
3. **抬上限**：组 16→64、部件 192→512、动作 32→96（含 schema 与"超限要报错不许静默丢"的测试）。

### P1（做出来"像成品"）

4. 裁剪遮罩（发丝压脸、瞳孔压在眼白上、舌头压在口内）。
5. 混合模式栈（multiply 阴影 / screen 高光），替代现在"把阴影画进贴图"的做法。
6. 拆件流水线的常驻闸：每个重绘件必须有 `align_redraw` 的 `.align.json` + 叠图证据，
   否则 `check_assets` 判红（这轮已给 `torso_noarms` 落了 sidecar，口径要推广到全部重绘件）。

### P2（形体与产能）

7. 四形态补齐：萝莉 / 青年女性（含设定稿 → 拆件 → rig）。
8. 其余 7 个角色 × 4 形态（第一阶段的终点）。
9. 侧/背视图与"转身"能力（现在只有正面）。
