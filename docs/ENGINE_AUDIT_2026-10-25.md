## 一、先回答「底层做得怎么样」

一句话：**工程实现扎实，模型表达力偏薄**。这两件事经常被混为一谈，得分开说。

### 1.1 扎实的部分（经得起查）

| 方面 | 实测证据 |
| --- | --- |
| 数据驱动 | 核心 C 不认识任何角色；换 `forms/<形态>/rig.json` 就换一套立绘。少女 103 件 / 15 组 / 26 动作 / 78 参数，Q 版 41 件 / 9 组 / 22 动作 / 41 参数，同一份引擎 |
| 错误定位 | 配置错 → `{file,line,field,message}` 四元组，HTTP 侧回 409 带 `diag`。不是"加载失败"了事 |
| 测试 | `make -s test` = **1058 项 0 失败**；`tools/selfcheck_repo.py` 545 项；素材闸门 `check_assets` 1644 项；另有 ASan/UBSan 目标 `make asan` |
| 无外部依赖 | JSON / PNG / deflate / HTTP / TLS / 配置校验 / 状态机全自己写，第三方只有 `stb_image.h` |
| 确定性 | 多线程分块渲染与单线程**逐字节一致**（`zrig_set_render_threads` 专为对拍留的）；同一 rig 两次导出 rig.json 字节相同 |
| 物理 | `zphys2` 是真 2D 粒子摆链 + 力场（重力/风/阵风/拖动惯性），不是"落后几像素"的伪摆动 |
| 参数层 | 命名对齐 Cubism（`ParamAngleX/Y`、`ParamEyeLOpen`…），表情支持 Add/Multiply/Overwrite 三种合成 |

这些不是自夸：每一条都有命令能复现（见本节末尾）。

## 二、Live2D 工序 ↔ 本项目对位

用户描述的流程是对的，完整版是七步（官方向：`docs/REFERENCE_NOTES.md` 已收录条目）：

| 步 | Live2D 官方做法 | 本项目现状 | 差距 / 下一步 |
| --- | --- | --- | --- |
| 1 | **全身设定稿**（正/侧/背 + 表情差分），确定头身比与比例 | 有 `design_sheet_*.png`（少女）+ Q 版底图；形态级 `form_art.json` 这轮才建立 | 四形态（少女/萝莉/青年/Q）**只完成 2 个**；侧背视图没有；萝莉/青年无稿 |
| 2 | 按 PSD 分层拆件，一件一 mesh | 脚本拆件（`make_*_parts.py` 30+ 支），有几何/颜色判据 | 拆件靠阈值，缺"拆完自动叠图比对原画"的常驻闸（这轮给配准补了 sidecar） |
| 3 | **每个部件独立 mesh + 挂进变形器树** | 部件有仿射 + 弯曲；组有 pivot/parent | **G1/G2**：这是与用户"全部独立部件骨骼"要求差距最大的一步 |
| 4 | 参数化（ParamAngleX…）+ 三态关键帧 | 78 参数，命名对齐；动作/表情/pose/xfade 都有 | 缺"参数 → 网格顶点"的绑定层（因为 G1） |
| 5 | 物理（摆链、风、惯性） | `zphys2` 5 条链，风/阵风/惯性齐全 | 够用；缺"衣物参与物理"（裙子只有整体摆） |
| 6 | 动作 / 表情 / 口型 / 眨眼 / 视线 | 26 动作、16 表情、viseme、眨眼五态、microsaccade | 动作层已较好；T63.3 表情与身体错时未做 |
| 7 | 导出 runtime（Cubism Core 闭源） | **自己写的 C 引擎**（`zrig.c` 6018 行） | 不能也不许用 Cubism Core；等价能力要自己补（G1–G5） |

**关于"像 Neuro-sama"**：Neuro-sama 的观感来自四条叠加 —— ①逐顶点网格带来的面部体积感
②大量的次级运动（发/裙/耳/尾的延迟与过冲）③输入插值到 60fps ④表情与口型分层的时序错开。
本项目 ②③ 有基础（`zphys2`、T63.1 头身错时），①完全没有，④差 T63.3。**所以第一优先级是 ①**。

## 六、P0 落地记录（2026-10-25 晚，第六十三问）

用户拍板「先 A = 引擎 P0」。三件事都做完了，**每一项都有闸门和实测证据**。

### 6.1 抬上限 + 撞上限必须报错

| 上限 | 旧 | 新 | 实测用量（少女 / Q 版） |
| --- | --- | --- | --- |
| `ZRIG_MAX_GROUPS` | 16 | **64** | 15 / 13 |
| `ZRIG_MAX_PARTS` | 192 | **512** | 103 / 41 |
| `ZRIG_MAX_ACTIONS` | 32 | **96** | 26 / 22 |
| `ZRIG_MAX_DEFORMS` | 32 | **64** | 25 / 8 |
| `ZRIG_MAX_BINDS` | 512 | **1024** | 172 / — |
| `ZSM_MAX_STATES`（状态机） | 32 | **96** | 与动作表同步 |

**代价（实测，不是估的）**：`sizeof(zrig)` 1,113,992 → **2,491,016** 字节（1.06 → 2.38 MB）。
进程里同时只有一份 rig（`zpet.c` 一次 `zrig_load` 一份），对桌面程序是零头。

**静默截断一并清掉**：旧代码是 `for (i = 0; i < n && r->nparts < ZRIG_MAX_PARTS; ++i)` ——
超出的组/部件/动作被悄悄丢掉，而被丢掉的组名还被后面的部件引用，报出来的是
"父组 'xxx' 未定义"，查错方向完全被带偏。现在判据写在循环里，撞上就报
「组数超过上限 64（含自动补的 root）」这种指名道姓的错误。
负控：单测 `test_rig_limits()` 造了 63 组（+root=64，必须能装）、64 组（+root=65，必须红）、
513 部件、97 动作四个用例；`selfcheck` 新增「没有残留的静默截断循环」静态闸。

### 6.2 变形器树：part → warp → rotate → root

`deformers[]` 从「一张挂在部件上的网格」升级成**节点树**：

```json
"deformers": [
  {"id":"shoulder_l","pivot":[236,470]},
  {"id":"elbow_l","pivot":[275,621],"parent":"shoulder_l"},
  {"id":"arm_l_fore_slim","part":"arm_l_fore","parent":"elbow_l",
   "cols":2,"rows":4,"points":[{"c":1,"r":0,"dx":4}]}
]
```

- 节点自带 `pivot`（画布坐标）与局部变换 `dx / dy / rot_deg / sx / sy`，由**动作通道**
  或**参数 binds** 写入（`{"deformer":"elbow_l","param":"rot_deg","scale":-28}`）。
- 部件这一帧的最终矩阵 = `A_chain · 组矩阵 · 部件矩阵`；链上按"父包住子"连乘。
- 部件也可以用 `"deformer":"<节点 id>"` 直接点名挂到某根链上（整件跟着骨头走，自己不需要网格）。
- 校验：`parent` 必须先声明；纯变换节点必须真的影响得到东西（否则报"影响不到任何部件"）；
  形变器通道不许写 `bend_x/bend_y`。

### 6.3 逐顶点参数驱动（keyform）

```json
{"id":"side_l_kf","part":"hair_side_l","param":"ParamAngleZ",
 "cols":2,"rows":4,
 "keys":[{"v":-1,"points":[{"c":0,"r":0,"dx":-6}]},
         {"v":0},
         {"v":1,"points":[{"c":0,"r":0,"dx":6}]}]}
```

第 0 组是**绝对**位移，其余是相对第 0 组的增量；按**合成后的参数值**（动作 → 表情 → 口型）
在相邻两组之间线性插值。这是与 Live2D「アートメッシュのパラメータキー（キーフォーム）」
对等的那一层：老的单标量 `amount` 只能表达"参数越大位移越多"（一条直线），
做不出"参数到 +1 回到原位"这种回中曲线。
渲染与探针（`zrig_deform_mesh`）**共用同一个求值函数** `deform_vertex_at`，不允许两套口径。

### 6.5 还没做的（诚实清单）

- **父级 warp 网格对子部件的传递**：现在节点树传递的是**刚体变换**（平移/旋转/缩放）；
  Live2D 里"包住若干子部件"的ワープデフォーマ会按**逐顶点位移场**推动子部件。
  我们的做法是让子部件也能挂自己的网格（等价于把形变下放到每件），但不是同一件事。记 G58.8。
- ~~**keyform 插值只有线性**~~：**2026-10-25 T66.11 已做** —— 每段可配名字缓动 / 阶梯 /
  三次贝塞尔 timing curve，单测 `test_keyform_ease()`（含手算值对拍与三种写错的负控）。
- **引擎有了能力，rig 里还没用起来**：`hand_l / forearm_l` 的三节骨、侧发三节链、
