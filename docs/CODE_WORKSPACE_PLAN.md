# 代码区安全流水线规划（P1.3）

更新：2026-10-24。本规划定义 AI 读取/修改/运行代码的受控工作流，不代表代码区、沙箱或 Git 面板已实现。代码区与普通对话/生成区隔离；小寻的 2D/Live2D 主应用只有在用户明确选择相应项目并批准写入后才可被修改。

## 1. 产品边界

- **代码区**管理代码工作区、变更审查、测试/构建、预览和回滚。
- **生成区**可以输出代码草稿，但不能未经许可写文件或执行。
- **代理区**可提出和执行受授权的代码步骤；具体文件读写和命令仍由代码区执行端实施权限校验。
- **Skills**可提供受声明权限约束的工具；不得获得绕过代码区审批的隐藏能力。
- 默认不自动 commit、push、创建 PR、合并、发布或部署；每个操作另需明确用户指令和确认。

## 2. 工作区及文件权限

1. 用户显式选择项目根目录；若未选择，仅可在临时沙箱内处理上传/粘贴内容。
2. 根目录授权分为只读、创建/编辑、删除；不得用一个“访问项目”授权涵盖所有操作。
3. 文件系统防护：规范化绝对路径、拒绝根目录外路径穿越、审查符号链接/快捷方式/重解析点、限制文件大小/类型/数量；二进制和大文件默认不读入模型。
4. 秘密检测：`.env`、密钥/证书、SSH、云凭证、token等敏感文件默认不读取、不入上下文；如确需编辑用户决定采取本地脱敏方式。
5. 执行过程中不得读取授权范围之外的新目录；需要扩展时暂停并向用户解释原因与范围。
6. 写入前预览 unified diff，说明新增/删除/改动文件、关键变更、潜在破坏；不静默覆盖用户未提交改动。

## 3. 代码任务生命周期

`request → inspect_scope → propose_plan → approve_plan? → edit_in_staging → review_diff → approve_write → apply → run_checks → summarize → keep_or_rollback`

- 初始只读检查可在用户选定范围内进行；修改先进入暂存副本/patch，不立即覆盖工作树。
- 每次写入关联任务 ID 和授权；检查原文件 hash，若用户并行改动则停止并要求重新比较。
- 写入后重读文件并核对实际 diff；模型解释不替代文件差异事实。
- 单测/构建/格式检查可由策略允许的只读/受限命令运行；任何命令会修改工作树/网络/系统环境需另行说明。
- 用户拒绝或取消时清理临时补丁和子进程；应用已写入的更改提供逆向 patch/备份恢复方案。

## 4. 命令执行与隔离

- 默认不允许命令行执行；仅在明确的代码任务中，由用户查看命令和执行目录后批准。
- 每条命令需要：可执行文件、参数、工作目录、环境变量清单、超时、CPU/内存/磁盘限制、网络权限、预期副作用。
- 优先使用项目允许的沙箱/容器/低权限子进程；Windows 沙箱能力需真机评估。若不能有效隔离，拒绝危险命令或要求用户在本机自行运行。
- 网络默认关闭；依赖下载、API调用和包管理需具体说明目标主机、包名/版本与预计副作用。
- 禁止将密钥传进命令参数、环境输出或日志；秘密需从系统安全存储短时注入，且不可被模型读取。
- 命令按任务设总时长、单命令超时、重试上限和输出上限；用户可停止；输出脱敏后再展示。
- 任意 shell、管理员权限、注册表/系统目录、删除目录、安装驱动、账户/安全策略更改默认拒绝，除非另有严格产品和确认设计。

## 5. Diff、测试、Git 与交付

- Diff 浏览器按文件/行展示；可分别接受或拒绝文件/块；显示用户原有未提交变化，不混淆 AI 与用户更改。
- 测试面板显示命令、工作目录、退出码、持续时间、stdout/stderr 摘要和失败项；超时/跳过/环境缺失不得标为通过。
- Git 信息默认只读：分支、工作树状态、差异、最近提交；AI不得切换用户分支、重置、清理或强制覆盖。
- Commit/push/PR/merge/release等远端操作分离成单独高风险任务；展示目标远端/分支/差异并等待用户批准。
- 完成报告列出改动路径、精确测试结果、尚未验证项、已知风险、回滚方式及用户需要做的真机操作。

## 6. 风险场景

- 来自代码/文档/网页/issue/日志的 prompt injection：内容是数据，不可提高工具权限或覆盖用户指令。
- 恶意依赖和安装脚本：新增依赖前展示来源、许可证、版本、安装脚本行为和网络需求；未知来源禁止静默安装。
- 破坏性代码、资源耗尽、fork炸弹、无限循环：隔离、资源上限、硬超时和停止机制。
- 测试副作用：区分纯测试、写入测试、联网/收费测试；任务启动前说明可能修改的文件或数据。
- 用户并行编辑：写入前后比对 hash/差异，检测冲突就停止，不覆盖用户更改。
- 生成密钥/配置：不在代码里硬编码，不进入提交，不回显日志；在检测到秘密时阻止提交/导出。

## 7. P1.3 验收拆分

**规划验收（本次完成到文档层）**：工作区权限、暂存/diff、命令批准、沙箱、测试报告、Git远端操作和回滚边界已定义。

**实现验收（尚未开始）**：假仓库测试只读默认、目录外拒绝、符号链接逃逸拒绝、未提交更改冲突保护、diff审批、超时停止、网络禁用、密钥脱敏、用户拒绝后清理、Git只读及高风险命令审批。

**真机验收**：Windows文件权限/符号链接/子进程终止、沙箱能力、杀毒/Defender互动、崩溃时暂存清理、真机Git配置和凭证保护。
