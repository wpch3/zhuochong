## 1. 现状盘点（为什么之前只有手套/锤子）

- 旧版互动是 `zpet_poke` 里写死的 if/else：头部→摸头，身体→抚摸，脚→惊讶，其它→点击；锤子→hammered。
- 动作只有 13 个（idle, focus, head_pat, happy, sad, surprised, hammered, stroke, clicked, dragged, talk, think, sleep）。
- 表情只能靠“眼睛开合 + 嘴”，没有眉毛、脸红、眯眼的独立层；表情拆件被 A/B 决定卡住（见 TASKS T2.1.1）。
- 没有台词、没有情绪状态、没有语音事件接口。

本轮把“触发 → 动作 → 台词 → 情绪”拆成数据（规则表），之后加互动只改配置。

### 2.2 拖动与甩动
- 拖起（dragged）→ 悬空晃腿、台词“带我去哪里呀”；放下（surprised→idle）→ “呼…落地成功”。✅ 已接规则
- 快速甩动（速度阈值）→ 头发飘、晕晕的表情（⬜ 需要速度检测，预览可由 API 模拟）。

### 2.3 道具（用户原话：要更多互动；道具 PNG 属于 UI，见 T2.4.5）
- 道具托盘：小零食、小花束、冰棒、雨伞、小玩偶（每个道具 = 1 条规则 + 1 张 PNG + 1 个动作）。
- 道具拖到角色上：吃东西、收花、撑伞等。⬜ 需要道具 PNG 与动作（动作表要扩充）。

### 2.4 闲置与时间
- 随机小动作：伸懒腰、打哈欠、东张西望、哼歌（⬜ 需要动作）。
- 长时间没人理：“无聊…”，30 分钟后轻微打盹（已有空闲入睡，可加台词）。
- 时间问候：早上/中午/晚上/深夜（需要本地时间与规则 `time_range`，⬜ 待加 kind=time）。
- 整点报时（可关闭，默认关）。

### 2.5 鼠标与注意力
- 鼠标在角色上停留超过 N 秒 → 抬头看你（focus 已有雏形：悬停视线跟随）。
- 鼠标快速来回划过 → 躲开/好奇（⬜）。
- 双击（⬜ 需要双击检测，Windows 层与预览都要实现）。

### 2.6 键盘与全局输入（需要用户授权，默认关）
- 你打字时：角色点头、敲键盘小动作；长时间不打字：困了（⬜，参考 BongoCat 的权限流程，T3.6）。

### 2.7 连击与好感（只存本机）
- 连击累计（摸头、锤击都计数），超过阈值的“彩蛋”台词与动作。
- 好感值（每天上限、只本地保存；不影响任何外部请求）。⬜ 需要设置持久化。

## 3. 话语互动（台词系统）

### 3.1 设计原则
- 台词全部在 `characters/<角色>/dialogue.json`，按 id 引用；互动规则只引用 id，不写死文本。
- 每组台词有多条变体，按顺序轮换（已实现）。
- 节流：`speech.min_gap_s`（全局最短间隔）+ 每条规则 `cooldown_s`。动作不受节流影响，只限制说话。
- `speech.enabled` 总开关；默认开。
- 每条台词都可以附带情绪（`mood`），用来驱动表情（第 4 节）。
- 台词标记 `status`：`draft`（草稿）/`approved`（用户确认）。草稿可以在预览中使用，但对外发布前需要用户确认（本项目规则）。

### 3.2 台词分类（需要补齐的部分）
| 分类 | 说明 | 当前 |
| --- | --- | --- |
| 互动回应 | 摸头、抚摸、锤击、拖动 | ✅ 草稿 |
| 情绪表达 | 开心/难过/惊讶/思考/困倦 | ✅ 草稿 |
| 时间问候 | 早安/午安/晚安/深夜 | ⬜ |
| 闲聊小话 | 随机碎碎念、天气、节日 | ⬜ |
| 语音通话 | 接通、听你说、思考、结束 | ✅ 草稿（回复原文优先） |
| 道具反应 | 吃、收、撑伞 | ⬜ |
| 无聊/求关注 | 长时间没互动 | ⬜ |

### 3.3 与 AI 对话的关系（后续阶段）
- 本地台词表 = 离线兜底（没有网络或 API 未配置时仍有反应）。
- 接入大模型后：回复文本由模型生成，经过同一套“情绪标签”解析后驱动表情与动作；模型回复不可用时回退到台词表。
- Token 上限：每次互动台词生成都计入 token 记录（T3.1）；默认不调用模型，只用台词表。

## 4. 情绪表达

### 4.1 情绪模型
- 情绪集合（先用 8 个，与表情拆件对应）：calm（平静）、joy（开心）、shy（害羞）、sad（难过）、angry（生气）、surprise（惊讶）、think（思考）、sleepy（困倦）。
- 每个情绪有强度（0–1）与衰减时间（比如惊讶 2 秒后回到平静）。
- 同一时间只有一个“主情绪”，其它作为次要叠加（例如开心时眼睛微眯）。

### 4.2 映射
| 情绪 | 动作 | 表情拆件（依赖 T2.1） | 当前可用 |
| --- | --- | --- | --- |
| calm | idle | 平静眼 | ✅ |
| joy | happy | 开心眼 ^^ + 嘴 | ✅ 动作；表情待拆件 |
| shy | stroke / head_pat | 脸红 + 眯眼 | ⬜ 需要脸红层 |
| sad | sad | 下垂眉 + 半闭眼 | ✅ 动作（眼睛透明度）；眉毛待拆件 |
| angry | think（临时） | 竖眉 | ⬜ 需要动作与眉毛 |
| surprise | surprised | 大眼 + 小口 | ✅ 动作 |
| think | think | 视线上移 | ✅ 动作 |
| sleepy | sleep | 闭眼 | ✅ |

### 4.3 情绪来源（优先级从高到低）
1. 用户的直接互动（摸头、锤击）→ 即时情绪。
2. 语音通话中的模型回复标签（call_reply 的 mood 参数）。
3. 时间与状态（深夜→困倦，长时间无人理→无聊）。
4. 默认平静。

## 5. 语音通话时的实时回应

### 5.1 通话状态机（与 airi 的四段结构对齐：STT 端点 → turn → 打断 → 口型）
```
idle ──请求通话(需用户同意)──▶ ringing ──接通──▶ connected
connected ──用户开始说话──▶ listening（focus，视线跟随，点头）
listening ──端点检测（停顿）──▶ thinking（think，小动作）
thinking ──模型开始回复──▶ speaking（talk，口型跟随音频）
speaking ──用户插话（barge-in）──▶ listening（打断当前语音，立即停口型）
speaking ──回复结束──▶ connected（回到 idle/focus）
connected ──挂断──▶ ended（台词“下次再聊”，回 idle）
```
- 每个状态映射到一个动作与一条台词（见 `interactions.json` 的 call_* 规则）。
- 打断（barge-in）必须能在 300 ms 内停止口型与语音（[需真机] 音频延迟需实测）。

### 5.2 对接点（已留接口）
- `zpet_call_event(p, kind, text, mood, now)`：语音模块每次状态变化调用一次。
- `call_reply` 的 text 是模型回复原文（显示为字幕/气泡）；mood 驱动表情。
- 口型：`zpet_set_viseme(...)`（待加，见 T3.3）。目前 talk 动作只有开合嘴的循环。

### 5.3 不做的事
- 不在语音通话中自动发送用户的麦克风数据，除非用户开启语音通话功能（features.json: voice，默认关）。
- 不保存通话录音；文字记录只存本机且可关闭。
- 通话请求由角色发起时必须先弹出同意按钮（社交模块的 `social_call_request`，默认关）。

## 8. 验收口径（每项必须遵守）
- 配置驱动：新增互动只改 `config/interactions.json` 与台词文件，不改代码（用测试验证一条新规则可生效）。
- schema_version 必填；坏配置报文件+字段。
- 台词必须有 `status`；草稿不得标为“已发布”。
- 所有素材过检查（分辨率、透明、洋红/白残留、水印、文字）。
- 测试标签：[测试锁]（单元）、[沙箱实测]（预览 API）、[需真机]（窗口、穿透、音频、光标、动画观感）。不替用户宣布真机项完成。
- 语音相关默认关闭；不保存录音；文字记录只存本机。
