# 项目整体接手审阅记录（2026-10-27）

> 本记录纠正旧交接中的分支元数据，并把项目目标、已落地能力、未完成边界和本次阅读范围留给后续代理。它不是产品规格的替代品，也不表示所有文件或验收都已完成。

## 1. 项目要做成什么

这不是单纯 Live2D 立绘或美术拆件项目。长期目标是一个**桌面原生 AI 伙伴，同时能做真实工作**：

- 有持续、可辨认的角色个性、说话节奏、关系边界和共同经历；可以成为用户长期信任的陪伴者，用户曾把“像女儿或家人”作为愿景表达。
- 能以透明桌宠、动作、表情和语音自然交流；工作时能作为代理，读取用户授权的工作区、规划任务、使用工具、核验结果，并在长任务中保存检查点。
- 可接入本地与云端语言/语音/视觉/图像/视频/3D 能力，使用多 Agent、Skills、MCP/外部工具，最终发展成完整的软件平台。
- 桌宠小窗、聊天/语音、工作区、多模型协作、任务中心、记忆与人格、模型/插件管理和生成能力应协同，而不是互不相通的功能堆。

用户在历史对话中还明确希望它可以在授权范围内于后台推进长期工作、离开时安静、回来后如实汇报。应采用事件驱动、可恢复的任务循环，不是让 LLM 永远轮询或为“像人”而编造 AI 的现实生活。角色演出、虚构设定、真实共同记忆、运行状态与工具记录必须区分。用户使用“真正的人类/家人”的愿景，不等于产品可以宣称 AI 具有真实意识或依赖用户。

## 2. 历史对话材料的阅读

根目录 `讨论对话.pdf` 是扫描图像 PDF（20 页、无可直接提取的文字层）。本次用本地 OCR 读取了其中 20 张不同的聊天截图（PDF 各页重复嵌入同一组图像）；OCR 有错字，不能替代原图逐字校对，但足以核对主题与关键要求。历史对话由“Live2D 手是否偏小、手部造型和 Neuro-sama 对照”展开，用户随后说明项目是 AI 陪伴桌宠 + 工作辅助的完整软件，并提出本地/云模型、键盘模式、多模态生成、语音陪伴、Agents/Skills、多工作区和多 AI 聊天。

历史讨论中反复出现、且仍影响项目的方向：

1. 人格不能只靠一段 prompt；角色要有稳定立场、经历、记忆和因人而异的取舍方式。
2. 长记忆要支持“多年后仍能找回真实共同经历”，不能把模型猜测说成事实；记忆应可追溯、可查看、可管理。
3. “思考区”应以用户可检查的任务计划、工具、进度、依据、错误和成本为主，不把不可用或不适合公开的模型隐式推理伪装成事实。
4. 自主工作须有范围化授权、任务状态/检查点、取消、恢复、验证和准确汇报；删除、公开发布、外发、付费或高风险命令仍需确认。
5. 多 Agent 要有明确分工、隔离上下文、共享经确认的结果，并有轮数/预算/终止条件；Skill 声明不等于权限。
6. 实时语音的关键是低延迟、打断与停止、文字/语音/角色动画状态同步；桌面感知不能默认常开。
7. 桌宠日常体验与完整工作区应分层：桌面入口轻量、自然；后台产品 UI/工作区承载任务和复杂设置。测试台不能冒充最终 UI。
8. 数据可迁移，语言模型更换时用户培养的角色、记忆和项目任务不应随之消失。

这次已阅读与核对较新的产品/平台/陪伴/代理/记忆/人格/隐私/实时与语音规划；项目后续的具体决策应以仓库的当前代码、任务台账和用户当轮指示为准，不应直接照搬历史 AI 建议。

## 3. 当前工程是什么、实现到哪里

当前实现采用 C11 核心、Win32 原生层和 headless C 预览服务；另有 Web 测试台与独立产品视图原型。角色外观、骨架、动作和配置以数据/素材包驱动，工具脚本负责生成、整理和 QA，并不替代出货时的 C 桌宠。

当前已存在的实质性软件能力（以源码和最新任务记录为准）：

- **角色/桌宠引擎**：数据驱动的 sprite rig、层级与网格形变器、参数/keyform、动作/表情导入、动作状态机、视线/眨眼、物理、挂点、穿透/命中相关平台逻辑；Win32 原生与沙箱预览共享核心逻辑。
- **角色认知**：`zpersona` 三层人格自定义及关系档，内心立场档案，`inner.json` 思维档案和可推导的角色差异；`zthink` 有可解释、确定性的反应节奏与主动开口判定。
- **记忆与上下文**：`zmem` 追加式长期记忆/锚点与审计接口；`zctx` 为上下文块做预算、来源和是否随请求发送的清单。界面、权限、跨项目隔离和长期记忆治理仍有未完成项，不可只凭引擎存在就宣称产品闭环。
- **模型链路**：`zgateway` / `zrelay` 已不仅是静态路由规划——项目记录显示已有真实 HTTP 请求、OpenAI-compatible 聊天、多轮上下文、费用/用量记录及 `ztls` 证书校验；当前接口族支持范围仍有限，Native Anthropic/Google 形状适配与提示注入防护仍在任务清单中。
- **语音/多模态/平台**：仓库有供应商契约、配置、生成/语音工具和多份路线规划；配置里出现供应商不代表相应运行时已完成。后台任务恢复、完整权限运行时、Skills/MCP 隔离执行、多 Agent 编排、全面多模态与 3D/三渲二仍须逐项看任务状态和实现证据。
- **产品界面**：`web/product.html` 是独立产品交互原型；当前复杂测试网页是测试台，不是最终桌面产品。透明无边框原生产品窗口及完整工作区仍是不同阶段。

核心代码入口：`src/core/`（`zrig`、`zpet`、`zpersona`、`zmem`、`zctx`、`zthink`、`zgateway`、`zrelay`、`zhttp`、`ztls`、`zphys2` 等）；`src/win32/`；`src/headless/`；`web/`；`config/`、`schemas/`、`characters/`；`tools/`、`tests/`。规划与现状分别查 `docs/PRODUCT_PLAN.md`、`PLATFORM_PLAN.md`、`AGENT_PLAN.md`、`AGENT_ORCHESTRATION_PLAN.md`、`COMPANIONSHIP_PLAN.md`、`PRIVACY_PERMISSIONS_PLAN.md` 和 `docs/memory/`，不要将规划中的能力写成已实现。
