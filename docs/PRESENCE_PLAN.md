## 1. T49 · 视线与跟随要"灵动"（用户原话：脑袋也跟着鼠标动一点点）

**用户的直觉和官方口径完全一致**。Live2D 官方《Motion Quality Improvement Tips》原文：
「只有脸在转会像机器人，要让身体的 X / Z 跟着脸一起动」；
社区那条被反复引用的提醒（Frusumi）：「人转头时头和身体**不会同时同量**地动，
把角度 X/Y 直接绑到体的倾斜会很单调；**让体延迟追随头**才自然」。

### 1.1 现状

`rig.json` 的 `look`：`speed 9.0`，`head {rot 5°, dx 4, dy 10}`，`chest {rot 1.2°, dx 1.5, dy 1}`。
也就是说：**头和胸其实已经在跟了，但它们和眼睛是"同一个平滑器、同一拍"**，
而且幅度是固定比例 —— 所以看起来像"整体缓慢偏移"，不像"看过去"。

### 1.2 要改成三级跟随（T49.1）

| 层 | 跟随延迟 | 幅度 | 实现 |
| --- | --- | --- | --- |
| 眼球 | 最快（≈0.05 s） | 满量程 | 现有 `look_cx/cy` 平滑 |
| 头 | 0.12~0.20 s | 眼球的 60%，**且超过阈值才动**（小幅看眼睛就够） | T47 的"延迟摆"（配方见下） |
| 身体 | 0.35~0.5 s | 头的 25%，上限 2~3° | 同上，再串一段 |

**延迟摆配方**（note.com/ku_shi 的做法，很适合拿来做"追随"而不是"摇晃"）：
> 揺れやすさ＝中等、**反応速度调低**、**収束の速さ拉满** ⇒ 得到一根"几乎不回弹、只是慢半拍"的摆。

这正好能用 T47.1 的粒子内核实现，**不需要再写一套插值**。

### 1.3 视线行为（T49.2）—— 让它像"在看"，而不是"在跟踪"

1. **换视线前先眨眼**（官方 Tips：視線を変えるときはまず瞬きすることが多い）。
   我们已经有 `look_blink`（因转视线而眨眼 + 冷却），要调参并补断言。
2. **阈值与死区**：指针在小范围内动，只有眼球跟；越过阈值头才转；再越过，身体才转。
3. **最大角速度 + 反动**（官方 Tips：人间不能瞬间停住，要有反动和刹车）：
   指针瞬移时，头**追不上**，并在到位时轻微过冲再回正。
4. **注意力会走神**：指针静止 > 6~10 s ⇒ 概率性地把视线挪开（saccade），再慢慢飘回来；
   鼠标移出屏幕 ⇒ 目送到边缘，停 1~2 s，回正。
5. **瞳孔微动**（cgbox：人的眼球不会静止）：常驻 ±0.5 px 的低频抖动，幅度要小到"说不出哪里变了"。

### 1.4 生命感常驻层（T49.3）

呼吸（已有 `ParamBreath`，T47.3 后它会真的驱动摇物）、
重心左右微移、手指极小幅度的动、偶发的"吞咽/歪头"小动作。
**判据：任意 30 秒静置录像里，不许出现两段完全相同的帧序列**（否则就是在循环播放）。

### 1.5 验收

- 鼠标从左端瞬移到右端：**眼球先到位、头迟 0.1~0.2 s、身体迟 0.3~0.5 s**（三条曲线的峰值不同帧）。
- 指针微动（< 阈值）时头部位移 < 1 px，眼球有响应。
- 静置 10 s 内至少发生 1 次自发视线漂移或眨眼，且**不与指针方向相关**。

## 2. T50 · 兽耳娘模式 + 情绪化耳尾

### 2.1 模式开关（T50.1）

兽耳娘 = **一组部件的互斥开关**，和发型轴、衣柜、兜帽同一套机制：

```
/api/pose?group=beast&id=on     → 猫耳 + 猫尾（+ 可选：爪、獠牙、肉球）
/api/pose?group=beast&id=off    → 全部隐藏
```

**真正的成本不在开关，在"关掉之后头顶长什么样"**：现在的头顶是按"有耳朵"画的，
关掉耳朵会露出耳根的遮挡区 —— 这是 DC16「被遮挡区域必须 AI 重绘」的老问题。
所以 T50.1 的素材清单是：**无耳版头顶发壳 1 张**（+ chibi 版 1 张）。

顺带把"多动物"接口留好：`beast=cat|fox|dog|wolf|rabbit`，耳尾各一套素材，
参数 ID 不变（`ParamEarL/R…`），换的是素材不是机器 —— 这和发型轴是同一个结论。

### 2.2 耳朵要会表达情绪（T50.2）

这一条有**学术依据**，不是拍脑袋（电通大 四條ほか《獣耳の感情表現能力》，以及绘画教程口径）：

| 情绪 | 耳朵姿态 | 来源 |
| --- | --- | --- |
| 生气 / 威嚇 | **イカ耳**：向后拉、贴平头部（剪影压扁） | 绘画教程（atam-academy、ichi-up）、动物行为 |
| 惊讶 | 两耳**靠拢 + 后倾** | 电通大论文（覚醒度高） |
| 悲伤 / 恐惧 | 向前倒、或**低速**向外旋 | 同上（快感低） |
| 喜悦 / 兴奋 | 立起 + **快速小幅反复**（动得快＝覚醒高） | 同上 |
| 平静 | 立起，随呼吸微动 | 教程通用 |

### 2.3 耳ピコ（T50.3）

参考 itodaneko 和 Live2D JUKU《ケモ耳の魅力的な作り方》的三步：
- **step1**：耳朵跟头 XY 的立体感 + 揺れ（我们已有 `ear_?_x`）；
- **step2**：**眉毛上下 → 耳朵立/伏**；**眨眼 → 耳朵抖一下**（物理输入接眨眼参数，不是接头部）；
- **step3**（进阶）：说话口型 → 耳朵朝嘴的方向轻微聚拢。

再叠一层**随机抽动**：平均 8~15 s 一次、单耳、70 ms 的快速抖动。
（用户原话"耳朵会抖动"就是这条；现在只有跟头摆，没有抽动。）

### 2.4 尾巴（T50.4）

已有四姿态（relaxed / up / puff / tuck）+ 2 段摆。T47 之后改成**统一一条链 + 情绪调参**：
- 生气：频率↑、幅度↑、根部更硬（"啪啪甩"）；
- 开心：高频小幅；
- 警戒/炸毛：`puff` 姿态 + 摆几乎停住；
- 害怕：`tuck` + 贴腿。
- 常驻：呼吸驱动的慢摆（T47.3 之后**不再需要靠动作假装**）。
- itodaneko 的一条细节值得抄：**尾巴对"体の回転X"的输入要反相**（身体往右，尾根往左）。

## 3. T48 · 外设联动：半身键盘模式 / 手柄模式 / 鼠标模式（bongocat 口径）

### 3.1 参考（查证过的工程做法）

- **ayangweb/BongoCat**（Tauri v2 + Rust，Win/macOS/Linux，Apache-2.0，2.3 万星）：
  内置 **standard / keyboard / gamepad 三套模型**，模型里就是
  `CatParamLeftHandDown` / `CatParamRightHandDown` 这种"手按下"参数 +
  每个键位对应一个 motion；支持导入自定义 Live2D 模型。
- **Bongobs-Cat-Standalone**（Live2D + OpenGL）把输入后端写得很清楚：
  **Windows 低级键鼠钩子（WH_KEYBOARD_LL / WH_MOUSE_LL）**，系统级生效、
  **游戏在前台时也能收到**、**不注入 DLL ⇒ 反作弊一般容忍**；配置里还有
  `cat.breath / eyeblink / track`（呼吸、眨眼、跟随）三个开关。
- **wayland-bongocat**：Linux 侧走 `/dev/input/eventN`，要处理多键盘设备与热插拔。
- 这一脉的源头：MMmmmoko 的 Bongo-Cat-Mver（Windows）、kuroni/bongocat-osu。

### 3.2 我们要做的四个模式

| 模式 | 取景 | 输入 | 表现 |
| --- | --- | --- | --- |
| `desk_keyboard` | **半身（bust）**，贴屏幕下沿 | 键盘 | 左右手交替按下；按键在键盘左/中/右 ⇒ 手的横向位置；长按＝按住 |
| `desk_mouse` | 半身 | 鼠标 | 右手跟光标横移，左键/右键＝按下；滚轮＝手指搓动 |
| `desk_gamepad` | 半身 | 手柄（XInput / HID） | 拇指按键、摇杆方向带动手腕；扳机＝食指 |
| `desk_pen` | 半身 | 数位板（可选，后置） | 握笔姿态，压感＝按下深度 |

### 3.3 工程拆解

- **T48.1 输入事件总线（平台抽象）**：`zinput` 层 → 事件 `{kind: key|mouse|pad, zone, down, t}`。
  Windows：`SetWindowsHookEx` 低级钩子；Linux：`/dev/input`；macOS：后置。
  ★ **隐私硬约束**：只上报"**哪一区**发生了按下/抬起"，**绝不记录键值内容**，
  更不落盘、不联网（BongoCat 把这点写进了卖点，我们直接采纳为红线，见 DC68）。
- **T48.2 半身取景与手部姿态**：复用 `FORM_MATRIX` 的**取景轴 bust**；
  新增手部姿态部件（手按下/抬起 ×2，键盘上的三个横向位置），走现成的挂件插槽机制。
- **T48.3 参数与映射表**：`ParamHandLDown` / `ParamHandRDown` / `ParamHandLX` / `ParamHandRX`
  （命名向 BongoCat 的口径靠，便于以后互导模型）；映射写在**声明式表**里，不改 C 代码。
- **T48.4 节奏与情绪**：打字速度（WPM）→ 专注表情 / 轻微摆头；连击里程碑 → 漫符特效；
  长时间不动 → 趴桌子。
- **T48.5 全屏与游戏礼貌**：前台全屏时自动隐藏或缩小（小伊桌宠的做法），热键恢复。

### 3.4 验收

- 键盘模式：按住 A，左手**在 0.1 s 内**落下并保持；松开回弹；
  连打 10 次/秒不丢帧、不卡住（事件有去抖与合并）。
- 手柄模式：拔掉手柄再插上能自动恢复（热插拔）。
- 隐私：抓一遍进程的落盘与网络，**没有任何键值内容**；日志里只有计数。

## 4. T51 · 表情扩充（用户点名：生气）

现有：中性 / 微笑 / 惊讶 / 难过 / 害羞 等 + 微表情（T44）+ 漫符（T43）。
**缺的就是"有攻击性"的那一档**，而这一档恰恰是陪伴型角色最有记忆点的部分。

| 表情 | 脸 | 耳 / 尾 | 漫符 |
| --- | --- | --- | --- |
| **生气（anger）** | 眉内压 + 眼睑上抬 + 嘴角向下（への字）；`ParamMouthForm` 负向 | **イカ耳** + 尾巴快速甩 | 青筋 💢 |
| **鼓腮不满（pout）** | 单边嘴角（T44.3 的坑）+ 腮鼓 | 耳朵半倒 | 小云朵 |
| **得意（smug）** | 眯眼 + 单边嘴角上扬 | 耳尖抖、尾巴高举 | ✨ |
| **委屈 / 哭（cry）** | 眼泪 + 眉外倒 | 耳朵前倒 | 泪滴 |
| **困（sleepy）** | 半目 + 呼吸变慢变深 | 耳朵松垂 | zzz |

工程上三件事：
1. 表情集走已有的**表情差分 + 加法叠加**口径（Live2D 的 exp3 也是"和默认值的差"再加到动作上）；
2. **情绪要同时改物理参数**（生气＝风阵 + 摆频率↑），这是 T47.3 的消费方；
3. 补上 T43.4 / T43.5 的漫符接线、T44.3 的单边嘴角 —— 它们本来就是 `[ ]`。

## 5. 从别的项目里"能做进来"的东西（用户问的第六件事）

查了一圈开源桌宠与 AI 伴侣（清单与 URL 见 `REFERENCE_NOTES.md` 第四十批），
下面这些是**我们还没有、但值得吃进来**的，按"收益/成本"排序：

| # | 想法 | 出处 | 为什么值得 |
| --- | --- | --- | --- |
| 1 | **语音可打断**（VAD 检测用户插话，立刻掐掉 TTS 并取消在途任务） | Open-LLM-VTuber 把这点做成一等公民 | 这是"像活人"与"像语音助手"的分水岭；我们 voice 队列已有雏形 |
| 2 | **流式 TTS：首句到达就发声** | 同上 | 响应延迟的体感直接减半 |
| 3 | **情境感知**：WASAPI 回环判断在听歌/看视频；前台窗口判断在写代码/逛网页；全屏自动躲 | 小伊桌宠 | 用户要的"陪伴"，核心就是**知道你在干嘛** |
| 4 | **Agent 状态联动**：思考中/执行中/等你/出错 各一个表情 + 进度卡片 | Agent 桌宠（12 个 agent）、CodePet（读 git 与用量做养成） | 我们本来就跑在 agent 工作流里，这是免费的"实时接信息" |

| 6 | **羁绊/养成数值**（好感、精力、心情，随互动与时间变化） | VPet（四维状态）、AITuber OnAir（kizuna） | 让"今天也打开它"有理由 |
| 7 | **多角色同屏 / 群聊** | Open-LLM-VTuber group chat | 对上用户"一个 AI 多个动物娘形象"的要求 |
| 8 | **模型/皮肤的导入与社区目录** | BongoCat（Awesome-BongoCat）、VPet（创意工坊） | 对上"模块化 UI + 自定义" |
| 9 | **点击穿透 + 置顶 + 透明窗口**（桌宠基本功） | 几乎所有项目 | Windows 壳要逐条确认 |
| 10 | **性能分级与帧率上限**（30/60/90/120/144/不限） | Agent 桌宠的设置项；BANDORI-PET 的 30→180 fps 教训 | T30 高分辨率必须配这个，否则高清＝卡 |
| 11 | **屏幕观察（看屏搭话）** | 桌宠工坊、桌面灵 | 明确做成**显式开启 + 本地优先**，默认关 |
| 12 | **插件/MOD 沙箱** | VPet 代码插件、deskpet-studio 的权限清单 | 和我们"UI 模块化"同源 |

**明确不吃的**：云端强绑定、账号体系、把用户内容上传（和我们"本地优先 + 绝对不要豆包"的口径冲突）。
