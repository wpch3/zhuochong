## 一、总体形态（三个进程，一套配置，一份数据）

| 组成 | 技术 | 职责 | 现状 |
| --- | --- | --- | --- |
| ① 桌宠（宠物窗） | 纯 C11 + Win32，零依赖 | 透明小窗、立绘动画、互动、气泡、道具、语音播放与口型 | ✅ 可运行（217 项单测） |
| ② 主工作区（软件主体） | 本机 Web（本地服务 + 浏览器界面） | 对话/工作区/代理/生图/视频/代码/skills/Token 计费/设置 | ⬜ 未开始（本文件的重点） |
| ③ 本地网关（API Gateway） | 本机进程 | 统一转发所有模型/语音/生图请求；**Key 只存本机**；计量与限流 | ⬜ 未开始 |

**为什么要三进程**：透明窗必须轻（C 原生、不闪、不吃 GPU）；工作区需要 Web 生态（编辑器、Markdown、图表）；
网关必须独立（桌面端与工作区共用一套 Key 与计量，且能随时切断外网）。

**事件总线（唯一通信方式）**：桌宠、工作区、网关之间只通过**本地事件**通信（本机回环 + 文件队列）：
`pet.action` / `pet.say` / `chat.delta` / `voice.chunk` / `token.usage` / `task.update` / `tool.request`。
模块之间不直接调用内部函数（沿用交接文件 2.1 原则）。

## 二、功能分区（用户点名的 7 个区 + 我补充的 8 个区）

### 1. 对话区（Chat）
- 多角色对话（7 个 AI 角色 + 自建角色）、会话列表、分支/重试、引用、导出。
- 流式输出、Markdown/代码渲染、附件（图片/文件）、粘贴长文本自动转附件。
- 社交模式（**每项独立开关，默认全关 + 每项 token 上限**）：群聊、循环回答、朋友圈、双角色召唤、角色请求通话。
- 语音联动：每句出声（默认关）、句级同步（Neuro-sama 做法）、逐字高亮仅在供应商给时间戳时启用。
- **缺（要补）**：会话级"人格卡"（角色登场时的自我介绍 + 说话风格权重）、上下文预算表（超限自动摘要）、
  "重新开始/时间线"（redo 分支）、提示词模板库（带变量）、内容安全过滤开关（本地词表）。

### 2. 工作区（Workspace）
- 项目/资料库：把文件、笔记、链接、图片组织成"项目"，供对话与代理引用（RAG）。
- 资料区：角色设定、世界观、素材清单；**本地向量检索**（轻量：关键词 + 小向量模型可选）。
- 便签/待办/剪贴板历史（本地）。
- **缺**：文件监听与自动入库、"引用即插入上下文"的统一接口、内容去重与失效检测、工作区快照（可回滚）。

### 3. 代理区（Agent）
- **代理编排**：任务队列、多步执行、工具调用（function calling）、失败重试、人工确认点。
- **Skills 增加区**：技能 = 一个目录（`skills/<id>/skill.json` + 提示词 + 工具声明 + 示例）。
  用户可**导入/新建/启用/禁用**技能，支持从文本或 URL 生成技能骨架。
- 定时任务（每天几点做什么）、触发器（收到文件→处理）、长任务看护（进度、断点续跑）。
- **缺**：工具权限模型（每个工具需授权，危险操作二次确认）、沙箱执行（文件/命令白名单）、
  代理的"记忆库"（长期记忆 + 摘要 + 手动编辑/删除）、失败归因与回放（同一输入重放 diff）、token 预算熔断。

### 4. 生图区（Image）
- 文生图 / 图生图 / 局部重绘 / 放大 / 抠图（透明背景）/ 批量。
- 图库：收藏、标签、参数回填（seed/prompt）、与角色素材流水线打通（**直接产出拆件候选**）。
- **缺**：提示词配方（风格/线稿/洋红底模板）、生成图质量验收（分辨率/透明通道/色卡/边缘）自动化、
  参考图锁定（img2img 保持取景，解决"表情对齐失败"）、批量生成队列与失败重试。

### 5. 视频区（Video）
- 文生视频 / 图生视频 / 视频转音频（提取音轨）/ 逐帧抽图（供素材使用）。
- **缺（重要）**：本地视频处理链（ffmpeg 封装：抽帧/转码/音频分离）、长任务进度与磁盘配额、
  视频素材入库规范（分辨率/帧率/时长/来源登记）。

### 6. 代码区（Code）
- 代码生成/解释/重构对话、diff 审核（应用/拒绝）、多文件编辑、运行输出展示。
- 与工作区联动：把项目目录挂进上下文（只读索引 + 显式授权写入）。
- **缺**：**执行沙箱**（本机受限运行：超时、内存、目录白名单、网络开关）、Git 面板（状态/diff/提交）、
  终端面板、依赖环境自检（把本项目 `selfcheck_all.sh` 做成界面里的一键按钮）。

### 7. 语音区（Voice）
- TTS（云端供应商 / 本地音色包 / 本地服务）、STT、实时通话（端点检测 + 打断 barge-in）、口型同步。
- 每日字符上限（默认 2000，超限退回文字）、开关默认关、缓存（同句不重复合成）。
- **缺**：播放与混音层（Windows）、录音与降噪、字幕组件、发音回归测试（多音字用例集已发现真实 bug）、
  音色包管理与合规登记（`tools/voice_packs.py` 已有，界面化即可）。

### 8. 桌宠区（Pet）
- 立绘引擎（数据驱动）、13 个动作（要扩到 30+）、互动规则表、好感度分档、台词变体、道具、话题卡片。
- **缺**：动作扩充（伸懒腰/打哈欠/东张西望/哼歌/生气/害羞）、双击/甩动/快速划过检测、
  时间问候（早/午/晚/深夜）、闲置随机台词、道具系统（托盘 + 拖放）、好感与连击的本地持久化。

### 9. 视觉区（Visual）
- 立绘、表情、配饰、主题（两套风格：柔和手绘 / Q 版糖果）、UI 组件素材（全部高清 PNG，禁 emoji/SVG）。
- **缺**：网格形变（mesh warp，做弯腰/扭头）、头发与尾巴的多段钟摆物理、动效时序表（统一缓动曲线）、
  高 DPI 与多屏适配、性能预算（待机 CPU < 2%）、素材版本管理与差异对比。

### 10. Token 计费区（Meter）
- 每次调用记录：时间、功能分区、角色、供应商、模型、入/出 token、费用（单价表可配置）、
  延迟、成功/失败、重试次数；按日/周/月/分区/角色聚合；预算与告警；导出 CSV。
- **缺**：价目表维护（供应商改价要能热更新）、异常用量检测（同一请求重复计费）、
  离线队列（网络失败先记账）、余额查询接口（供应商支持时）。

### 11. 基础功能区（System）——全部是**必需品**，现在都没有
- 设置中心（分区配置、热键、开机自启、缩放、透明度、语言）；配置校验与"一键修复"。
- 数据管理：备份/恢复/迁移/清空（分类：会话、记忆、素材、音色、日志）；存储位置自定义。
- 隐私与权限：**麦克风 / 全局键鼠钩子 / 联网**三项显式授权开关 + 一键断开；沙箱目录白名单。
- 诊断：日志分级、崩溃转储、一键诊断包（脱敏）、性能面板（FPS/CPU/内存）。
- 更新：版本号、变更日志、检查更新（可选，默认手动）。
- 无障碍：字幕、减少动效、字号缩放、色弱校验、键盘全操作。
- 多屏与全屏应用兼容（全屏时不打扰）、勿扰模式、专注计时器（联动桌宠状态）。

### 12. AI 能力扩展区（Skills & Plugins）—— 用户点名的重点
- **三张注册表**：`skills/<id>/skill.json`（技能）、`providers/<id>/provider.json`（模型/语音/生图供应商）、
  `modules/<id>/module.json`（功能模块）。全部声明式，新增不改核心代码。
- 技能可选能力：提示词模板、工具声明（本地函数/HTTP）、需要的工作区资料、token 预算、界面入口。
- **缺**：技能市场（本地导入导出 + 远程清单）、技能依赖与冲突检测、沙箱权限声明、
  技能测试台（给一段输入看工具调用与输出）、版本与回滚。

### 13. 数据与存储（Data）
- 全部只存本机；SQLite（结构化：会话/计量/任务/记忆）+ 文件（素材/模型/日志）。
- **缺**：索引与压缩（历史会话归档）、迁移器（`schema_version` → 升级脚本）、
  加密选项（本地数据库可选加密）、导出格式（Markdown/JSON/HTML 可读可带走）。

### 14. 运维与测试（Ops）—— 项目质量底线
- 已有：`make test`（217 项）、`scripts/selfcheck_all.sh`（六步）、Actions 语音渲染流水线。
- **缺**：把语音/素材/CI 纳入自检、配置 schema 迁移测试、性能回归（启动时间/内存）、
  长稳测试（连续运行 24h 不泄漏）、假服务器接口契约测试（超时/限流/额度/报错）。

### 16. 训练区（Training）—— 音色模型 + AI 模型（用户要求：让工具成为完整工具）
- **四类训练**：图像 LoRA（角色/画风，直接解决拆件风格不一致）、对话 LLM LoRA/SFT、音色训练（导出音色包）、
  嵌入/RAG 模型；另含 STT 微调与路由小模型作为可选项。
- **执行器三选一**：本机 GPU / 远程 SSH 服务器 / 云 GPU（用户自备账号，key 只存本机）。
- **数据集管理**：导入（含视频抽帧/抽音轨）→ 清洗去重 → 标注打标 → 切分（hash 可复现）→ **合规声明闸门**。
- **模型库**：base、方法、超参、数据 hash、评估报告、许可、体积；一键应用（对话/语音/生图/检索）与回滚；强制 model card。
- **评估**：图像角色一致性、LLM 评测集通过率、语音可懂度与基频、检索 Recall@k；人工打分页。
- **详细设计见 `docs/TRAINING.md`（含硬件预算、合规硬规则、任务 T15.1–T15.10）。**

### 15. 交付与发布（Release）
- Windows 安装包（含桌宠 + 工作区 + 网关 + 素材与音色包）、绿色版（解压即用）、
  版本与变更日志、自动更新（可选）、卸载清理、许可与第三方声明页（`docs/LICENSES.md`）。

## 三、模块化与目录（落地结构）

```
app/                主工作区（本地 Web：布局、组件、主题；只消费配置与事件）
gateway/            本地 API 网关（转发 + 计量 + 限流 + Key 管理）
pet/（src/win32）    桌宠（现有 C 代码）
config/             ui.json features.json providers.json voices.json items.json topics.json
characters/         <角色>/character.json forms/*/rig.json outfits/ dialogue.json voice/
skills/             <技能>/skill.json + 提示词 + 工具声明（可无限添加）
modules/            <模块>/module.json（功能模块，默认关闭 + token 上限）
themes/             主题包（颜色/圆角/描边/字体/装饰/动效）
voices/             音色包（model + meta + sample）
train/              recipes/（训练配方） datasets/（数据集清单与 hash） models/（模型库与 model card）
data/               本机数据（SQLite + 文件），不入库
docs/               规格、规划、手册、记忆
```

**三条铁律**（沿用并强化）
1. 新增内容 = 新增目录/配置，**不改核心代码**；
2. 每份配置带 `schema_version`，错误必须指出"文件 + 行 + 字段 + 原因"，不崩溃不静默；
3. 功能模块默认关闭，每个可设 token 上限；危险操作二次确认。

## 九、模组化落地契约（第六十四问：用户点名的「完全可自定义 + 完全可模组」，可机检）

> 用户原话（第四十四问起反复强调，第六十四问再次点名）：**角色、形态、服装、配件、
> UI 主题/布局、道具、话题、模块、provider、声音，一切可定制/可加/模块化，不许动核。**
> 这一节把这句话从口号变成**能在 `make check` 里跑红**的东西。

### 9.1 三句话口径

1. **内容 = 目录**。角色是 `characters/<id>/`，模组是 `mods/<id>/`，主题是 `themes/<id>/`，
   技能是 `skills/<id>/`，音色是 `voices/<id>/`。装 = 拷目录，卸 = 删目录。
2. **清单 = 身份证**。每个包必须有自己的清单（`character.json` / `mod.json` / `theme.json`），
   `id` 与目录名一致，并声明 `schema_version` / `api_version`。
3. **装之前先验**。`tools/mod_lint.py` 在**装载之前**把包查一遍 —— 包写错和引擎坏掉必须分得开。

### 9.2 契约表（每一项都有闸）

| 想加的东西 | 放哪里 | 引擎侧上限（唯一出处） | 闸 |
| --- | --- | --- | --- |
| 角色 | `characters/<id>/character.json` | —— | `mod_lint --all-characters` |
| 形态 | `characters/<id>/forms/<form>/rig.json` | `ZRIG_FORM_CAP 64`（`zrig.h`） | 同上 + `test_zpet_content_scaling` |
| 服装 | `characters/<id>/outfits/<id>.json` | `ZRIG_OUTFIT_CAP 128` | 同上（引用必须能在适用形态里找到） |
| 动作 | `rig.json` 的 `actions` | `ZRIG_ACTION_CAP 96` | 同上 + `ZSM_MAX_STATES` 同步闸 |
| 变形器 / 部件 / 组 | `rig.json` 的 `deformers/parts/groups` | `ZRIG_MAX_DEFORMS 64` / `512` / `64` | selfcheck「没有残留的静默截断循环」 |
| 模组 | `mods/<id>/mod.json` | —— | `mod_lint --all-mods`（api_version / 权限 / 依赖 / 文件清单） |
| 主题、技能、音色、provider | 各自的 `<id>/` 目录 | —— | 各自的 `*_packs.py verify` / `check_platform.py` |

### 9.3 已经落地的四条（第六十四问本轮）

1. **上限只允许有一个出处**：`ZRIG_ACTION_CAP / ZRIG_FORM_CAP / ZRIG_OUTFIT_CAP` 公开在
   `src/core/zrig.h`，`zpet.h` 与 `tools/mod_lint.py` 全部引用它；`selfcheck` 会核对
   「闸里的常量 == 引擎宏」，两处各写一个数字的情况一律判红（LESSONS 405 就是这么栽的）。
2. **撞上限不许静默丢**：`zpet` 扫描 `forms/`、`outfits/` 与动作清单时，溢出会记
   `zpet_forms_dropped / zpet_outfits_dropped / zpet_actions_dropped` 并打 `ZLOGW`，
   不再出现「界面上少两套衣服但没人知道」。
3. **包写错要指名道姓**：`tools/mod_lint.py` 报错带字段名与文件路径（贴图不存在 / 贴图是整张
   不透明（白底烤进去了）/ group 指向不存在的组 / forms.json 声明 ready 却没目录 /
   outfit 引用了不存在的部件 / 动作通道目标解析不了 / 缺 idle）。
4. **闸本身要有负控**：`tools/mod_lint.py --self-test` 造 14 个坏包，每一条都必须判红；
   它已经进 `make check`（`selfcheck_repo.py` ⑳）。

- `api_version` 的兼容策略与迁移工具（当前只认主版本 1）；
- 权限**真正生效**（`net` / `files.write` 走网关拦截，而不是只声明）；
- 主题包 / 技能包的运行时注册。
