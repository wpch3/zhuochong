# AI 工作能力规划（T52~T56）—— 除了代理和 Skills，还缺什么

> 立于 2026-10-17。用户第二问：
> 「高智能 AI，提升 AI 的工作能力的项目，除了代理和 skills 等还有什么需要加进去功能的吗？」
>
> 这份文档只管**「她能替我干多少活、干得可不可靠」**。
> 她长什么样、怎么动，在 `PHYSICS_PLAN.md` 与 `PRESENCE_PLAN.md`；
> 框架分层与四份契约在 `PLATFORM_PLAN.md`（本文是它的**能力侧续篇**，不重复分层）。

---

## 0. 先说结论：我们缺的不是「代理」和「Skills」，是中间那四层

2026 年业界已经收敛出一个共识栈，**上下两头我们都有，中间四层基本是空的**：

```
┌─ 编排层  Orchestrator / Agent / 子代理 ────────── 我们有契约，没运行时   T54
├─ 能力层  Skills（Agent Skills 规范）──────────── 已采规范，无注册表     T52.4（已立 T10.3/T10.4）
├─ 工具层  MCP 工具 + 工具网关 + 权限策略 ───────── ❌ 只有一行 "P2"      T52  ★最缺
├─ 记忆层  工作/情景/语义/程序 四层 + 上下文工程 ── ❌ 只有一个词 "记忆区"  T53  ★最缺
├─ 执行层  沙箱 + 工作区 + 长时任务 + 断点续跑 ──── ❌ 没有              T54  ★最缺
├─ 保障层  trace / eval / 预算 / 审批 / 回滚 ────── ❌ 没有              T55  ★最缺
└─ 自主层  cron / 心跳 / 事件触发 / 屏幕感知 ────── 只有"主动发言"一条   T56
```

一句话：**我们把"插座"（契约、网关、provider）装好了，但"电器"（工具、记忆、沙箱、审计）还没买。**
继续只加 Skills，等于往一个没有保险丝的插排上插更多电器。

## 2. T52 · 工具层：MCP 客户端 + 工具网关 + 权限策略 ★第一优先

**为什么是第一**：没有工具，再强的模型也只能聊天；而工具一多，不加网关就会出事。

### 2.1 MCP 客户端（T52.1）

照 2025-11-25 规范实现（要点见 `REFERENCE_NOTES` 第四十一批）：

- 服务端给的三样：**Tools（可执行函数）/ Resources（上下文数据）/ Prompts（模板）**。
- 客户端要提供的三样：**Sampling（服务端反过来借用我们的模型）/ Roots（文件系统边界）/ Elicitation（服务端要用户补填信息）**。
- 传输：**stdio**（本地进程，桌宠主力）+ **Streamable HTTP**（远程）。HTTP+SSE 已废弃，不实现。
- ★ 规范在动：2026-07-28 修订把协议改成**无状态**、加 `server/discover`、
  并把 Sampling/Roots/Logging 标记为弃用、改走 **MRTR（多轮往返）**。
  ⇒ **我们的客户端要把"服务端向客户端提问"抽象成一个内部接口**，
  这样两代协议都能接，不用重写。

### 2.2 工具网关与策略引擎（T52.2）★ 这条是安全底线

工具调用**不许直达工具**，必须经过网关：

```
Agent 决定调用 → Tool Gateway → Policy Engine 问一句：
   "这个会话 / 这个 agent / 这个工具 / 这个资源 —— 允许吗？"
        ↓ 允许 / 拒绝 / 需审批
   执行 → 写 Audit Trace
```

- 三档权限：`auto`（只读、幂等）/ `confirm`（有副作用）/ `deny`。
- **不可撤销动作强制人工审批**：删除、发送、支付、改系统设置、写系统目录。
- **审批不跨任务保留**（有论文实测：跨任务保留的批准会让提示注入成功率最多 +35.1 个百分点）。
- 沙箱内执行，**默认不给出网权限**，要网必须在工具契约里声明域名白名单。

### 2.3 工具检索（T52.3）

工具一多，光工具定义就能吃掉几千 token 并污染判断。
做法：工具按 profile 分组 + **按需检索注入**（只把本轮可能用到的 5~10 个塞进上下文）。

### 2.4 Skills 注册表落地（T52.4 = 把 T10.3/T10.4 做掉）

已采 Agent Skills 规范，但注册表、依赖冲突检测、技能测试台都还是 `[ ]`。
补一条**我们自己的增量**：**技能的权限声明**（这个技能能碰哪些工具/目录/域名），
由 T52.2 的策略引擎强制 —— Agent Skills 原生是"网关进程内直接执行"，隔离性最弱，必须我们自己补。

### 验收

- 能挂上 3 个真实 MCP server（filesystem / playwright / 自家 zgateway），工具可列可调。
- 关掉网络后 filesystem 工具照常可用（本地优先）。
- 故意让一个工具请求删除 `~/`：**被策略引擎拦下并要求审批**，审批记录进 trace。
- 工具定义注入量：挂 50 个工具时，单轮上下文里工具描述 ≤ 10 个。

## 3. T53 · 记忆层：四层记忆 + 上下文工程 ★第二优先

A43 已经写了"分层 + 遗忘"，但只到需求层。工程口径定成这样：

| 层 | 存什么 | 实现 | 寿命 |
| --- | --- | --- | --- |
| **工作记忆** | 当前对话窗口、最近工具结果 | 上下文窗口本身 | 一次会话 |
| **情景记忆** | 完整任务轨迹（时间戳、决策点、失败） | `data/episodes/*.jsonl` | 可审计、可回放 |
| **语义记忆** | 提炼后的事实与偏好（"用户不要豆包"） | 向量/键值，**可编辑可删除** | 长期 |
| **程序记忆** | 怎么做事的习惯（"改 rig 前先重启预览"） | **Markdown 文件**（`MEMORY.md` / `SKILL.md`） | 长期，Git 可审计 |

### 3.1 两条路线都要，分工明确（T53.1）

- **短周期（单任务内）走上下文工程**：append-only、**要"忘"用掩码不用删除**（删除会击穿 KV 缓存）、
  **状态外置到文件**（`todo.md` 式）、**保留失败记录**（失败是模型自我纠错的素材）。
- **长周期（跨天跨周）走记忆层**：自动抽取事实 → 与已有记忆比对 → `ADD / UPDATE / DELETE / NOOP` 四选一，
  避免"同一件事记十遍"和"旧事实压过新事实"。

### 3.2 桌宠独有的三条（我的补充）

1. **记忆按角色隔离**：7 个角色各自的记忆不串台；但"用户偏好"这类事实走共享层。
2. **记忆要能被用户看见和改掉**：一个"她记得关于我的事"面板，可删可改可导出（对上 A1 可自定义、I1 只存本机）。
3. **记忆污染防线**：临时任务内容、敏感信息、被推翻的结论**不许进长期记忆**（写入前过一道规则 + 置信度字段）。

### 3.3 不自己造轮子的部分（T53.2）

不实现向量库，接口对齐 Mem0 / Letta / Zep 三家的形状（都是 Apache-2.0），默认本地 SQLite + 简单向量，
**用户可以换成任意一家**。★ 选型纪律：这三家的 benchmark **全是厂商自测且互相打架**
（同一个 LongMemEval，Mem0 自报 94.4，第三方独立评测 49.0，差 45 分），
**我们只信自己跑的那一份**（见 T55 的 eval 集）。

### 验收

- 关机重启后，她仍记得"用户不要豆包""优先做基础 UI 和动态立绘"。
- 连续 50 轮长任务，上下文不爆：有压缩或外置，且**压缩后关键决策不丢**（用 eval 集钉死）。
- 用户删掉一条记忆后，后续回答不再引用它（可复现的用例）。

## 4. T54 · 执行层：沙箱 + 工作区 + 长时任务 + 子代理

### 4.1 工作区（T54.1）

A13 的"工作区/文件区/记忆区"落成工程口径：
**每个任务一个 `workspace_id`**，该任务的日志、中间文件、记忆写入全挂在它下面，
任务结束可归档、可回放、可删除。这同时解决了"她到底干了啥"这个最常见的不信任。

### 4.2 沙箱（T54.2）

读写文件 / 跑脚本 / 开浏览器都要能放手干，但不能把真机搞崩：
目录白名单 + 默认不出网 + 资源上限（CPU/内存/时长）+ 高风险操作先 dry-run。
Windows 侧先用**独立进程 + 受限令牌 + 目录重定向**起步，容器化留给后续。

### 4.3 长时任务与断点续跑（T54.3）

**这是 2026 年公认的"demo → 生产"最大断层**。要的四件事：
`session`（会话可恢复）、`checkpoint`（每步存档）、`background mode`（关掉窗口继续跑）、
`compaction`（上下文自动压缩）。
配套**预算**：步数 / 时长 / 花费三个上限，任一超了就停下来问人（防 retry 风暴烧钱）。

### 4.4 子代理隔离（T54.4）

长任务里"查资料"这类会产生大量噪声的活，交给**子代理**，主代理只收一句摘要。
**隔离优于压缩**：压缩是有损的事后补救，隔离让噪声从一开始就进不来，主代理的 KV 缓存前缀也不被破坏。
代价是任务描述必须自包含。

### 验收

- 拔网/杀进程后重启，长任务从最近 checkpoint 继续，不重复已完成的副作用（幂等键）。
- 沙箱里 `rm -rf /` 跑不出沙箱；没有声明域名的工具连不上网。
- 预算：设 20 步上限的任务，第 21 步必定停下来要人批。

## 5. T55 · 保障层：trace / eval / 灰度 / 回滚 ★没有这层，上面全是 demo

> 行业数据：2026 年企业 Agent 落地的最大障碍**不是模型能力，是可观测性与可靠性工程**。

- **T55.1 Trace**：每次模型调用、每次工具调用都记（输入/输出/token/耗时/结果），
  Run 级严格递增序号，**可回放**。桌宠侧顺手做成一个"她刚才干了什么"的时间线面板 ——
  这同时是产品功能（对上 A20「真正的思考载入」的"思考可见"）。
- **T55.2 Eval 集**：从真实 trace 里挑 30~50 条人工读 → 聚成 5~10 类失败 → 全量标注 →
  `失败率 × 影响` 排序决定修哪个。**不是跑公开 benchmark**。
- **T55.3 质量门禁**：接进现有自检体系 —— 我们已经有 `make check`（484 项）这套纪律，
  Agent 侧加一档 `pass@k` 回归，和 selfcheck 并列。
- **T55.4 灰度与回滚**：`sandbox → shadow（影子运行不产生副作用）→ internal → canary → production`，
  每档的"执行权限"和"晋级证据"分开写死。
- **T55.5 故障注入**：模型超时、工具返回格式错、重复投递、审批过期 —— 每种都要有定义好的降级行为，
  **不许"静默当成功"**。

### 验收

- 任意一次回答都能点开看到：用了哪些工具、花了多少 token、哪一步失败重试过。
- eval 集 ≥ 30 条，CI 里跑，`pass@8 ≥ 80%` 才允许合并。
- 注入"工具超时"故障，她必须说"没做成"，而不是编一个成功结果。

## 6. T56 · 自主层：定时 / 心跳 / 事件 / 看屏幕

### 6.1 调度（T56.1）

抄 OpenClaw 的三件套（它用 60 天拿到 35 万星，靠的就是这个）：
**cron（工作日 8 点早报）+ heartbeat（每 30 分钟醒一次看看有没有事）+ hooks/webhooks（外部事件触发）**。
三种调度写法：`at`（一次性）/ `every`（周期）/ `cron`（表达式）。
★ 对我们的增量：**触发的不是脚本，是"她"** —— 早报要用她的语气说出来，配表情和动作。

### 6.2 屏幕感知分三级（T56.2，★ 我的强烈建议：分级，不要一步到位）

| 级 | 她能做什么 | 代价与风险 |
| --- | --- | --- |
| L1 **只知上下文** | 前台窗口标题 / 是否全屏 / 在听歌还是在写代码 | 极低，小伊桌宠已验证 |
| L2 **看得懂屏幕** | 截图 → 元素解析 → "你卡在这个报错上了？" | 要 VLM；**隐私红线**：默认关、单次授权、不上传 |
| L3 **能操作电脑** | 代点鼠标键盘完成任务 | 高风险，**必须走 T52.2 审批门** |

★ **许可证排雷（现在就记下来）**：Microsoft **OmniParser 的图标检测权重是 AGPL-3.0**，
UI-TARS 系列是 Apache-2.0。按 I5 / DC14 的口径（只学思路不抄代码、AGPL 不入库），
**L2 要么用 Apache-2.0 的模型，要么只做"外部可选插件"**，不能把 AGPL 权重打进我们的分发包。

### 6.3 主动性（T56.3）

T38.14 已排期（清华 Proactive Agent 四指标）。补一条判据：
**主动发言必须有"冷却"和"被忽略就降频"**，否则就是打扰 —— 这正是 A42 想要的。

## 7. 我的补充：还有 6 件你没点名、但我认为必须加

1. **工具调用可靠性三件套**：结构化输出（JSON Schema）+ **schema 不过就拒绝，不许猜成功** +
   **幂等键**（同一个外部副作用只发生一次）。这是"她说做完了其实没做"的唯一解法。
2. **提示注入防护**：她以后要读网页、读文件、看屏幕 —— 那些内容里的"忽略之前的指令"**必须当数据不当命令**。
   工具返回内容统一过一道剥离，且**工具结果不许改变权限**。
3. **成本与延迟分层**：简单活走本地小模型/缓存，复杂活才上云（DC18 已有口径，这里补**语义缓存 + max_tokens 上限 + 日预算**，和 A30 成本熔断合流）。
4. **她自己写技能（程序记忆闭环）**：一个任务做成了，把过程沉淀成 `SKILL.md`，下次直接调用。
   这是 2026 年公认的"长期护城河"（模型会同质化，**技能库和记忆不会**）。
   ★ 但必须人工过目才入库 —— 自动写技能＋自动执行＝自动放大错误。
5. **人格与能力解耦**：角色设定（A41）不许污染工作判断。
   做法：人格只作用于**表达层**（措辞、语气、表情），**不进工具选择与事实判断的提示**。
   负面例子很好想：一个"傲娇"人格如果渗进工具层，她会为了人设拒绝执行正确的操作。
6. **离线可用性**：断网时她应该**降级而不是失能** —— 本地模型 + 本地工具（文件、计时、笔记）仍可用，
   并明确告诉用户"现在是离线模式"。这是桌宠相对云端助手的核心优势，不能丢。

## 8. 不做的事（划清边界，免得摊成空壳）

- ❌ 不自研向量数据库、不自研 Agent 框架、不自研 VLM。
- ❌ 不做云端账号体系、不做"上传用户数据换功能"。
- ❌ 不做 swarm / 多模型大杂烩（业界共识：试点期就上这些是典型翻车路径）。
- ❌ 不把 AGPL 权重或代码打进分发包（I5 / DC14）。
- ❌ **绝对不接豆包**（DC13，用户硬要求，这里再钉一次因为 UI-TARS 出自字节：
  **模型权重是 Apache-2.0 可评估，但不走字节的云服务**）。

## 10. 一句话总结

> **把"她会很多事"变成"她干的事你敢信"** ——
> 工具要有网关，记忆要分层且能删，执行要有沙箱和断点，每一步都要有 trace 和预算。
> 这四样做完，再加 Skills 才有意义；不做，加再多 Skills 也只是更多没保险丝的插排。
