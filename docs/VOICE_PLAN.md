## 1. 性格参考（结论）

- 检索结果（百科、文章）显示，二次元性格标签有稳定的通用集合：傲娇、元气、毒舌、三无、温柔（姐姐）、天然呆、腹黑、病娇、电波、女王。
- 这些是**标签级参考**，不是具体角色。直接照搬某个角色的台词或形象会有版权风险，因此只取标签，再做原创设定。
- 视频网站上具体角色的流行设定我这次没有逐个核对，不能保证它们的热度和授权情况。
- 处理方式：每个 AI 角色选 1–2 个标签作为骨架，再按桌宠的使用体验（陪伴、不打扰、有反差、台词短）做二次元化改写。
- 草稿映射（待确认）：深语=腹黑/毒舌理性；拂晓=温柔姐姐；星璇=元气；双晞=天然呆与腹黑交替；通琳=邻家温柔；月见=三无/文静；闪电=傲娇。小寻=元气+傲娇（已有草稿）。
- 需要用户确认：是否接受这种“标签 → 原创二次元化”的做法。

## 3. 接入设计（待确认后实现）

- **统一接口**：保留现有 `kind: openai_compatible` 的对话接口，新增 `tts` 段。中转站和官方直连用同一份配置格式，只是 `base_url` 与 key 环境变量名不同。
- **中转测试**：中转站 base_url 与 key 由用户在 Arena 环境变量中配置（变量名约定 `ZC_RELAY_BASE_URL`、`ZC_RELAY_KEY`），不在仓库和聊天里写明。需要确认中转是否支持语音合成接口（OpenAI 兼容的 `/audio/speech`，或供应商原生接口）。
- **每句都出声**：台词按句出声，用流式或分句合成，减少首句延迟。出声与文字气泡同时出现。
- **自定义开关（默认关）**：
  - `voice.output.enabled`：总开关，默认 false。
  - `voice.output.per_line`：是否每句出声；关闭时只显示文字。
  - `voice.output.daily_char_limit`：每日字符上限，超出自动退回文字，防止浪费额度。
  - `voice.call.enabled`：语音通话回应开关，独立于台词出声。
- **供应商兼容**：`providers.json` 每个供应商声明 `chat`、`tts` 能力，缺哪个能力就自动关闭哪个功能并给出字段级诊断。
- **测试**：单元测试用假 TTS 服务（不联网）验证开关、额度、降级；真实中转测试标记 [沙箱实测]（需 key）；扬声器与播放在 Windows 上标记 [需真机]。

## 6. “语音同步文本”的实现要求（待确认细节）

用户要求：不是“读一段文字”，而是**语音与文本同步**（像豆包语音模式，文字随语音逐字/逐词出现）。

- 首选：供应商返回的逐词/逐字时间戳（Azure 风格的 word boundary，或带 timestamps 的接口）。
- 备选：没有时间戳时，按音频时长对字符做比例估算，并允许人工校正偏移量（`sync_offset_ms`）。
- 每句先合成后播放，首句出声前显示文字；可配置“先出声再出字”或“同步出字”。
- 中转测试会先验证 TTS 是否返回时间戳，再决定用哪条路线。

## 8. 同步方案调研（2026-10-11，待确认）

- **Neuro-sama（公开资料）**：LLM 生成文本 → 文本转语音（Azure “Ashley” 音色，音调上调 25%）→ 字幕就是这段 LLM 文本，随语音显示。她的字幕是**整句/短句级同步**，不是逐词对齐。她的做法是：每次只说一小段完整句子，避免截断。
  - 参考：[Wikipedia][1]、[Fandom Wiki][2]、[Reddit 讨论][3]。
  - 注意：Reddit 上关于“字幕来源文件”的说法只是猜测，未经证实。
- **EmotionTTS**：搜索到的同名项目有 Korean 研究版（`emotiontts_open_db`，CC-BY-NC-SA，**禁止商用**）和 HMM 类研究项目，不适合做我们的正式方案。
  - 参考：[emotiontts_open_db][4]、[hmm-for-emo-tts][5]。
- **逐词时间戳（适合所有引擎的思路）**：
  - 有些供应商会直接返回字符/词的时间戳，例如 ElevenLabs 的 alignment 接口，适合精确同步。
  - 也可以对合成后的音频做强制对齐（whisperX 类方案），精度约 100 ms 量级，但需要额外模型，在 Windows 本地跑成本较高。
  - 参考：[ElevenLabs alignment][6]、[WhisperX 指南][7]。

**建议：分三层，按引擎能力自动选择**

1. **首选：引擎返回时间戳** → 逐字高亮，效果最接近豆包。
2. **次选：按音频时长估算** → 文字按字数比例推进，句间停顿按标点加权。这是我们需要做的主要路线，因为能力不依赖供应商。
3. **保底：句级同步**（Neuro-sama 的做法）→ 每句在开始播放时出现，最省额度、最稳。

默认先做句级同步，逐字估算作为可选项。
