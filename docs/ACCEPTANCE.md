## 一、Windows 窗口与输入（最早需要你上手的一批）

### AC-01 · T8.5 透明窗里的气泡与点击穿透 `[ ]`

- 怎么测：启动桌宠 → 在角色身上点、在角色旁边的空白处点。空白处的点击应该落到**后面的窗口**上
  （比如桌面图标、浏览器），角色身上的点击应该被桌宠接住。再拖动角色、让它压在正在打字的窗口上。
- 算过：① 空白区点击 100% 穿透；② 角色区点击 0% 穿透；③ 拖动时不卡顿（肉眼看 ≈60fps）；
  ④ 聊天气泡弹出时，气泡自己的区域不穿透。
- 不过先查：第十七批查到的结论 —— **Tauri 和 Electron 都没有"按区域穿透"的原生能力**，
  实战做法是 ~60fps 轮询鼠标位置、按 alpha 命中测试切 `set_ignore_cursor_events`。
  先查轮询频率是不是掉了、命中测试用的是不是**当前帧**的 alpha（换动作后 alpha 变了）。
- 沙箱边界：预览服务器里已经有 `/api/region` 做区域命中查询。
  原来记的"没渲染过一帧全返回空"**是记错了**，实测症状是"同一个请求在首帧前后
  给两种答案"（渲染前按画布坐标、渲染后按帧坐标）。2026-10-15 已修（DC29）：
  坐标系固定，并且可以 `space=canvas|frame` 指明，答复里回报换算后的 `cx/cy`。
  命中测试的算法可以在沙箱用静帧验。

### AC-02 · T5.3 输入检测：双击 / 快速甩动 / 快速划过（Windows 层）`[ ]`

- 怎么测：对角色做四个动作 —— 双击、按住快速甩、鼠标从身上快速划过、长按不动。
- 算过：四种手势各触发**不同**反应，且连续做 20 次不误触发（甩动不被识别成双击）。
- 不过先查：阈值是按预览里的像素/毫秒调的，真机 DPI 缩放（125%/150%）会让像素距离变味 ——
  先查阈值是不是按**物理距离**而不是像素算的。
- 沙箱边界：手势判定逻辑已可在预览 API 上实测（`[沙箱实测]`），差的只是 Windows 侧的钩子。

### AC-03 · T12.3 输入检测的立绘联动（Windows 层）`[ ]`

- 怎么测：同 AC-02，但看的是**立绘反应**：甩动时头发/裙摆要有惯性，划过时眼睛要跟。
- 算过：动作切换没有突跳（相邻两帧位移 < 8px），松手后 1s 内回到待机。
- 不过先查：`fade`/`fade_out`（默认 0.22 / 0.2）是不是被动作覆盖了；物理的
  Output Maximum 是否 >100%（第十七批：**>100% 会抽搐**）。
- 沙箱边界：立绘侧 29 项已在沙箱实测有效，缺的只是真实输入源。

### AC-04 · T8.2 全局输入反应（默认关，需显式授权）`[ ]`

- 怎么测：默认安装后确认**开关是关的**；打开后在别的窗口打字，角色应有反应；关掉后再试。
- 算过：关闭状态下，任务管理器里看不到钩子、日志里 0 条输入事件。
- 不过先查：Windows 可能把全局钩子当成可疑行为 —— 先查是不是被杀软拦了而不是代码没跑。
- 沙箱边界：开关与授权状态机可在沙箱用假事件源跑通；真钩子只能真机。

### AC-05 · T9.6 隐私三开关（麦克风 / 全局键鼠 / 联网）+ 一键断开 `[ ]`

- 怎么测：逐个关闭三个开关，然后**用抓包和资源管理器验证**：关麦克风后进程不占麦（Windows 11
  设置里的"最近访问麦克风"不出现）、关联网后无出站连接、一键断开后三项同时失效。
- 算过：**关了就是真关**（系统层面看不到占用），不是只在 UI 上灰掉。
- 不过先查：是不是只停了上层调用、底层 SDK 还握着设备句柄。
- 沙箱边界：开关本身与"关闭后拒绝请求"的代码路径可在沙箱测；**系统层面的占用只能真机看**。

## 二、语音链路

### AC-06 · T22.1 语音链路收尾：能听见 `[ ]`

- 怎么测：点一次"说句话"，听扬声器。
- 算过：**能听见、不爆音、不卡半句**；中文多音字（重、长、行、着）读对。
- 不过先查：Windows 混音层有没有被独占模式占住；缓存目录是否可写。
- 沙箱边界：合成后的 wav 可在沙箱生成并做频谱检查，**但"好不好听"只能你听**（DC12 定的口径：
  音色由你主观验收，我不许自己换方案去推翻）。

### AC-07 · T13.5 播放/混音层 + 播放队列 + 打断（barge-in）`[ ]`

- 怎么测：让角色说一段长话，中途说话打断它；再连续触发三句，看是排队还是叠在一起。
- 算过：打断后 **300ms 内**停声；队列里的句子按序播放不重叠。
- 不过先查：停声是"停止播放"还是"把缓冲区也丢掉"—— 只停播放会把剩下的缓冲继续吐出来。
- 沙箱边界：队列状态机可单测；**延迟和手感只能真机**。

### AC-08 · T7.2 端点检测与打断（<300ms）`[ ]`

- 怎么测：对着麦说一句话然后停。量"停嘴"到"角色开始回应"的时间。
- 算过：**端点判定 < 300ms**，且不会把句中的换气当成说完（20 句里误切 ≤ 2 句）。
- 不过先查：VAD 的 `min_silence_duration`；第二十批查到 —— **原声少停顿时关 VAD 延迟更低，
  多停顿场景开 VAD 的 WER 好 2~3%**，两者要按场景选而不是一把梭。
- 沙箱边界：沙箱**没有麦克风**，只能用预录 wav 喂进去验算法；真人说话的节奏验不了。

### AC-09 · T21.4 实时 STT + 打断（neuro-sama 式回路）`[ ]`

- 怎么测：边说边看字幕；说到一半时角色正在说话，看能不能被打断。
- 算过：**从"说完"到"首字出来" < 800ms**；端点误判率 < 10%；连续说 5 分钟不漂移。
- 不过先查：按 DC17 的参数纪律 —— `beam_size=1`、`condition_on_previous_text=False`
  （不关会假设漂移）、显式指定语言（省 ~50ms/段）、`word_timestamps=False`。
  仍不达标就换原生流式族（NeMo FastConformer，80~320ms lookahead）。
- 沙箱边界：沙箱无麦、无 GPU，**连模型都装不下**（出网白名单没有 HuggingFace）。
  能做的只有：接口契约、假音频喂入、延迟记账字段。

### AC-10 · T16.7 歌声合成（TTS 唱句 + 音高对齐）`[ ]`

- 怎么测：给一句带简谱的歌词，让它唱。
- 算过：**音高对得上**（和参考音轨比，半音内）、歌词听得清。
- 不过先查：TTS 引擎本身不唱歌 —— 要走"合成 + 音高重采样"，先查音高曲线是不是被平滑掉了。
- 沙箱边界：音高提取与对齐可在沙箱用 numpy 验；**好不好听只能你听**。

### AC-14 · T16.2 通知中心与系统通知 `[ ]`

### AC-15 · T22.11 性能与长稳（待机 CPU < 2%、24h 无泄漏）`[~]`

- 怎么测：挂 24 小时，期间正常用。记录开头和结尾的内存、句柄数、CPU。
- 算过：待机 **CPU < 2%**、24h 内存增长 < 5%、句柄数不单调增长。
- 不过先查：轮询类的东西（点击穿透的 60fps 轮询、事件流心跳）是不是没在待机时降频。
- 沙箱边界：**单进程 2 万帧已过**（无泄漏），24h 和真实桌面负载只能真机。

### AC-16 · T17.7 真机侧保险（24h 长稳 + 透明窗/托盘/音频回归）`[ ]`

- 怎么测：每次发版前在你机器上跑一轮固定脚本：开机自启 → 24h → 三类回归。
- 算过：三类回归全过且无崩溃日志。
- 不过先查：崩溃时先看 `logs/` 里的最后一帧参数快照，而不是猜。
- 沙箱边界：回归脚本本身可在沙箱写好并自测，**执行必须真机**。

### AC-17 · T21.2 本地模型自定义区块（列模型 / 调参 / 显存 / 量化档）`[ ]`

## 六、游戏三档（A25，口径由你三次澄清锁定）

### AC-20 · T21.7 档一·观战陪聊（读屏 + 看懂 + 实时回应，**零输入**）`[ ]`

- 怎么测：开一局网游，让它看着。
- 算过：① 能抓到指定窗口；② 看到关键事件会**主动开口**；
  ③ **代码层面不存在输入通道** —— 这条不是"没点"，是搜遍代码找不到发送输入的 API。
- 不过先查：抓窗在独占全屏下会黑屏 —— 先确认游戏是无边框窗口模式。
- 沙箱边界：读屏→理解→开口这条回路可以用**录屏文件**当输入在沙箱跑通（还没做）。
  "代码层不存在输入通道"**已在 2026-10-15 立成常驻闸**：`check_platform.py` 扫全仓
  11 个注入 API 关键词（SendInput / keybd_event / XTestFake* / pyautogui / ViGEm …），
  140 个源文件 0 命中；**闸自带探测器自检**，正则写坏时先报"假绿"再说别的。
  真机要验的只剩"抓得到窗口、看得懂、会开口"。

### AC-21 · T21.11 档二·Minecraft 协议游玩（Mineflayer + 技能库）`[ ]`

- 怎么测：开一个局域网世界，让 AI 以第二个玩家身份进来，下指令让它采集/建造。
- 算过：能进世界、能按指令干活、**代码超时会熔断**（不会卡死在一个任务里）。
- 不过先查：版本协议对不对（Mineflayer 对 MC 版本敏感）。
- 沙箱边界：技能库与熔断逻辑可单测；**进真世界只能真机**。

### AC-22 · T21.8 档三·手柄游玩（虚拟手柄 + 急停 + 逐游戏授权）`[ ]`

- 怎么测：对一个单机游戏授权后让它操作；随时按急停热键。
- 算过：① **急停任何时候可用**（包括 AI 正在连按时）；② 默认只读、每个游戏单独授权；
  ③ **网游进不了这一档**（授权列表里根本列不出来）。
- 不过先查：急停是不是走了同一个事件循环 —— 如果主循环卡住，急停也会卡住，必须独立线程。
- 沙箱边界：授权白名单与"网游不可进档"**可以用静态闸现在就验**；虚拟手柄只能真机。

### AC-23 · T28.1 眼睛不再卡在半闭、立绘不再忽大忽小发糊 `[ ]`

- 怎么测：① 抚摸身体（`stroke`，会 loop）持续 5 秒以上 —— 眼睛应是 **∩ 形笑眼**，
  不是一条没有瞳孔的扁青带；松手回 idle 后眼睛完整睁开。
  ② 连点几次立绘触发不同动作 —— 立绘在屏幕上的**大小不应变化**。
  ③ 对比静止和动作中的脸部清晰度，应看不出差别。
- 算过：眼区瞳孔像素 0.5 档 24→34（+42%）；嘴鼻区锐度在所有动作下与 idle 噪声同级
  （−7.0%~−11.1%，idle 自身 −7.4%）；原生渲染 vs 放大显示的眼区锐度 1641 vs 850。
- 不过先查：带宽不够时自动档会降级 —— **先降帧率到 6fps，再降分辨率**。
  如果用户觉得"宁可糊一点也要顺"，`stage.js` 的 `tuneQuality()` 里把顺序调过来。
- 沙箱边界：**观感只能由用户确认**；可复算的部分（画质百分比、显示尺寸、瞳孔像素）
  已经进 `web-test` / `test_core` / `selfcheck` 三个闸。

### AC-24 · T30.4 抚摸/摸头现在是 ∩ 形笑眼，挥手的肩部缺口仍在 `[ ]`

- 怎么测：① 摸头或抚摸身体，**整个过程**（包括刚按下和快结束那两下）眼睛都应该是
  **∩ 形弯月笑眼**，不该出现"闭着眼但没在笑"的谷型 ∪；② 点"挥手"，**预期仍然有问题**
  ——肩膀和袖子之间会露出背景三角缺口、肘部有硬折痕，这两条是已知缺口 G102/G103，
  本轮只定位没有修；③ 在**本机**打开（localhost）时，立绘应该能放大到接近整屏，
  且不会自动变糊（远程预览仍会降级，这是有意的）。
- 算过：head_pat 时间线的「闭着没笑」问题帧 **4 → 0**，stroke **2 → 0**；
  上臂 −12° 时肩下格子实心率 100% → 14.2%（这条**没修**）；
  本地模式 `QUALITY_SCALES=[1.0]`、`tuneQuality()` 直接 return（web-test 9 项含负控）。
- 不过先查：如果摸头时你觉得「笑眼来得太慢」，是 pulse 的 `dur 0.30`——

### AC-25 · T30.4 画面变流畅了，而且一个像素都没变 `[x]` ✅ 2026-10-15 用户验过：挥手/惊讶/摇摆三个大幅度动作**均无接缝、无撕裂**

  ② 肉眼找**画面有没有横向的接缝、撕裂、或者偶尔闪一下花**——这是分块渲染最典型的翻车方式，
  如果看到了请直接告诉我，那说明哪条带的边界算错了；
  ③ 右键另存一张立绘，用任何看图软件打开，应该是**完全正常的 PNG**（不是半张、不是花的）。
