# P2.3 双角色/多代理协作与冲突仲裁规划

更新：2026-10-24。本文件把“两个角色一起陪伴”和“多个代理共同完成工作”拆成两种产品模式。它们共享轮次仲裁和权限底座，但角色的表演不等于代理的自主执行。本文件是规划，不是实现授权。

## 1. 目标与明确非目标

**目标**：让用户能理解谁在说话、为什么轮到该角色、共享了哪些上下文、任务由谁负责；避免角色互相抢话、循环附和、重复答复、越权和预算失控。

**当前不做**：无限角色群聊、角色互相私下调用工具、代理自授权限、未经确认的跨角色长期记忆、未经用户批准的外部平台发言、用人格设定遮掩模型/代理身份、多个代理共同写同一文件。

## 2. 两种模式，分开配置

### A. 陪伴角色共演（Companion mode）
- 角色是表现/对话身份，不自动获得额外工具权限。
- 一个“主持角色”负责主答；其他角色只有被用户点名、被主持邀请或明确适合补充时才发言。
- 角色档案定义语气、专长和可参与场景，不允许用人设突破安全、隐私或用户明确指令。
- 默认单角色输出；多角色模式由用户打开，可随时关闭。

### B. 任务代理协作（Agent mode）
- 一个协调代理负责任务拆解、权限预检、预算和最终验收；专职代理通过结构化交接提交证据/产物，不进行自由漫谈。
- 每个代理获得任务级最小权限、数据范围、工具白名单和 token/时间预算；额度合计受任务全局上限约束。
- 并行仅用于独立只读/不同文件任务；共享写入须通过协调器排队或隔离分支/补丁，再由用户/主代理整合。
- 所有副作用仍经过统一权限与用户确认门；子代理不能授权其他代理或提升权限。

## 3. 轮次与仲裁状态机

建议单个会话采用：`idle → collect → select → speak/execute → yield → idle`。

1. 用户消息进入后收集有限时窗内的相关事件；过期、重复、被取消消息不参与。
2. 仲裁器依优先级选择：明确点名 > 正在执行任务的负责人 > 用户预设主持角色 > 单角色默认；安全/澄清/阻塞消息优先中断。
3. 每轮设一个“主响应者”；其他角色最多一次短补充，且不能重复主答内容。未被选中者保持沉默，不模拟实时多人在线。
4. 同级候选冲突时采用稳定轮换/用户指定优先级，避免随机争抢；记录选中理由（内部诊断可见，不必展示冗长思维链）。
5. 用户插话、暂停或取消时，停止所有生成和可取消工具任务；不可取消副作用需如实报告状态。
6. 工具结果回到负责代理，不因其完成就自动给其他角色权限或允许公开发言。

## 4. 记忆与上下文隔离

- 默认每角色独立的风格配置；共享会话事实仅存在本轮/会话工作区，不因此写入长期记忆。
- 任务代理只获取任务所需文件/资料范围；交接只包含明确列出的事实、来源、置信度、产物路径、未解决问题和权限状态。
- 角色的私有草稿/中间推理不互相共享；不持久化隐藏思维链。可审计的是结构化行动与证据，不是内部推理全文。
- 长期记忆仅由统一记忆政策控制，按来源、范围、保留期限和用户同意管理；用户可查看、更正和删除。
- 共享信息在界面标明来源与共享对象；敏感资料不进入角色风格提示或无关子代理上下文。

## 5. 冲突规则

冲突排序：系统/安全与法律边界 > 用户当前明确指令 > 任务权限与验收条件 > 已确认用户偏好 > 角色表达偏好。

- 角色观点不一致：指出分歧来自不同假设/证据，标注来源与置信度，必要时提一个澄清问题；不能靠投票产生事实。
- 代理方案不一致：协调器列出方案差异、证据、成本/风险和可逆性；高风险或用户偏好不明时暂停交用户裁决。
- 文件修改冲突：不得最后写入者覆盖；生成可检查的并集/冲突 diff，测试通过后再整合。
- 工具结果与角色意见冲突：以可验证结果为准，并保留不确定性；任何代理不能伪称工具已成功。
- 超预算/超时/死循环：停止新工作，保留可用产物和状态，报告剩余事项，不自动增预算/切换付费供应商。

## 6. 用户控制与界面状态

用户至少可看到：模式（共演/任务协作）、启用角色/代理、当前主持/负责人、各项状态（等待/生成/工具审批/完成/失败/取消）、权限/预算、共享上下文摘要和停止全部按钮。允许设定默认角色顺序、每轮角色上限、是否允许代理并行。

默认值：陪伴模式仅一个角色；代理模式串行、读权限优先、工具与网络按需授权；多角色公开发言、跨代理写操作和外部副作用默认关。

## 7. 验收用例

1. 用户未开启多角色时，只产生一个角色回应。
2. 用户点名角色 B，B 作为主响应者；A 不抢答。
3. 两个角色各自收到同一事件时，只选中一个主答，补充不重复。
4. 用户中断后，所有可取消生成/代理停止；迟到结果不发送。
5. 两代理提出冲突方案时，呈现差异与证据，不悄悄任选高风险动作。
6. 两代理尝试写同一文件时，冲突隔离并产生 diff，不覆盖用户/他人改动。
7. 子代理尝试调用未授权工具、扩大数据范围或分配额外预算时被拒绝并记录。
8. 达预算、断线、超时、重复事件时可恢复状态且不会重复执行副作用。
9. 删除共享记忆/任务后，派生摘要和检索索引按既定生命周期清理。
10. UI 和日志区分“计划”“正在执行”“已执行/验证”，不能把代理交接当作完成。

## 8. 实施顺序与门槛

1. 先在离线模拟器实现仲裁状态机与事件回放；不接平台、不接真实工具。
2. 再做单用户文本共演小原型，逐步验证轮次、取消、重复抑制；允许用户完全关闭。
3. 任务代理协作后做，先只读、串行、结构化交接，再评估隔离并行写入。
4. 每项工具分别授权，外发/付费/不可逆动作需确认；部署前做安全和成本评审。
5. 真机/UI验收按产品计划执行；当前规划无需用户运行测试。
