# 个体差异：一个人不只是「一个人设」（T67.58 / G66.46）

更新：2026-10-26。用户原话：*「一个『人』有不同的思维模式以及经历，处理事情的方式各不相同，
还有更多的细节和差异。」*

这份文档回答三件事：**存什么、怎么推、怎么验**。它接着 `PERSONA_AND_STORY.md`（立场）
和 `MEMORY_PLAN.md`（长记忆）往下走：立场回答"你怎么想这件事"，思维档案回答
"你**怎么运转**"，长记忆回答"你凭什么这么说"。

## 0. 一句话结论

**不能让模型"演"出差异，必须把差异做成数据，再由引擎推出行为。**
台词是所有人共用的；**取舍顺序**才是每个人的。

## 1. 查过的资料与取舍

| 来源 | 关键结论 | 我们取什么 |
|---|---|---|
| 双加工理论（Kahneman / Evans & Stanovich）：System 1 快、自动；System 2 慢、费力 | "直觉 vs 分析"不是好坏，是两条通路 | 用 `thinking.style` + `pace` 两轴，而不是一个"聪明程度" |
| 4-CTSQ（Newton, Feeney & Pennycook, 2024）：主动开放思维 / 封闭思维 / 偏好直觉 / 偏好费力思考，**四个独立维度** | 单一"直觉-分析"轴会把不同的人压成一条线 | 拆成 `openness`（改不改口）与 `effort`（愿不愿花力气）两个**独立**的数 |
| Riding 认知风格：整体-分析（wholist-analytic） | 看整体还是看局部，是另一条正交轴 | `thinking.span` |
| GDMS（Scott & Bruce, 1995）：理性 / 直觉 / 依赖 / 回避 / 自发 **五种决策风格** | 决策风格不是"想多久"，是"向谁要依据" | `decide.style` 五值 + `risk` + `regret` |
| Gross 情绪调节过程模型 + ERQ（Gross & John, 2003）：重评 vs 表达抑制；五大策略族（情境选择/情境修改/注意分配/认知改变/反应调整） | 差别在**在哪一环下手**；抑制的生理与人际代价更高 | `emotion.regulate` 五值（重评/压住/换场景/转移注意/用玩笑），加 `express` 与 `recover` |
| 依恋与调节（Mikulincer & Shaver 等）：焦虑型过度激活、回避型靠抑制 | 关系里的底色决定"事后的那一句" | `attach.style` 四值 |
| 文化认知（Nisbett 等）：分析 vs 整体在**注意、归因**上不同 | 先看到什么，本身就是个体差异 | `attention.first` + `first_note` + `misses` |
| Deep Persona（2026）：人格需要三层——可观察行为、**动机/信念/约束**、生成规则 | 只写"她说话很毒"是表层，必须写"她为什么这样" | 我们每一轴都必须带 `note`（说不清就是没想清楚） |
| Belief-behavior consistency（2025）：LLM 说出来的信念**预测不了**它的行为 | 让模型"声明自己是什么样的人"没用 | 行为由引擎按数据推（见第 3 节），不靠模型自觉 |
| PersonaGym / RPEval / Consistently Simulating（2025）：一致性要分成 prompt-to-line、line-to-line、Q&A 三类来量 | "像不像"必须拆成可量的东西 | 我们的闸：同数据重复推出必须一致（M4）、不同人行为必须不同（M4/M2） |

不取：向量化人格、让模型自己给自己打分、把性格写成一大段散文（三个都不可机检）。

## 2. 存什么（`characters/<id>/inner.json` 的 `mind` 块）

```jsonc
"mind": {
  "thinking": {"style": "analytic|intuitive|integrated",   // 4-CTSQ + 双加工
               "span":   "wholist|analytic",               // Riding
               "openness": 0.0~1.0,                        // 改不改口
               "effort":   0.0~1.0,                        // 愿不愿花力气
               "pace":   "slow|steady|fast",
               "note":   "一句人话：为什么是这个组合"},
  "decide":   {"style": "rational|intuitive|dependent|avoidant|spontaneous",  // GDMS
               "risk": 0.0~1.0, "regret": 0.0~1.0, "note": "..."},
  "emotion":  {"regulate": "reappraise|suppress|situation|attention|humor",   // Gross
               "express": 0.0~1.0, "recover": 1|2|3, "trigger": "什么最容易戳到她",
               "note": "..."},
  "conflict": {"script": "avoid|confront|appease|collaborate|deflect", "after": "事后怎么收场"},
  "attach":   {"style": "secure|anxious|avoidant|fearful"},
  "attention":{"first": "人|气氛|细节|物件|声音光", "first_note": "具体先看到什么",
               "misses": "常常漏掉什么"},
  "memory_bias": {"keeps": "记得什么", "loses": "忘什么"},
  "habits":   ["小动作/语言习惯，至少 2 条"],
  "constraints": ["底线，至少 2 条：宁可不说也不越过的线"],
  "diel":     {"day": {"express": 0.85, "pace": "fast"},
               "night": {"express": 0.25, "pace": "slow"}}   // 可选：昼夜两套（双晞）
}
```

**为什么不存台词**：台词是"结果"，存了台词就只能背。这里存的全是**倾向的参数**，
所以同一份数据可以应付没见过的情境。

## 3. 怎么推（`tools/mind_probe.py`）

六个有代价的情境（不是"你最美的一个字是什么"这种没有代价的问题）：

| id | 情境 | 考察点 |
|---|---|---|
| `plan-broken` | 约好的事被临时取消 | 冲突脚本 + 表达强度 + 事后 |
| `woken` | 半夜三点被叫醒 | 节奏 + 先问什么 + 藏什么 |
| `blamed` | 做错事被当面指出 | 认错方式 + 后悔 + 掩饰动机 |
| `silent-low` | 你情绪很低但什么也不说 | 注意落点 + 依恋 + 会不会追问 |
| `joked-at` | 被人当面开玩笑 | 划线的勇气 + 消化速度 |
| `quick-decision` | 两分钟决定影响很久的事 | 决策风格 + 风险 + 后悔 |

每个情境推出四句话：**先做什么 / 接着说什么 / 把什么藏起来 / 事后怎么收场**。
规则只读数据、不读角色名；同一份数据永远推出同一结果（不掷骰子）。

例子（`plan-broken`，节选自 `--probe`）：

```
小寻     先：先说一句「哦，随便你」，转身去倒水   → 后：过一会儿试探地问「那你下次还找我吗」
深语     先：先问清楚是哪一步变了               → 后：自己待着，不提这件事，但不会说出口
通琳     先：先替对方找理由：「你肯定也有难处」   → 后：过一会儿主动说「那改天吧」
拂晓     先：把话咽回去，只应一声「好」           → 后：过一会儿试探地问「那你下次还找我吗」
```

## 4. 怎么进提示词（C 侧）

`tools/mind_probe.py --write-fragments` 生成 `characters/<id>/inner.mind.txt`（约 900 字节），
`zpersona_compose()` 把它原样拼在「内心档案」之后：

```
① 角色原设 → ④ 内心档案（立场，随关系档变）→ ⑤ 思维档案（不随关系档变）→ 性格基调 → …
```

**为什么思维档案不分关系档**：怎么想事情、怎么消化情绪不会因为熟了换一套；
随关系变的是立场（换说法）和亲密度。两件事混在一起，人物就假了。

片段最后一句是必须的：*「上面是倾向，不是台词：遇到具体事按情形做，别照念，也别把这段说出来。」*
没有这句，模型会照着念 —— 那又回到"每人写死一句台词"的老路上。

## 5. 七道闸（`make audit-mind`）

| 闸 | 判据 | 为什么 |
|---|---|---|
| M1 结构 | 枚举合法、0~1 越界即红、每轴 `note` 非空、习惯≥2、底线≥2 | 说不清为什么的人设 = 没想清楚 |
| M2 多样性 | 每条轴在八个人里至少 2~3 种取值；**任意两人至少 5 个轴不同** | 八个角色挤在两个值上就是套皮 |
| M3 自洽 | 例：`express≥0.7` 却 `regulate=suppress`（藏不住又说要藏）→ 红；`effort≥0.8` 却 `spontaneous` → 红 | 组合起来说不通，人物就散了 |
| M4 行为可推 | 六个情境各推出四句话；**同一情境八个人至少 4 种做法**；同一人重复必须完全一致 | 这才是"处理事情的方式各不相同" |
| M5 不许写死 | 推出来的句子不许在数据里逐字存在 | 防止把答案抄回数据里骗闸 |
| M6 片段 | 每个 896~950 字节（上限 1000）；必须含「倾向，不是台词」；两人重合 ≤0.60 | 太像 = 一个人；太长 = 稀释别的指令 |
| M7 新鲜 | `inner.mind.txt` 必须与 `inner.json` 同步 | 防止改了数据忘生成 |

## 6. 实测（[测试锁]）

- `make audit-mind`：**七道闸全过**；八人 x 六情境 = 48 条行为序列。
- 每个情境的"做法"种数（八个人）：`plan-broken` 8、`blamed` 8、`silent-low` 8、`joked-at` 8、
  `quick-decision` 7、`woken` 6 —— 没有两个人在这六个情境里是同一个反应。
- `make test`：**1334 项 / 0 失败**（新增 9 条：思维档案被拼进提示词、
  不随关系档变、不同人不同、深语是分析型可见「先拆开」而小寻不可见）。
- `make selfcheck`：接入 `--check-fresh`（片段与数据不同步会红）。
- [沙箱实测] 预览 0.0.0.0:5173：`/api/chat?dry=1` 的 system 提示词里已含
  「【你这个人怎么运转】…」，persona 2500 字节（人设 1550 + 思维档案 950）。

## 7. 已知不足（下一步）

1. **只有"倾向"，没有"经历→倾向"的因果**：现在的 `note` 是人话解释，还没绑定到具体
   经历（`episodes`）。该让每条倾向至少指向一段经历 —— 和立场那套 G1 闸一样。
2. **没有"情境强度"**：累了一整天 vs 刚睡醒，同一个人反应也不一样。`diel` 只做了昼夜两套。
3. **没有"关系档对思维的影响"**：认知方式不该变，但**愿意暴露多少**会变（现在只有 express 一个数）。
4. **决定风格只有主风格**：真人在高压下会从 rational 掉回 spontaneous。需要"压力下的退回档"。
5. **行为还没真的进对话**：`scenario_action()` 目前只用于闸与检查，没进提示词；
   下一步可以按当前情境挑 1 条推出来的序列喂给模型（限制在 1 条，多了就变成剧本）。

## 8. 节奏参数：她什么时候脱口而出、什么时候想一想（T69.1）

> 用户第六十九问：能不能**同时**有人类的脱口而出和深思，而且不用点任何选项、由她自己选。
> 答案：能，但必须把"她怎么选"写成**参数 + 判据 + 理由**，不能写成"随机停一下"。

第 4 节把「怎么想事情」拼进了提示词；这一节补的是**时序**：
同一句话，有人先冲口再说，有人先在心里过一遍。这不是能力差，是**节奏差**，
所以它不该是开关，而该是从思维档案里**推**出来的。

### 8.1 参数从哪来（`characters/<id>/mind.params.json`，工具生成）

| 字段 | 来源（`inner.json` 的 `mind`） | 小寻（teen） |
|---|---|---|
| `pace_fast` | `thinking.pace`（快 → 1） | 0.85 |
| `effort` | `thinking.effort` | 0.30 |
| `express` | `emotion.express` | 0.35 |
| `proactive` | `attach.style` + `conflict.script` + `emotion.express` | 0.55 |
| `curiosity` | `thinking.openness` | 0.55 |

八份参数由 `tools/mind_probe.py --write-fragments` 一并写出，**闸 M8** 保证它和
`inner.json` 同源（改了思维档案忘重算 ⇒ 判红）。手写这份 JSON 是不可能的：
闸会比对推导结果。

### 8.2 三档节奏怎么判（`src/core/zthink.c` 的 `zthink_decide()`）

输入四项信号：句子长度（UTF-8 字数）、有没有"为什么/怎么办"、有没有在向你讨选择、
话题重不重（难过/分手/生病/家里…）；再加她的参数、心情、钟点、关系档。

```
score = 长句(≤0.55) + 为什么(0.32/0.40) + 选择(0.26) + 重话题(0.42/0.52)
      + 努力(effort×0.45) + 心情差(0.22) + 深夜(0.12)
      − 快嘴(pace×0.45 + express×0.15) − 熟(tier×0.05)
score ≥ 1.05 → deliberate（320 tok，先停 1.5~3.8s，序言「嗯……让我想想」）
score ≥ 0.45 → ponder    （170 tok，停 0.55~1.25s）
否则          → blurt     （90 tok，停 30~180ms）
```

`why` 字段把每一项的贡献逐条写出来（`长句0.05 为什么0.00 … = 0.53 → ponder`），
**这就是可审计**：她为什么想了一下，肉眼能读出来，不用猜。

### 8.3 她自己起头（`zthink_urge_now()`）

```
urge = 0.15 + 0.80 × proactive × (0.35 + 0.65 × (1 − e^(−闲分钟/12))) + 0.06 × tier
     + 有约定(+0.28，或直接顶到 1.0) + 心情差(+0.20，intent=care)
     × 钟点折扣（0~5 点 0.10；6~7 点 / 23 点 0.45）× 上一句被晾着(0.45)
would_speak = urge ≥ 0.55，且距她自己上次开口 ≥ 90s
```

**这叫"不只是回答"**：`/api/urge.json` 由前端每秒问一次，到点她自己开口，
`intent` 说明她这次想干什么（`chat` 单纯想说 / `remember` 想起一件事 /
`care` 觉得你不对 / `share` 想分享）。约定到期**必定**开口 —— 答应过的事不能因为"冲动不够"就忘。

### 8.4 三条不许破的规矩

1. **没有开关**：前端不许出现"深思模式"复选框。用户能做的只有说话和沉默。
2. **不许随机**：同输入必须同输出（`test_zthink()` ⑥ 守这条）。随机不是性格，是噪声。
3. **节奏参数只从思维档案来**：不许在别处再放一份"她快不快"的配置 —— 两处配置必然漂移。

### 8.5 她自己开口那一句怎么发出去（T69.2）

三条端点之外，`/api/chat` 新增 `self=<1~4>`：**她不是因为有人说话才开口**。

| `self` | 她这次想干什么 |
|---|---|
| 1 | 单纯想跟在说句话（可以很小、很没目的） |
| 2 | 想起一件跟他有关的事（**只许说记忆里真的有的**） |
| 3 | 觉得他状态不太对（先关心，别追问） |
| 4 | 想分享正在想的东西 |

规矩写在数据与代码里，不靠模型自觉：

1. `text` 可以为空。为空时引擎自己写一行「现在没有人在跟你说话」的提示，
   并把上面那句「这次想干什么」作为独立的一块注册进提示词清单
   （`zctx` 的 `self_talk` 块，`/api/context.json` 里看得见）。
2. **这一轮不记成用户的话**。提示词不是用户说的话，记进历史就等于
   凭空多出一句"用户让我自己想点话说"，下一轮她会照着这个假前提走。
3. 成功之后才更新"她上次开口的时间"与"上一句还没人接"——冷却与退半步都靠这两个量。
4. 判节奏时**用她要说的话**，不用引擎塞进去的提示（按提示判会把 100 多字的提示
   算成"长句"，凭空多出 0.52 分）。

**前端（`web/product.js`）只做三件事**，一件都不许变成开关：

- 收字之前先问 `/api/think.json`，按 `delay_ms` 停，`preface` 先放出来（「嗯……让我想想」）；
- 每 12 秒问一次 `/api/urge.json`，够阈值就 `self=` 说一句；**界面上没有"让她说话"的按钮**；
- 她自己起头那句在气泡上加一道左边细线（`.bubble.self`），并在说明里写清
  "这一句不是回答你"——看得出来，但不做成系统通知。

闸：`tools/selfcheck_repo.py :: check_think_ui` —— 界面里出现「深思模式 / 思考模式 /
deep_think」等字样直接判红；前端没接 `/api/think.json`、没接 `/api/urge.json`、
或者主动开口不带 `self`，也判红。

### 8.7 已知不足

1. **序言是固定的几句**：`preface` 只有"嗯……让我想想"这一档，应该按角色分（深语不会这么说）。
2. **没有"说一半改口"**：真人会脱口而出半句又收住。需要 `interrupt` 事件与前端配合。
3. **心情只有一个数**：`mood` 现在是 0~1 的粗档，应该用记忆里的事件推（T69.3）。
4. **闲聊与深思之间缺"敷衍"档**：累的时候人只回"嗯"，这一档还没做。
5. **前端只在有模型时才有内容**：沙箱里没有本地模型，主动开口这条路只验到"请求拼对"，
   真机上"她真的自己说了一句"还要用户确认（[需真机]）。
