# 工作区信息架构与关键流程（P1.1）

更新：2026-10-24。本文定义产品区块职责和首批桌面流程，用于后续原型/视觉设计前对齐；不代表 UI 已实现或视觉方案已获确认。桌宠悬浮角色与工作区职责分离，现有 Live2D/2D 角色区域保持轻量且独立。

## 1. 产品外壳与导航

### 常驻外壳
- **桌宠浮窗**：始终可见的角色、轻量互动、状态气泡、静音/暂停入口；不承载完整工作区。
- **主工作区**：通过托盘/快捷入口打开；对话、任务、生成与代码等复杂操作在此完成。
- **托盘/系统菜单**：显示运行/暂停、打开工作区、角色可见/隐藏、静音/勿扰、退出；高风险设置不放在单击即执行的位置。

### 主工作区候选导航（首轮不超过 7 个一级项）
1. **首页**：继续上次任务、快捷新建、角色状态与权限提醒；不主动展示无必要的仪表盘数据。
2. **对话**：文本/语音会话、上下文/引用、停止和会话管理。
3. **任务**：统一待处理、进行中、等待确认、失败、已完成；任务详情含步骤、进度、成本及产物。
4. **创作**：生图/生文/生音频/生视频的输入与结果；代码生成只允许转交代码区安全流程。
5. **代码**：项目选择、变更 diff、测试/预览、命令审批与回滚。
6. **代理与 Skills**：代理配置/委派、技能管理/权限审计；信息架构评审时可合并为“自动化”。
7. **资料与记忆**：来源和本地记忆的查看/修正/清除；用户确认后可与对话侧栏合并。

全局设置作为顶栏/侧栏固定入口，包括角色外观、模型与供应商、语音、权限与隐私、费用、诊断、无障碍、更新。**是否把代理/Skills、资料/记忆作为一级导航仍待原型验证**，不预设最终视觉布局。

## 2. 核心对象及信息归属

- **会话**：按用户可见的对话线程组织；可选上下文与记忆来源；独立删除/导出。
- **任务**：可由对话或模板发起；状态、步骤、权限、预算、产物、日志摘要、失败原因与取消动作集中展示。
- **产物**：图/文/音/视频/代码差异；保留创建来源、版本、许可/引用和导出方式。
- **代理运行**：任务的执行者/编排视图，不另造一份与任务冲突的状态；代理、Skill 和每一步调用均关联任务 ID。
- **权限授予**：不属于会话内容；在权限中心集中管理、可撤销，单次授权显示其范围。
- **记忆/知识**：与原始会话分离，显示来源、时间、可信状态与删除影响；默认为用户可控。

## 3. 首批关键用户流程

### FLOW-01 首次启动与隐私基线
1. 展示角色/桌宠与主工作区的区别，以及当前可用功能。
2. 用户选择本地角色素材或稍后设置；不强制联网、不要求麦克风。
3. 介绍模型供应商/Key 的本机设置位置，不索取或显示密钥内容。
4. 语音、屏幕、全局输入、平台连接、代码执行、长期记忆维持关闭；用户以后逐项开启。
5. 进入首页，可立即使用无模型依赖的桌宠互动。

### FLOW-02 新建文本对话
1. 从对话区或首页输入；明确当前对话将发送到哪个供应商，或标明本地处理。
2. 请求前按权限策略选上下文；来源摘要可检查/移除。
3. 显示“排队/生成/完成/错误”；随时可停止；失败说明是否重试会产生额外成本。
4. 答案可复制、重新生成（先显示预算影响）、保存成任务或删除会话。
5. 不默认把对话转为长期记忆；记忆建议需用户明确接受。

### FLOW-03 创建生成任务
1. 选生图/文/音/视频类型或模板。
2. 填写输入、参考素材、模型与输出位置；显示供应商、权限和成本/额度提示。
3. 运行前预览参数与预计影响，任务进入统一队列。
4. 显示排队/运行/部分完成/失败/取消；可停止和重试，重试说明可能再次计费。
5. 结果落本地、显示元信息/来源/格式/许可提醒；用户主动导出或交给其他区块。

### FLOW-04 代码任务（高影响步骤需审批）
1. 选择/创建受限工作区；先让代理读取和分析，不默认写入。
2. 展示计划、允许读取的目录、预计命令/网络需求和预算。
3. 提交前预览 diff；用户逐项批准写入。
4. 测试/构建在受限环境运行，命令与输出可见；支持停止、超时和回滚。
5. 汇总改动文件、测试精确结果、未执行项和人工复核点；默认不 commit/push/发布。

### FLOW-05 委派给代理/Skill
1. 用户给出目标；代理先给步骤和所需工具/权限，不隐式扩权。
2. 用户选择代理/模板和任务预算；多个步骤显示依赖关系。
3. 只在触及新权限或高风险操作时暂停请求确认；审批对象和后果清楚。
4. 用户可暂停、取消、检查步骤或等待结果；错误不会无限自动重试。
5. 完成前按原验收条件逐条核对，交付可打开的产物/差异和测试结果。

### FLOW-06 开启语音会话
1. 用户在对话区主动开启语音并授予麦克风权限；显示明确采集状态和停止按钮。
2. 展示转写（若用户开启），确定端点后生成回复；用户插话立刻取消旧轮次与旧 TTS。
3. 文本、字幕、语音与角色说话动作关联同一 turn；TTS失败时保留文字。
4. 挂断后释放麦克风、取消队列、清理音频缓冲；默认不保存录音。

### FLOW-07 用户管理记忆与授权
1. 用户在资料/记忆区或单条建议中查看记忆来源、时间、范围和置信度。
2. 可编辑、删除、设置过期、导出；删除时解释摘要/索引/缓存是否也会清除。
3. 在权限中心分别打开/撤销麦克风、目录、平台、网络等权限。
4. 撤销后停止采集/新请求并取消队列；不静默切换到另一个供应商或账号。

## 4. 全局状态与界面反馈矩阵

| 状态 | 必须说明 | 可执行操作 | 禁止行为 |
| --- | --- | --- | --- |
| 空状态/未配置 | 下一步如何开始、是否需要供应商/素材 | 进入设置、使用本地互动 | 不假装服务已连接 |
| 排队 | 正在等待何种资源、可否取消 | 取消/查看队列 | 不显示虚构百分比 |
| 运行 | 当前阶段与已授权范围 | 停止/暂停（支持时） | 不隐藏外发/代码动作 |
| 等待用户确认 | 将做什么、影响范围、成本/不可逆性 | 批准/拒绝/修改 | 不自动超时批准 |
| 部分完成 | 哪些已产出、哪些失败 | 查看/继续/清理 | 不把部分结果说成全成功 |
| 失败/超时/限流 | 失败阶段、是否可能计费、恢复选项 | 重试/改供应商/停止 | 不无限自动重试 |
| 已取消/过期 | 哪些处理已停止，远端处理是否可保证停止 | 关闭/重开任务 | 不让迟到结果覆盖新轮次 |
| 权限拒绝/撤销 | 哪项能力被关闭及其影响 | 重授权/改用低权限路径 | 不阻止用户使用无关功能 |
| 无网络/模型不可用 | 本地替代与能力边界 | 重试/离线继续 | 不伪造模型回答 |

## 5. P1.1 设计交付与验收

**信息架构规划已完成到文档层**；接下来视觉设计前需做低保真原型并由用户评审。

原型至少覆盖：首页、对话、任务详情、生成任务、代码 diff/审批、权限中心、陪伴浮窗的状态关联。验收：
- 新用户无需麦克风/Key/账号也能完成首次启动和桌宠互动；
- 从创建到取消/失败/完成的任务状态可理解；对话、任务、产物、审批关系不混淆；
- 权限、费用、外发位置可在执行前知情；高风险动作不会被一个普通“继续”按钮隐式批准；
- 桌宠悬浮窗不塞入工作区全套功能，气泡/字幕不挡脸，透明区穿透交由现有窗口测试流程；
- 视觉设计仍遵循现有设计稿先审后实现、素材 REF-FIRST 及项目 UI 约束；本文件没有批准任何具体视觉稿。
