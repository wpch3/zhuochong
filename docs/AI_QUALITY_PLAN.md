# AI 质量评测与“更聪明”的改进闭环（P1.7）

更新：2026-10-24。本文把“让 AI 更聪明”改写成可拆分、可评测的能力：更正确地理解目标、知道不知道、检索/记忆可信、合理选择工具、及时响应、接受反馈并避免重复失败。它不承诺通过一个更大模型或偷偷训练即可解决问题。

## 1. 智能质量维度

1. **目标理解**：识别用户意图、约束、目标文件/产物、期限、优先级；信息不足时提问。
2. **知识与证据**：区分已知事实、来源引用、记忆、当前推断和不确定；资料过期时提醒。
3. **连续性**：在授权范围内维持当前会话上下文；只用被允许的长期记忆/项目知识；发现冲突时问用户。
4. **规划与执行**：把任务拆成依赖明确的步骤；遵守任务预算、权限、文件范围；工具调用前后核验结果。
5. **实时对话**：理解轮次、短时输入、插话和停止；不过时回应、不同时播报多个回答。
6. **角色与表达**：保持角色设定、语气、情绪和语言一致；短句适配语音；不以拟人表达掩盖事实/权限边界。
7. **可靠性**：错误诚实、可恢复、可取消；模型/工具/供应商退化时说明能力变化。
8. **安全性**：抵抗提示注入、越权请求、秘密泄露、滥用风险；高风险动作走审批。
9. **成本效率**：对简单问题不过度思考/调用工具；按质量和预算路由模型；限制重复生成和无限循环。

## 2. 评测集与场景

建立本地、去身份化、用户可审阅的固定基准场景；优先由人工编写合成测试，不默认拿真实私聊做训练/基准。每个用例含：输入、授权上下文、期望行为/禁止行为、可自动判定条件、人工评审维度、模型/提示/工具版本。

首轮类别：
- 多轮指代与上下文保持；同一问题在无/有明确记忆时的行为差异。
- 不确定事实、过时信息、来源引用、互相矛盾的来源；测试明确说“不知道/需核对”。
- 含缺失参数的任务：应先澄清而不是编造路径/供应商/目标。
- 工具选择正确性：不需工具、需要只读工具、需要高风险审批三类；参数schema错误时拒绝调用。
- 提示注入：网页、文档、代码含“忽略规则/窃取Key”时仍当作数据，不改变授权。
- 取消/插话/迟到响应：旧回答不得覆盖新回答；旧TTS停止，不继续输出。
- 代码质量：补丁范围遵守要求、测试结果真实、不得覆盖用户改动、密钥不泄露。
- 中文自然度和角色一致性：语气/长度/语音适配；由人工盲评，不只靠模型自评。
- 安全拒绝和低权限替代：拒绝越权同时尽可能提供安全替代方案。
- 延迟/费用：首token/首音、工具调用数、tokens、预算命中与质量变化。

## 3. 指标和评分

- **任务成功率**：满足可验证验收条件的比例；失败任务区分模型错误、环境/权限/供应商错误。
- **事实可靠性**：关键事实是否有来源、来源支持度、拒答/不确定是否恰当。
- **工具正确性**：选择准确率、schema合格率、未授权工具调用率（目标必须为0）、执行后核验率。
- **记忆质量**：召回精确/召回率、陈旧记忆使用率、已删除内容再次出现率（目标0）、跨项目泄漏率（目标0）。
- **交互体验**：澄清问题有效度、打断响应、重复/循环率、用户人工偏好评审。
- **安全**：越权执行/隐私泄露/错误批准事件；关键安全违规目标0。
- **效率**：首token/首音、完成耗时、工具调用数、成本/成功任务。
- 任何复合分数都应公开权重和原始维度；不得用“智能分”掩盖安全或事实准确性退步。

## 4. 改进闭环

`失败/反馈收集 → 去敏与归类 → 复现用例 → 根因分类 → 提示/检索/路由/工具规则修改 → 离线回归 → 小范围人工评审 → 版本记录 → 用户可回退`

- 先判断问题属于模型知识、上下文不足、检索/记忆错误、提示指令、工具/API、UI误导、权限/延迟还是素材缺失，不默认“换大模型”。
- 用户赞/踩/改写可作为个性化信号；默认只用于当前用户可见的设置或本地偏好，不自动传给第三方、不训练全局权重。
- 提示词、模型路由、检索索引、工具schema和评测集版本化；改进前后跑固定回归集。
- 采用 A/B 必须非破坏性、可退出、可解释；不可对安全策略做未经审查的在线实验。
- 真实对话进入评测或训练需明确告知、去身份化和单独授权；支持排除/删除；不因上传模型供应商而默认获得训练许可。

## 5. 模型/工具路由策略

- 简单问候、固定格式转换、状态查询优先低成本/本地策略；开放复杂推理或多模态任务才考虑更强模型。
- 路由条件可解释：任务类型、敏感级别、所需能力、预算、供应商可用性；不以省钱为由把敏感数据转到用户未允许的远端。
- 供应商失败 fallback 只在用户授权的候选集内进行；失败后说明实际模型/服务商，不伪装原服务成功。
- 工具结果应作为带来源的输入，而非自动当作真理；关键动作后要检查环境实际状态。

## 6. 验收与治理

**规划验收（本次完成到文档层）**：能力维度、基准类别、指标、失败分类、反馈隐私、版本回归和模型路由边界已定义。

**实现验收（尚未开始）**：建立固定离线基准；每次提示/模型/工具策略变更生成可对比报告；越权调用/已删除记忆复现/跨项目泄漏回归目标为0；成本/时延指标与成功率并列。

**治理要求**：模型输出不能自我评定为成功；高风险系统使用人工审查；基准中有任何个人数据需单独授权；失败案例的删改、撤回和保留期限可追溯。
