# 分层记忆与个性化规划（P1.8）

更新：2026-10-24。本计划定义用户可控的对话/项目记忆，不代表向量库、RAG、跨会话记忆或自动记录功能已实现。记忆优先是可检查的本地数据管理问题，其次才是检索技术选择。

## 1. 记忆层级

| 层级 | 内容 | 建议寿命 | 默认行为 |
| --- | --- | --- | --- |
| 当前输入/轮次 | 当前用户消息、当前模型回答、正在处理的临时上下文 | 当前轮次/任务 | 处理后按会话设置处理；不自动成为长期记忆 |
| 会话记忆 | 当前对话的有限历史/摘要 | 当前会话；用户可清空 | 明确会话边界；不跨会话串用 |
| 项目记忆 | 用户批准的项目目标、路径约定、设计决定、已验证事实 | 项目生命周期/用户设置期限 | 项目隔离；来源可追溯；切项目不自动携带 |
| 用户偏好/长期记忆 | 语言、输出格式、明确要求记住的偏好/事实 | 仅用户批准并可设过期 | 建议先询问；敏感内容不默认保存 |
| 可检索资料库 | 用户选择导入的本地文档/素材说明/项目文档 | 用户管理 | 只索引明确选定内容；保留文件来源与删除映射 |

与程序内不可变安全规则、角色设定或任务配置区分：它们不是从对话推断出的记忆，不能让用户记忆覆盖权限、安全策略或当前指示。

## 2. 记忆条目结构

每条记忆概念上包含：`memory_id`、类型、内容/受保护引用、来源（会话/文件/用户输入）、创建/更新时间、有效期限、置信度/确定性、敏感级别、适用范围（用户/项目/代理）、用户批准状态、是否从摘要派生、引用父条目、删除/纠错状态。

- 区分明确陈述、系统观察、模型推断和用户批准的总结；推断不能伪装成事实。
- 单条记忆可查看原始依据或摘要依据；检索结果可供用户核对。
- 相互矛盾、过期、来源不明或低置信记忆应谨慎使用或询问，不能默默覆盖用户当前说明。
- 同一事实在多层记忆中重复时建立引用/索引，而不是复制无法同步删除的多份正文。

## 3. 写入、检索与遗忘

### 写入
- 默认仅保存当前会话实现多轮连续性；长期记忆采用“建议—预览—用户接受”或显式开关。
- 仅写入稳定、有未来价值、非敏感、来源清楚的项目约定/偏好；原始聊天全文不自动变成用户档案。
- 提供“不要记住此内容”与“记住这条”的直达操作；用户可关闭长期记忆而不影响当前轮次对话。

### 检索
- 先按范围/权限/时间过滤，再按相关度检索；禁止跨用户、跨项目、跨代理越界。
- 输入模型前显示或记录使用了哪些记忆来源（本地可查看）；敏感项单独授权。
- 记忆仅为证据之一；当前明确指示优先于旧偏好；关键决策以用户确认记录为准。
- 无相关可信记忆时返回未找到，不编造“我记得”。

### 更新/删除
- 用户可查看、编辑、设过期、删除、导出单条/某层/全部；记忆关闭时说明是否仍保留会话日志。
- 删除必须清理正文、派生摘要、搜索索引、向量/关键词索引、缓存与代理checkpoint的引用；备份中明确最晚清除时机。
- 用户改正某条记忆后保留更正来源，旧事实不可再次作为有效上下文。
- 对供应商已收到的上下文，明确本地删除不能代替供应商侧数据删除申请。

## 4. 隐私与权限

- 长期记忆默认关闭或逐条确认，具体默认由用户决定；当前规划不擅自设为默认开启。
- 敏感类别（健康、财务、身份/凭证、精确位置、私人关系、未成年人信息等）默认不做长期记忆；若产品需支持，应单独设计更严格授权与保留策略。
- 记忆数据本地加密/安全存储需求在实现前评估；API Key/密码/身份认证秘密绝不存入AI记忆。
- 记忆显示、检索、导出和删除均纳入权限审计；日志不含记忆正文。
- 云端推理仅发送完成当前任务所需上下文；先展示供应商与记忆来源，遵从 `PRIVACY_PERMISSIONS_PLAN.md`。

## 5. 与代理/Skills/任务模板的隔离

- 每个项目和agent profile可有独立记忆命名空间；跨命名空间共享须显式授权并记录来源。
- Skills 默认不能读取长期记忆；每次调用仅给其完成功能所需的最小摘要。
- 任务模板不保存记忆正文、Key、账户信息或个人目录绝对路径；模板运行时由用户重新提供或选择。
- 代理恢复任务使用checkpoint而非长期记忆；恢复前重验权限、预算、文件变化和副作用，不能因为记忆里“上次同意”就重复执行。

## 6. 实现路线候选

- 首先实现用户可读的本地结构化记忆列表、范围/来源/删除；
- 再选简单关键词/标签/全文索引，测量是否够用；
- 仅在数据规模和召回评测证明有必要后，评估向量检索/RAG及其本地索引、嵌入供应商、删除与隐私成本；
- 不先承诺特定向量数据库，也不照抄 Neuro-sama 未公开的记忆实现。

## 7. P1.8 验收拆分

**规划验收（本次完成到文档层）**：层级、范围、来源/置信度、写入同意、检索过滤、更新/删除、代理隔离及供应商披露已定义。

**实现验收（引擎层已完成 T67.45；界面/隔离/导出尚未开始）**：跨会话/项目/代理泄漏测试目标为0；记忆关闭后不得新增长期条目；删除后搜索/摘要/缓存不再召回；用户纠错覆盖旧记忆；无来源内容不被报为已记住；本地导出/删除和日志脱敏可测试。

## 8. 长记忆线：四年后她还是她（T67.45，2026-10-26 落地）

用户原话：*「对真正的『人』记忆线是很长的……她在四年后还能想起 nimiko，那个最开始陪着她成长的人。
要让我们知道在很久之后她还是她。」*

判据不是"存了聊天记录"，而是四条可机检的：
**① 四年后仍能说出最开始那件事的原话和日期、「多久以前」；② 不编造；
③ 自述跨年可追溯、不漂移（还是同一个人）；④ 用户随时能翻出原话。**

### 8.1 为什么不走"检索记忆"那条路

查过的资料（结论，不抄实现）：

- Generative Agents 的记忆流：每次观察落库（timestamp + importance + embedding），
  检索 = `α_rec·recency + α_imp·importance + α_rel·relevance`，recency 指数衰减。
  ⇒ **四年后的分数必然趋近 0**。能活到四年的记忆，必须在**写入时**就被认定"不许淡"。
- Anchor（2026）：长程陪伴里"轨迹回忆"平均只有 **44.4%**，用户状态回忆近乎四选一；
  **没有任何模型或上下文配置能稳定解决**。⇒ 不能指望模型自己记，必须由引擎提供原文。
- 人格漂移：Li et al. 2024 实测 **8 轮**就出现；100 轮级普遍偏离；lost-in-the-middle（U 形注意力，
  首尾强、中间塌）。⇒ "她还是她"要靠**引擎侧稳定的锚**，不是靠把人格写得更长。
- 重巩固（回忆会改写记忆）：对人正常，对陪伴产品是灾难（三年后"记得"没发生过的事）。
  ⇒ 反过来做：**正文不可变**。
- Selective Forgetting：`0.35·recency(90 天半衰) + …`，低于阈值剪枝。⇒ 采纳 **90 天半衰**这个数，
  但**只让检索端淡，正文一条不删**。

### 8.2 落盘格式（`data/<角色>/memory/chronicle.zm`）

append-only，重放即状态；32 字节头 + 正文：

| 偏移 | 内容 |
|---|---|
| 0 | `u32` magic `ZME1` |
| 4 | `u16` type：1=ADD 2=PIN 3=DEL 4=TOUCH 5=SALIENCE 6=STORY 7=UNPIN |
| 6 | `u16` 正文长度（≤ `ZMEM_MAX_TEXT` 240 字节，按整字截断） |
| 8 | `u32` id（连续，重放时校验） |
| 12 | `i64` t（unix 秒，写入方给 → 测试里可以做"四年快进"，导入老记忆可以给历史时间） |
| 20 | `u32` FNV-1a 正文哈希（读盘逐条对账；改 1 字节即拒绝加载） |
| 24 | `u32` aux（ADD: kind \| salience<<8；SALIENCE: 新值<<8） |
| 28 | `u32` once-key 哈希（0 = 不参与去重；同一个键只会写一次，幂等） |

为什么不"整份重写"：四年 2.9 万条 → 2.9 万次全文件 IO；而且 append-only 天然能回答
"她三个月前是怎么描述这件事的"（历史版本都在）。`zmem_verify()` 重放一遍做全量对账。

### 8.3 两种命运 + 一条铁律

| | 日常事件 EVENT | 锚点 ANCHOR |
|---|---|---|
| 上限 | 40000 条（超了拒绝写入，不覆盖） | **12 条**（满了拒绝新增，**不静默降级**） |
| 衰减 | 只在**检索端**：`exp(-天数/90)` | 不衰减，**永远** pin 进上下文 |
| 删改 | 只能用户显式删（落墓碑，正文留着可审计） | 降级必须给理由，理由落盘 |

铁律：**正文一次写成，永不改写**；之后只许改 `access / last_hit / salience`（salience 只许升）。
"遗忘"不做成删除 —— 静默丢数据比明着缺更糟。

### 8.4 检索公式（`zmem.c: recall_impl`）

```
rel  = 查询与正文的汉字二元组重合率            （0..1，<0.20 直接不参与）
rec  = exp(-(now-t)/86400/90)                 （半衰 90 天）
score = 2.0*rel + 1.2*(salience/9) + 0.8*rec  （<0.45 直接不参与）
```

**不硬凑**：一条都过不了闸时整块返回空，并留一句"没列在这里的事就是没有记录，
说记不清，不许编一个细节来填"（这句在实测里是"不编造"的关键）。

**分层召回（本轮新加，见 8.6）**：不是取前 K 名，而是
① 把候选按"年龄桶"（0-1 / 1-2 / 2-3 / 3-4 / 4+ 年）分组；
② **每个有候选的桶先保一条，从最老的桶保起**；③ 剩余名额按分数补（每桶最多 2 条）；
④ 还有空位就无视桶配额补满（配额是软约束，不许浪费名额）。K = 8。

### 8.5 自述（"她还是她"的可机检部分）

版本化，一次改写必须同时满足：① 距上一版 ≥ 30 天；② 与上一版汉字二元组重合 ≥ 55%；
③ 至少引用一条**真实存在且未删除**的记忆 id（`[#12,#34]正文`）。
三条闸分别防"天天抖"、"换了个人"、"凭空抒情"。

### 8.6 实测（[测试锁]，可复跑）

| 闸 | 命令 | 结果 |
|---|---|---|
| 单元（行为规则 A–J） | `make test` → `test_memory_longarc` | 1325 项 / 0 失败 |
| 长跑（质量） | `make soak-memory` | 1460 天 → 见下 |
| 仓库体检（静态） | `make audit-memory` | 结构/哈希/锚点上限/自述三闸/不许存密钥/单条 ≤240 字节 |
| 运行时对账 | `/api/memory.json?verify=1` | 冒烟里打（`tools/api_smoke.py` 新增 8 项） |

长跑实测（1460 天 × 每天 4 条 = 5850 条 + 8 个信物 + 2000 条干扰）：

- 专名提问：8/8 找回，全部第 1 名，单次回忆 **~1.0 ms**；
- 自然提问（只说"你送我礼物的那天还下雨"）：**6/8 → 8/8**（改分层召回 + K=6→8 之后）；
- 灌 2000 条提到同一件东西的新事：8/8 仍找得回；
- 40 件同类小事横跨四年：**最老那件仍在**，块里横跨 4 个年份；
- 回忆 500 次后正文逐字节不变；重开条数/锚点/正文都在，对账通过；
- 落盘字节只会因 TOUCH 记录增长（+32 字节/条），正文不增。

6 年（2190 天、8774 条、1.06 MB）：12 个信物全部找回，最慢 9.71 ms（首次缓存未热）。

### 8.7 已知可优化（按优先级）

1. `recall` 线性扫全表（4 万条每次 ~几十毫秒）；需要倒排索引（二元组 → id 列表）。
2. 相关度只有二元组，没有同义词/别名表。`nimiko / miyune` 这类**专名变体**要靠别名表才对得上。
3. 没有"撤销/编辑"。写错了只能删了重写，而删除是墓碑。
4. 锚点上限 12 硬编码在头文件里，换角色想放宽必须重编。
5. 单条 240 字节对"那天你到底说了什么"偏短（长对话原文要分段存）。
6. 记忆块与 `zctx` 会话历史可能重复灌入同一句话（还没去重）。
7. 分层召回的桶宽是固定 1 年；更细的做法是按"被提及的段落"动态分桶。

### 8.8 与第 7 节实现验收的关系

第 7 节的**引擎层**验收本轮完成（本地结构化、可查看、可删除、删除后不再召回、
无来源不报"我记得"、不存密钥、日志不含正文）。
**产品层**仍未完成：给用户看的记忆列表/管理界面、跨会话/跨项目隔离、导出。

### 8.9 HTTP 端点（记忆线）

| 端点 | 方法 | 作用 |
|---|---|---|
| `/api/memory.json` | GET/只读 | `verify=1` 全量对账；`q=<问题>` 返回这一轮会进提示词的块；`n=` 条数；`with_deleted=1` 连墓碑；返回 items/anchors/deleted/stories/bytes/oldest/newest/tz_offset_min/block |
| `/api/memory/add` | GET | `text` / `kind`(0 事件…3 约定) / `salience` 1~9 / `once` 幂等键 / `t` 历史时间（只接受 2000 年之后、不晚于明天） |
| `/api/memory/del` | GET | `id` + `reason`：落墓碑，正文留档但不再被检索 |
| `/api/memory/pin` | GET | `id` 升成锚点；`unpin=1` + `reason` 降级（**没理由拒绝**，理由落盘） |
| `/api/memory/story` | GET | `versions=1` 版本数 / `latest=1` 最新自述 / `history=1` 全部版本 |

原则：**这组端点全是本地读写，不出网**；正文不进日志（日志只打条数与字节）。
