# 自研 2D 作者工具与角色制作工作流（执行记录）

## 范围与原则

做自主 C `zrig` 引擎的作者工具、工程和插件；不把自有 JSON/PNG 或 `.zproj` 宣称为官方 Cubism 格式，也不反编译或暗示能生成官方私有 `.moc3`。官方流程与许可参考见 `docs/CUBISM_WORKFLOW_AND_EDITOR_GAPS_2026-11-06.md`。桌宠 Q、带兽特征 Chibi、无兽特征 Chibi、少女是不同资产，不能相互覆盖。每次都在隔离副本中开发、记录来源、测试后才考虑迁移正式资产。

## 本轮完成及证据

1. **黑描边**：从无兽特征试装生成独立黑描边试装，算法针对暗线及透明轮廓，保留 alpha/坐标；`tools/build_human_chibi_blackline.py`、`experiments/live2d_chibi_human_blackline/qa/`、`make test-blackline`。这是自动处理而非人工精描，需用户和美术目视审阅；原版未覆盖。
2. **可视化素材画布**：`tools/rig_editor/` 在浏览器读取 PNG、按图层/坐标绘制静态近似，允许选定部件后拖动并撤销、重做；挂点坐标只读。`make test-rig-editor` 含计算、模拟 UI 与编辑后真实 C 帧测试。静态画布不处理遮罩、参数变形、物理、姿态等，不能视为 C 渲染预览。真实浏览器自动化仍缺。
3. **自研工程快照 v1**：`tools/zrig_project.py` 创建/验证/解包 `.zproj`，有文件上限、路径检查与 SHA-256；`experiments/live2d_chibi_human_blackline/model.zproj` 为可复验示例。`make test-zrig-project` 测试正常往返、篡改、重复路径、路径逃逸、现有目录保护、外部动作拒绝，以及解包后真实 C 加载。SHA 不代表签名，v1 不支持外部动作/表情，不含原画 PSD 或编辑历史。

## 实际制作与检查顺序

1. 固定角色、画风、比例和每套外观；记录用户选择与素材来源。不得将无兽特征版替换有兽特征版。
2. 准备真实可编辑分层源和遮挡补画：面部/眼白/虹膜/睫毛/上下眼睑、口腔/舌/嘴线、前后发、躯干、臂/腕、两套手型、衣裙与鞋分别检查。当前 AI 整图差分及本工程包**不是**原始分层工程。
3. 在隔离目录切件、检查透明边缘和色差；静态画布用于放置与图层排布。设置参数与绑定，导出 rig 副本；涉及 socket 的部件不能用坐标拖动代替挂点编辑。
4. 用真实 C 预览分别测试睁/闭眼、口型、头部、动作及极值，记录渲染帧与像素指标；在浅/中/深底分别看毛边，检查组合穿插和切缝；数值通过不等于美术通过。
5. 生成一个新的 `.zproj` 文件，验证并在全新目录解包，重新用 C 引擎加载。v1 对少女的外部动作不适用，不能省去依赖或将它包装成完整工程。
6. 人工审阅并记录未通过项，再决定是否接入正式资源。跑本仓库测试及静态自检，报告未通过项；Windows 发行需 Windows 真机验证。预览是无认证服务，不能用于敏感信息。

## 后续里程碑与完成门槛（尚未完成）

- **M1 稳健工程与导入**：版本化 manifest、相对资源和外部动作/表情依赖、分层原画及许可证记录、增量重导入/备份/迁移、用户可视化打包；门槛为含少女外部动作的工程完整往返、损坏/中断/恶意输入测试及真实 C 运行一致。
- **M2 真实可视编辑器**：与 C 预览隔离安全通信（无凭据的本机/受信环境限制），图层树/多选/隐藏/锁定/排序、画布平移缩放、可视化锚点和变形器层级、撤销事务；门槛为真实浏览器端到端、引擎图像对照及重启后工程可恢复。
- **M3 网格与绑定器**：纹理 UV、手工/自动三角网格、顶点拖动、父子旋转/弯曲、参数范围与 1D/2D keyform、多轴插值、遮罩/绘制顺序、旋转组合；门槛为极值与中间态的稳定可复现 C 帧、无反面/越界/接缝及参数语义测试。
- **M4 动作与物理**：时间线、插值、表情混合、口型、物理调试、参数录制回放与确定性；门槛为跨帧率/暂停/过渡测试、关节与布发目视验收。
- **M5 插件**：明确编辑器和运行时不同 ABI、能力声明、生命周期、兼容版本、卸载/错误处理、可审计权限、隔离威胁模型及签名/分发策略；现有 `src/core/zmod.c` 会在本进程加载本机代码，**不是沙箱，也不自动实施权限限制**。门槛为真实构建、加载、事件、卸载、崩溃隔离和安全测试，Windows/Linux 分别验证。当前没有完整插件 SDK 或可信插件沙箱。
- **M6 模型生产**：先解决少女长发戴帽遮挡等已知问题、再完成 Chibi 的手臂与双手型/发型、网格和物理；按隔离图稿→目视→用户确认→C 全动作→生产审批执行，不得以静态图当完成模型。

当前静态仓库自检仍有正式 teen/chibi rig 生成器指纹及 ROADMAP/TASKS 计数两项失败；不要盲目覆盖既有资源以消红。源代码、单元测试或运行截图不等同于 Cubism 格式兼容或 Windows 产品验收。
