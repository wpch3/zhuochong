# 正式软件的界面（PRODUCT_UI）

> **2026-10-24 用户定调**：「截图的这个 UI 只能存在于测试网页，
> 进入正式软件的时候必须完全优化和更改。」
>
> 这份文件把这条约束钉死，并写清楚正式软件到底长什么样、
> 哪些东西现在就该按"将来要换 UI"来做。

---

## 一、先说清楚：现在那个界面是什么

`http://localhost:5176` 上那一大堆卡片 —— 动作按钮、情绪按钮、形态下拉、缩放滑条、
rig 调试台、路由沙盘、聊天框 —— **是脚手架，不是产品。**

它存在的理由只有一个：**底层能力必须有地方点得到，否则没人知道它到底做没做对。**
这个理由很硬，所以测试台要留着；但它跟用户最终看到的东西**没有关系**。

| | 测试台（现在） | 正式软件（将来） |
| --- | --- | --- |
| 形态 | 浏览器里的网页 | 桌面上的透明窗口 |
| 布局 | 左立绘 + 右侧一长条卡片 | **没有卡片。只有小寻站在桌面上** |
| 暴露什么 | 全部：参数、层号、id、决策理由 | 只暴露用户要做的决定 |
| 谁看 | 我和用户验收用 | 用户每天开着 |
| 审美要求 | 能用就行 | **这是产品的脸** |

**判断一个控件该不该进正式软件的办法**：问"我奶奶会用这个吗"。
「缩放 0.55」滑条 —— 不会。「动作 kirara_jump」按钮 —— 不会。
「换个发型」 —— 会。「跟她说句话」 —— 会。

## 二、正式软件长什么样

### 2.1 主界面 = 没有界面

桌宠的正确形态是**透明、无边框、置顶的窗口，里面只有角色**。
没有标题栏、没有背景板、没有侧栏、没有卡片。用户看到的就是小寻站在他的桌面上。

一切交互从立绘本身发起：

| 用户做什么 | 发生什么 | 底层已有 |
| --- | --- | --- |
| 点头部 | 摸头 → 她有反应 + 说一句 | ✅ `/api/region` 区域命中 |
| 点身体 | 抚摸 | ✅ |
| 拖动 | 她被拎起来，有被拖的动作 | ✅ `dragged` |
| 双击 | 唤出说话输入条 | 🔲 |
| 右键 | 出一个小菜单（见 2.3） | 🔲 |
| 不理她 | 自己待机/张望/换重心/打瞌睡 | ✅ 空闲动作已经在跑 |

### 2.2 说话 = 气泡 + 贴着她的输入条

**不是侧栏里的聊天卡片。** 正式软件里：

**T62.1 的实现边界**：在单独的产品视图原型中验证气泡与贴身输入条，不把测试台侧栏卡片改头换面、不移除测试台功能，也不把原型误称为 Windows 最终窗口。测试台继续只负责测试；后续 T62.2 再将已经验证的产品交互接入透明无边框原生窗口。

* 她说话 → 立绘上方弹出气泡，几秒后自己消失（测试台那个 `「…」` 就是雏形）。
* 用户说话 → 双击 / 快捷键唤出一条**贴在她脚边的细输入条**，打完回车就收起来。
* 历史记录**默认不显示**。想看才开（右键 → 聊天记录）。

那条"谁答的 · 本地还是云端 · 花了多少"的小字呢？——**要留，但要收起来**。
正式软件里它变成气泡角上一个小点：本地是绿点，云端是蓝点，点一下才展开详情。
用户有权知道，但不该被每句话都糊一脸技术名词。

> 这条是有分寸的：**可以收起来，不可以不给。** 把"这句话去过哪里"藏到用户找不到的
> 地方，和不告诉他没区别。

### 2.3 右键菜单 = 正式软件唯一的"控件集合"

一层、最多七项，每项都是用户语言：

```
  跟她说话
  换个样子   ▸  形态（少女/Q 版/…）· 发型 · 衣服
  她的性格   ▸  （persona 面板的产品化版本）
  ───────
  设置
  暂时隐藏
  退出
```

`动作`、`情绪`、`缩放`、`rig 调试`、`路由沙盘`、`平台总览`、`用量`
—— **一个都不进右键菜单**。它们要么挪进设置的高级页，要么只留在测试台。

### 2.4 设置 = 独立窗口，不是常驻侧栏

分页：`外观` / `说话` / `模型与隐私` / `声音` / `高级`。
「模型与隐私」那一页是本地/云端双栈的产品化落点：
一个"优先用本机模型"的开关 + 一句人话解释 + 云端密钥填写，
而不是现在那张 29 条端点的表。

### 2.5 托盘图标

关窗不退出，收进托盘。右键托盘 = 和 2.3 同一个菜单。

## 三、现在就该按"UI 要换"来做的事

UI 重做是将来的事，但有些决定**现在做错了，将来就要返工两遍**。
这几条从今天起执行：

### 3.1 ★ 给人看的文案一律进数据层

**2026-10-24 当天就踩了这个坑**：动作按钮的中文名写在 `web/components/actions.js`
的硬编码表里，结果 `nod` / `wave_both` / `heart_hands` / `kirara_jump` /
`look_around` / `star_eyes` / `shift_weight` / `tiptoe` **八个按钮在截图里露了英文 id**。

根因不是"忘了加"，是**名字放错了地方**。放在界面层，就得每个界面写一遍；
正式软件 UI 一重做，这些文案全得重写。

已经改掉：名字进 `rig.json`（由 `tools/make_rig.py` 的 `ACTION_TITLES` 生成），
引擎经 `/api/info.json` 的 `action_names` 送出去，谁画界面都拿同一套。
`tools/selfcheck_repo.py` 加了红线：**任何动作没有中文名就判红**。

**推广**：情绪名、形态名、发型名、服装名、错误提示 —— 同理，都该在数据层。
（形态名 `form_names` 已经是对的，这次照它的样子做的。）

### 3.2 ★ 决策理由要有"人话版"

`default_local` / `sensitive_local` / `cap_heavy` 这类枚举是给程序看的。
正式软件要显示的是"**没有任何理由上云，就在你电脑上跑的**"。
路由沙盘已经有这套翻译，别让它只活在测试台里 —— 翻译表也该下沉到数据层。

### 3.3 ★ 不要在测试台上做"美化"投资

测试台的样式够用就行。**现在往那些卡片上花的任何审美功夫都是要扔的。**
（同理：这轮发现 `app.css` 里自己发明了 `--card-alt` 这种不存在的变量名，
修是修了，但不值得在这上面再多花时间。）

### 3.4 ★ 引擎不许假设"界面长什么样"

`/api/*` 返回的是**事实**（她在做什么动作、有哪些形态、这句话谁答的），
不是**渲染指令**。现在基本做到了，继续守住 ——
正式软件换成原生窗口之后，它调的还是这套接口。

## 四、什么时候做

正式 UI 不是现在做。理由：**底层还没齐，现在定界面等于照着半成品画。**

| 阶段 | 前置条件 | 任务号 |
| --- | --- | --- |
| **现在～** | 继续补底层；所有新文案进数据层（3.1~3.4） | 随各任务 |
| **P1 气泡 + 输入条** | 聊天链路稳定（✅ T61.10 已通）+ 多轮上下文（T61.11） | **T62.1** |
| **P2 透明窗口 + 点击穿透 + 置顶** | Windows 真机壳（已有雏形）；这是最硬的一块 | **T62.2** |
| **P3 右键菜单 + 托盘** | P2 之后 | **T62.3** |
| **P4 设置窗口** | 形态/发型/服装/模型四块的数据层都稳定 | **T62.4** |
| **P5 测试台降级** | 正式 UI 能用之后，测试台收进 `--dev` | **T62.5** |

**P2 是关键路径**：透明无边框置顶窗口 + 点击穿透（非角色区域的点击要穿到桌面）
是桌宠的立身之本，做不到就只是个"带图的小窗口"。
这件事只能在 Windows 真机上验，沙箱里验不了 —— 得提前说清楚。
