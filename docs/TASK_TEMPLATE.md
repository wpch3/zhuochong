## 试用任务卡：P1.12 VRM 本地预览可行性 spike

> 这是隔离的未来可选方向，不启动完整 3D 桌宠，也不改写或替换现有 2D/Live2D 方向。

- **用户价值**：判断合法来源的 VRM 模型能否以低成本做本地预览，为以后是否支持 3D 提供证据。
- **范围内**：限定的一次短时可行性 spike；先查现有开源 runtime，再以独立浏览器页面/临时分支外的隔离原型验证单个本地 VRM 文件加载、基础显示和错误提示。无模型样本时先只完成技术调查，不伪称实测。
- **明确不做**：不合入 C/Win32 主渲染器；不改当前 2D/Live2D 角色资源、rig、动画、默认显示和构建依赖；不做 VRChat 上传/Unity 工程转换；不获取或转存未授权模型；不承诺完整表情/物理兼容。
- **隔离与停止条件**：原型单独放置，不引入主程序依赖；首轮调查/验证严格限时，建议上限 2 小时。若模型导入、许可或运行时集成需要明显扩展，停止 spike，汇报选项后再等用户决定，不顺手扩展范围。
- **参考依据**：`@pixiv/three-vrm`（MIT, Three.js/WebGL）与 `vrm-c/UniVRM`（MIT, Unity）；具体版本与能力在实际执行前复核。参考记录见 `docs/REFERENCE_NOTES.md`。
- **输入/权限**：用户自己拥有或获准使用的本地 `.vrm` 文件；原型纯本地加载，不上传、不持久复制；检查模型元数据/许可字段。
- **交付物**：一页结论（选型、版本、许可、支持边界、主程序隔离方案）及若条件满足则一个不进入主程序的最小加载原型。
- **验收**：证明一个获授权样本能本地显示，或产生清楚可复现的失败诊断；说明模型格式、材质/表情/眨眼/物理支持差异；仓库主程序源代码、2D/Live2D素材和构建配置无改动。
- **回滚**：删除隔离原型/缓存即可；不得留下 3D 依赖进入主程序。
- **下一决策**：仅由用户决定是否继续独立 3D renderer 设计；未批准前 P1.12 不自动升级为正式功能开发。
