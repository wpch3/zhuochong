# 训练区设计（TRAINING）—— 音色模型 + AI 模型

更新：2026-10-11 ｜ 状态：**规划（用户明确要求：训练音色模型与 AI 模型的功能也要加上，让工具成为完整工具）**
关联：`docs/PRODUCT_PLAN.md`（总规划）、`docs/VOICES.md`（音色手册）、`docs/memory/TASKS.md`（T15）

> 一句话：**训练不是新造一个炼丹炉，而是把"数据集 → 配方 → 执行器 → 模型库 → 应用"这条链做进软件**，
> 训练本体交给成熟开源工具，软件负责编排、追踪、评估、合规与"训完直接用"。

---

## 一、为什么训练区能反哺这个项目（三个立刻见效的用途）

1. **角色美术 LoRA（最重要）**：用用户的三张参考图（`小寻.png` / `小寻短发.png` / `小寻长发.png`，1696×2528 白底）
   训练专属画风/角色 LoRA → 之后生成小寻的**四形态设定图、表情集、拆件图**时，**画风、发色、发夹、服装细节自动一致**。
   这直接解决历史两大痛点：**取景漂移**（配合 img2img 锁框）与**风格不一致**（表情集对齐失败的根本原因）。
2. **音色模型**：训练/微调专属少女音色（自有或已授权声源）→ 导出**音色包**（`voices/<id>/`）→ 软件零改动即可使用。
3. **对话模型微调**：用本项目积累的台词与互动数据做 LoRA/SFT → 角色语气更稳（7 个 AI 角色各自的说话风格），
   并支持**本地小模型**（隐私优先时不出网）。

## 二、支持的训练类型（都在同一套"任务 + 数据集 + 模型库"框架里）

| # | 类型 | 用途 | 推荐工具（开源） | 显存参考 | 产物 |
| --- | --- | --- | --- | --- | --- |
| T-A | **图像 LoRA**（角色/画风） | 小寻四形态与拆件、主题素材、表情集 | kohya_ss / sd-scripts；Flux/SDXL 各有配方 | 8–16 GB | `*.safetensors`（LoRA） |
| T-B | **对话 LLM 微调**（LoRA / QLoRA / SFT / DPO） | 角色性格与台词、工具调用格式 | LLaMA-Factory / unsloth / axolotl | 7B QLoRA ≈ 10–16 GB | LoRA 适配器 + 合并模型 |
| T-C | **语音合成**（音色/风格） | 小寻少女音的专属版本 | GPT-SoVITS 微调 / CosyVoice2 零样本 / Piper 官方训练 | 6–12 GB（Piper 可 CPU） | **音色包**（我们的格式） |
| T-D | **语音识别**（可选） | 语速/口音/专有名词更准 | Whisper / Paraformer 微调 | 8–12 GB | STT 模型 |
| T-E | **嵌入与检索**（RAG） | 工作区资料检索更准 | sentence-transformers / reranker 微调 | 6–12 GB 或 CPU 小模型 | embedding / reranker |
| T-F | 分类/路由小模型（可选） | 意图识别、工具路由 | scikit-learn / 小型 transformer | CPU 即可 | 小模型文件 |

> 说明：**不训练生成模型的底座**（从零预训练）——成本与算力不现实；只做**微调/LoRA/蒸馏**，这是行业标准做法。

## 三、架构：执行器 + 任务 + 数据集 + 模型库 + 评估

```
┌ 训练区界面（工作区内的一个分区）───────────────────────────────┐
│ 数据集管理 │ 配方模板 │ 任务队列 │ 进度日志 │ 评估 │ 模型库 │ 合规声明 │
└───────────────┬───────────────────────────────────────────────┘
                │ 事件总线（pet.event / task.update / token.usage）
        ┌───────▼────────┐
        │ Trainer 执行器  │  三选一（可混用，配置里切换）
        │                │  ① 本机 GPU（Windows，最省事）
        │                │  ② 远程服务器（SSH，用户自有卡）
        │                │  ③ 云 GPU（用户自备账号与 key；只存本机）
        └───────┬────────┘
                │ 产物
        ┌───────▼────────┐
        │ 模型库 Registry │ 每个产物：base、方法、超参、数据 hash、评估、许可、体积、日期
        └───────┬────────┘
                │ 一键应用
   对话/语音/生图/检索 直接切换（config/providers.json 与 config/voices.json）
```

**关键设计（与"全部可自定义"一致）**
- **配方（recipe）是数据不是代码**：`train/recipes/<id>.json` 声明：类型、base 模型、数据集要求、超参、导出格式、评估指标。
  新增一种训练方法 = 新增一个配方文件，不改核心。
- **数据集是版本化对象**：导入 → 清洗 → 切分 → 锁定 hash；训练记录里必须写明用了哪个版本的哪个数据集（可复现）。
- **模型库与"应用"分离**：训练完不自动生效，必须显式"应用到某角色/某分区"，并可一键回滚。
- **沙箱限制写清楚**：沙箱**无 GPU、无外网、内存 3 GB** → 训练只能在你的机器/服务器/云上跑；
  本软件提供**配方、数据准备脚本、导出适配器、评估与验收**，这部分沙箱内可完成。

## 四、数据集管理（"能训练"的一半在于数据）

| 步骤 | 做什么 | 工具/要点 |
| --- | --- | --- |
| 导入 | 图片/音频/视频/文本/对话记录 | 视频自动抽帧（ffmpeg）与抽音轨；音频自动 VAD 切句 |
| 清洗 | 去重（感知 hash / 文本近似）、去噪、静音切分、响度归一 | 图片：分辨率/透明通道检查（复用素材验收脚本） |
| 标注 | 图片打标（触发词 + 角色特征）、音频转写（STT 初稿 + 人工修正）、对话按角色分轮 | 打标界面（本地）；触发词约定如 `xiaoxun, silver blue hair, whale clip` |
| 切分 | train / val（默认 9:1），固定随机种子 | 记录 hash 与划分清单 |
| 合规 | **来源与授权声明**（自有/已授权/公开许可）、真人肖像与声纹的明确同意 | 无声明不允许开训（硬闸门） |

## 五、评估（不评估就不算做完）

| 类型 | 自动指标 | 人工 |
| --- | --- | --- |
| 图像 LoRA | 角色一致性（CLIP/自建特征相似度）、触发词命中率、与参考图的色卡偏差 | 生图对比页（同一提示词 × 多 LoRA）打分 |
| LLM LoRA | 评测集（角色台词/工具调用格式）通过率、PPL、胜率（新旧模型对打） | 对话抽检打分 |
| 语音 | 基频/时长/相似度（说话人嵌入余弦）、可懂度（用 ASR 回读比对文本） | 试听打分（复用试听页） |
| 检索 | Recall@k、MRR | 抽样看命中资料 |

> 本项目现成可复用的评估代码：`tools/voice_pitch.py`（基频测量）、`tools/prepare_sprites.py`（色卡/残留检测）、`tools/voice_packs.py`（音色包验收）。

## 六、合规与安全（硬规则，不可绕过）

1. **只训练自有或已获授权的数据**；禁止克隆真人声音（用户既定红线），禁止使用商业角色素材训练后商用。
2. 每个数据集必须填 `license` 与 `source`；**没有声明 → 训练任务不允许入队**。
3. 每个模型产物必须生成 **model card**（`train/models/<id>/model_card.json`）：base、数据来源、方法、超参、
   评估结果、许可、已知限制、训练者与日期。
4. 人脸/声纹类数据需单独授权字段；训练产物默认**只在本机使用**，不自动上传。
5. 云 GPU 训练时，API key 与数据上传范围必须显式确认（默认只上传声明的数据集切片，且默认**关闭**）。

## 八、与其它分区的衔接

- **生图区**：加载角色 LoRA → 生成四形态设定图/表情集/拆件候选 → 自动过素材验收 → 进 `characters/<角色>/`。
- **语音区**：训练产物导出**音色包** → `voices/<id>/` → 写进 `config/voices.json` → 立即可用。
- **对话区**：LLM LoRA 应用到指定角色（`providers.json` 里的本地模型项）→ 角色语气一致；支持"新旧对比"页。
- **工作区**：训练的模型与配方、数据集、评估报告全部进工作区资料库，可检索、可引用、可备份。
- **Token 计费区**：训练不计 token，但记**资源账**（GPU 小时、云费用、显存峰值），与推理账分开展示。

## 十、歌声合成与声音转换（回答"网上 AI 模仿动漫角色唱歌"）

现象说明：B 站/抖音上"AI 翻唱"绝大多数属于**歌声转换（Singing Voice Conversion, SVC）**，
不是让 TTS 直接唱。流程是：**别人的歌声（或自己唱）→ 音色转换模型 → 目标音色**。

| 方案 | 说明 | 本地可行性 | 数据需求 | 许可注意 |
| --- | --- | --- | --- | --- |
| **So-VITS-SVC** | 最经典的 SVC；支持说话/唱歌音色转换 | ✅ 本地可跑，GPU 4–8 GB | 目标音色 10–60 分钟干净人声 | 代码/模型许可需逐项核对；**音源授权是硬前提** |
| **RVC** | 实时性更好，训练快，社区工具多 | ✅ 本地可跑，GPU 6–8 GB | 同上 | 同上 |
| **DiffSinger / OpenUtau** | 直接"合成歌声"（不是转换），需标注音高/发音 | ✅ CPU 也能推理，训练需 GPU | 音源 + 音高标注（大工程） | 音色需自有/授权 |
| **TTS 唱句**（取巧做法） | 用现有 TTS 把歌词按乐句合成，再按音高曲线做 PSOLA 变形对齐旋律 | ✅ 最省力（本项目的 `--shift-method praat/psola` 已具备能力） | 无需新训练 | 无额外风险 |

**结论**：
1. **本地能做**，但需要 GPU（沙箱 2 核 3 GB、无外网，跑不了训练；推理可交接给用户机器）。
2. 训练/转换都必须满足 `docs/TRAINING.md` 第六节的合规闸门：**自有或已授权的声音**，
   并且产物要写 model card。动漫角色的官方音源**不能**直接用于训练后商用。
3. 落地方案：本项目做"配方 + 数据集管理 + 导出 + 验收"，把 SVC 产物当**音色包**接进软件；
   歌词与旋律对齐用 `timeline` 思路（参考 airi 的 `pipelines-audio`），先做"TTS 唱句 + 音高对齐"的最小可用版。
