# 高阶自主能力 Backlog（仅规划，不激活）

更新：2026-10-30。本文是 `docs/ROADMAP.md` 的受控远期规划；当前不代表任何能力已实现或获准运行。

> **G79 主人显式审批是启动闸，不是事后开关。**四个模块 `mod_vtuber_stream`、`mod_game_player`、`mod_device_control`、`mod_proactive_soul` 在主人对具体模块、平台、权限、时段、数据范围逐项明确同意之前：不得启用、不得后台运行、不得连接外部平台、不得模拟输入，也不得把它们加入自动执行队列。默认拒绝（deny-by-default）。一次审批只覆盖明确列出的范围，可撤销、可审计；超范围动作必须重新审批。
>
> 这里只完成架构规划，不开通权限、不请求凭据、不执行设备/账号操作。落地顺序仍服从 `ROADMAP.md` 的基础软件与安全前置。

## 共用安全与 C ABI 契约（G79）

所有自主模块统一依赖纯 C 的权限/模块 ABI（规划关联 `zperm`、`zmod`、`zbus`）：

- 模块 manifest 声明稳定 `module_id`、ABI 主/次版本、能力清单、数据分级、外部端点、资源上限和可撤销操作；未知能力一律拒绝。
- `zperm` 在每次副作用之前做能力检查；显式审批记录包含主人、模块、资源范围、动作范围、有效期限、速率/预算上限及撤销状态。模块不得自行扩大 scope。
- `zbus` 只传带来源、时间戳、关联 ID、权限标签和隐私级别的事件；敏感消息/屏幕内容不得因转发而降级。跨模块调用仍重新鉴权。
- 每项副作用先产生可读预览（如无法预览须明确阻断或单独授权），有审计日志、停止令牌、超时、速率限制和失败关闭；能回滚的操作提供回滚接口。
- 插件 ABI 以 C 的 `struct_size`、`abi_version`、不透明句柄、能力查询和显式函数表为边界；不得把宿主内部结构布局、C++ ABI 或未稳定的指针所有权暴露给插件。跨线程事件使用 `zbus`，模块卸载先停发事件、取消任务、释放资源再卸载。
- 测试先用离线假适配器/模拟器；真账号、真设备、真推流只能在 G79 对具体范围审批后做端到端测试。

## `mod_vtuber_stream` — 自主直播（G79-STREAM）

**目标范围：** 经审批后控制 OBS WebSocket、准备虚拟摄像头/推流输出、读取已授权直播间的弹幕并驱动语音、口型、表情、动作回应。

**路线：** (1) 只读 OBS 状态适配器与版本化 C adapter ABI；(2) 场景/来源白名单、推流目标和带宽预算；(3) 预览模式演练，弹幕仅作带权限标签的 `zbus` 事件；(4) 主人逐项批准后才开放场景切换、语音播报和开/停播；(5) 真机试播与断网、撤销、重复事件演练。

**G79 范围授权：** 平台/频道、OBS 主机与 WebSocket 权限、允许场景和来源、虚拟摄像头设备、推流目标、允许时间窗、弹幕读取范围、可回复行为、时长/带宽/费用上限必须分别确认。默认只读、不开播；开播/下播、发言和读弹幕均为可审计副作用。提供醒目的主人中止键和独立断流路径。

**验收门槛：** 假 OBS/假弹幕测试 → 主人审阅的预览 → 经 G79 授权的短时真机试播；确认弹幕权限隔离、口型/表情事件关联、审计完整、断开 WebSocket 即停止输出。未获授权时测试必须证明没有任何外部连接。

## `mod_game_player` — 自主玩游戏与消遣（G79-GAME）

**目标范围：** 空闲时在明确批准的本地小游戏/专用沙箱内做视觉理解、键鼠/手柄模拟输入和自主消遣；不把“陪玩”解释为可代打线上游戏。

**路线：** (1) 离线棋盘/内置小游戏及合成画面；(2) 只读屏幕捕获与隔离进程；(3) 可视化输入计划和动作回放；(4) 主人批准具体游戏、窗口、输入设备和时间后，才开启受限输入。支持暂停、退出、资源/时长预算与崩溃恢复。

**G79 范围授权：** 允许的游戏/进程、窗口捕获范围、键鼠/手柄种类与按键白名单、时段、最长时长和是否允许联网逐项确认。默认不捕屏、不输入、不启动游戏；禁止作弊、绕过反作弊、交易/付费、访问账号凭据和隐私目录。

**验收门槛：** 沙箱首验为内置小游戏闭环（开始/暂停/结束），输入只作用于沙箱窗口；主人可以随时中止；确认切到其他窗口、权限撤销或超时会立即停止输入与捕获。

## `mod_device_control` — 跨设备操控（G79-DEVICE）

**目标范围：** 主人明确委托下的 PC 桌面自动化，以及通过官方 ADB、投屏或 Android 无障碍授权路径进行手机远程感知/操控。

**路线：** (1) 只读桌面/设备发现且逐设备审批；(2) 桌面动作预览、白名单目录与事务化回滚；(3) Android ADB/投屏/无障碍独立 adapter，敏感权限逐项呈现；(4) 逐任务执行前确认、执行后 diff/回滚；(5) 记录审计并测试撤权、断连和失败恢复。各 adapter 隔离，PC 授权不推导手机授权。

**G79 范围授权：** 主机/设备 ID、桌面应用、目录/文件、手机投屏画面、ADB 命令白名单、无障碍服务作用范围、可执行动作、有效期分别审批。删除、发送、安装、购买、登录、提权、改系统设置等高影响动作默认禁止；若未来开放，须逐次二次确认并可逆。默认不扫描、不投屏、不触控。

**验收门槛：** 在临时目录完成“预览→归档→一键撤销”；Android 用测试设备验证每项系统授权可撤销、断连停止、屏幕内容不外传。没有主人审批时对真实设备的连接数必须为 0。

## `mod_proactive_soul` — 主动社交陪伴（G79-SOCIAL）

**目标范围：** 由 Internal Drive 情感驱动环与本地作息记忆决定是否适时通过桌面或经批准的聊天软件主动联系主人。驱动环只提出候选，不拥有发送权限。

**路线：** (1) 离线模拟节律、驱动强度和“保持安静”的决策；(2) 生成可审阅的候选消息，不发送；(3) 主人配置频率、时段、勿扰、渠道和语气；(4) 仅在 G79 单独授权的桌面/IM 渠道内发送；(5) 48 小时静默/限频/撤销演练，加入重复抑制和敏感内容过滤。

**G79 范围授权：** 主动联系渠道、联系人/会话、允许时段、每日次数、消息类别、是否允许引用记忆分别确认。默认只在本地生成候选、不联网、不发送；禁扰优先级高于任何情绪/驱动信号，撤销立即清空待发队列。不得以情感压力诱导回复或暴露敏感记忆。

**验收门槛：** 离线 48 小时模拟证明限频、勿扰、去重；真渠道仅在审批后做单条端到端确认，撤销后没有任何发送请求。

## 与全生态规划的关系

四形态通用母版、商业 Cubism 兼容、纯 C 3D/三渲二和 IM 双向桥接见 `docs/LIVE2D_CONFORMANCE.md`、`docs/ROADMAP.md` 与 `docs/memory/TASKS.md`。IM adapter 的被动收发不自动授予 `mod_proactive_soul` 主动发送权限；直播弹幕也不自动授予 IM 账号权限。所有能力仍需独立 G79 授权。
