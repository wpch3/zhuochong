## A25 玩游戏 / 陪玩（2026-10-14；范围经用户两次澄清，以本条为准）

**用户原话（第二次澄清，排他）**：「不是完全禁止网游，而是让他们可以在网游
也陪伴聊天和实时屏幕操作进行回应对话，而其他的可以真正的游玩。」

所以不是"哪些游戏能玩"，而是**按游戏类型分成三档能力**。档位是硬约束，
不是偏好 —— 网游永远锁在只读档，这既是守规矩也是技术现实（反作弊会检测输入注入）。

### 档一 · 观战陪聊（**所有游戏都能用，含网游**）

AI 看着你玩，实时说话。**零输入**——不碰键盘、不碰鼠标、不碰手柄。

- A25.1 **实时读屏**：按窗口/区域抓帧，帧率可调，不看时不占资源。
- A25.2 **看懂画面**：帧喂给视觉模型，得到结构化状态（血量/技能CD/小地图/结算画面）。
- A25.3 **实时回应对话**：看到关键事件就开口 —— 夸、吐槽、提醒、安慰。
  这正是 A27（neuro-sama 式实时回路）最典型的落地场景，两者共用一套事件流。
- A25.4 **绝不操作**：这一档在代码层面就不接输入通道，不是"默认关闭"而是"没有这个口"。
- A25.5 **英雄联盟一类网游强制锁死在本档**，不提供任何提升到档二/档三的开关。

### 档二 · 协议游玩（Minecraft，优先做）

- A25.6 用 **Mineflayer**（Minecraft 协议客户端）以**一个普通玩家**身份登录，
  拿**结构化世界数据**（方块/实体/背包/聊天），不是像素。**不装 mod、不截屏、不模拟键鼠。**
- A25.7 动作空间是**代码**（Voyager 已验证）：模型生成调用 Mineflayer 的脚本，
  跑通的存进**技能库**复用，越玩会的越多。
- A25.8 常用动作走**参数化命令**（照 MINDcraft：`!collectBlocks("oak_log", 1)`），
  只有复杂行为才现写代码 —— 可靠性差别很大。
- A25.9 **快慢分工**（实测：GPT-4 每动作 25 秒，本地 7B 300~500ms）：
  走位/躲怪/应答走**本地模型**，造房子/定目标走**云端模型**。直接依赖 A23 双路由。
- A25.10 生成的代码必须**限时执行 + 失败计数 + 熔断**（Voyager 的已知坑是
  反复试同一个错法、一直烧额度）。依赖 A30。

### 档三 · 手柄游玩（本地双人 / 局域网双人，非 Minecraft）

- A25.11 屏幕捕获 + 状态理解（复用档一的 A25.1 / A25.2）。
- A25.12 **输入用虚拟手柄**而不是模拟键鼠 —— 本地双人本来就是手柄分屏，
  虚拟手柄更贴合"第二个玩家"这个身份，也更容易做频率上限。
- A25.13 **全局急停热键**，任何时候一键切断输入。
- A25.14 进本档必须**逐游戏显式授权**，默认只读。

### 档位判定

- A25.15 要有一张**游戏档位表**（游戏 → 允许的最高档位），网游条目**不可提升**。
  不在表里的游戏默认档一。档位由 A29 的权限模型统一管辖。
  ← **已落地**：`config/game_tiers.json`（3 档 / 4 类别 / 7 个游戏条目）
  + `tools/check_platform.py` 七项静态闸。负控验过四种改坏法：
  把英雄联盟提到档三、把网游类别解锁、给档一偷开键盘口、把默认档改成档三 —— 全部判红。

## A27 实时接取信息并回应（2026-10-14，用户原话："像 neuro-sama 一样实时接取信息并回应"）

## A29 统一权限模型（2026-10-14 审计补登，横切 A25/A26/A27）

P4 这批能力合起来意味着：AI 能**看屏幕、控键鼠、读文件、联网、常开麦克风**。
这几件事单独看都合理，凑在一起就是一个很大的攻击面 —— 而现在只有 A25.4 一句
「逐游戏授权」在管它。必须有统一的权限模型，否则每加一个能力就多一个后门。

- A29.1 能力按**危险度分级**：只读（看屏幕/读文件）< 发声 < 联网 < 控键鼠 < 写文件/执行代码。
- A29.2 每一级要**独立开关**，默认全部关闭，开启要用户显式确认一次。
- A29.3 **全局急停**：一个热键切断所有"动手"类能力（键鼠控制、代码执行），任何时候可用。
- A29.4 **敏感区域屏蔽**：屏幕捕获要能排除指定窗口/区域（密码管理器、银行页面）。
- A29.5 **操作留痕**：所有"动手"类操作写审计日志，可回看 AI 都干了什么。
- A29.6 麦克风/屏幕**正在被读取时要有显眼的指示**，不能偷偷开着。

## A30 成本熔断（2026-10-14 审计补登，横切 A23/A27）

实时回路（麦克风常开 + 屏幕持续捕获 + 视觉模型）走云端 API 会非常烧钱，
而现在只有 G3 的「预算告警」—— **告警不是熔断**，而且 G3 还没做。

- A30.1 **硬上限**：按日/按月设花费上限，到顶**自动停**而不只是提醒。
- A30.2 **分能力配额**：视觉/语音/文本各自独立计额，一个失控不拖垮全部。
- A30.3 **降级而非停摆**：到额度先切本地模型、降采样率、降帧率，最后才停。
- A30.4 **预估先行**：开启实时模式前，按当前设置估算每小时花费并告诉用户。
- A30.5 空闲时**自动降频**：没人互动就把捕获与推理降到最低。

## A31 性能预算（2026-10-14 审计补登，横切 A25/A27 与 B1）

实时陪玩时同时在跑：屏幕捕获 + 视觉推理 + STT + TTS + 立绘渲染。
桌宠本体必须始终流畅，否则"陪伴"变成"卡顿"。G27 只管了**待机** CPU < 2%。

- A31.1 立绘渲染**永远优先**：其余任务不得让桌宠掉帧。
- A31.2 实时模式下的占用上限要有明确数字，并实测记录（CPU / 内存 / 显存）。
- A31.3 捕获与推理**可独立降档**（帧率、分辨率、模型大小）。
- A31.4 本地模型推理要能**让出资源**：用户自己玩游戏时自动退让。
