# 教训与陷阱（LESSONS）

> 规则：**同一个坑掉两次就是失职**。摔过一跤就写在这里，写清"症状 → 原因 → 正确做法"。

## 一、代码陷阱（已踩过）
1. **deflate 的 distance=1 回溯**：只有当"紧邻的前一个字节与当前字节相同"且"前面已输出过至少 1 字节"时，
   才能用 RLE 复制。否则解码器复制的是前一个字节（`…01 00 00 00…` 被解成一片 `01`）。
   症状：PNG 能解码但 adler 校验失败 / 图像内容错误。**验证方式：与真实 zlib 往返比对。**
2. **合成颜色被钳成纯白**：`zimg` 的 `sample_premul()` 输出颜色归一化到 0..1，而 `zimg_draw()`
   里若再乘 255 就会饱和。约定：**预乘采样一律归一化 0..1**，输出前才乘 255。
3. **`z_dirname()` 原地修改传入缓冲**：`z_path_join(buf, …, "logs/pet.log"); z_dirname(buf);`
   会把 buf 变成 "logs"，后面再用 buf 就错了。**先拷一份再 dirname。**
4. **区域命中坐标未换算**：`regions` 用画布坐标（848×1360），而窗口/帧是缩放后的（如 466×748）。
   平台层必须先把帧坐标换成画布坐标（`zrig_frame_to_canvas`），否则缩放一变就点不准。
5. **唤醒不能用普通请求**：`sleep` 优先级最高且声明 `interruptible: false`，
   任何唤醒必须 `force=1`，否则被状态机拒绝、角色"睡死"。
6. **JSON 生成器 key 后的逗号**：写 key 时已输出逗号，值再走一遍 `w_pre_value()` 会多一个逗号
   （症状：`{"a":1,,"b":2}`，解析失败）。用 `after_key` 标志短路。
7. **JSON Schema 校验器崩溃**：schema 里写 `"type": 123` 这类非法值时不要顺着继续走；
   取子项不能用只支持数组的 `zjson_at`（对象也要能按序号取）。
8. **mini 正则不支持 `{n}`**：`^#[0-9A-Fa-f]{6}$` 这类颜色 pattern 必须支持 `{n}`/`{n,m}` 量词，
   否则合规配置会被误判为错误。
9. **日志文件打不开**：见第 3 条；症状是启动就打印"[log] 无法打开日志文件: ./logs"。

## 二、素材陷阱（已踩过）
1. **洋红噪点残留**：AI 生成图的边缘有"距离远但色相仍是洋红"的抖动像素。
   只按"到键色的欧氏距离"抠图会漏掉它们（放大 4 倍才看得见）。
   正确做法（已实现）：距离判定 **或** 色相判定（`R+B-2G > 阈值`）+ 去孤立点 + **边缘颜色用内部像素外扩**。
2. **白边/棋盘格**：JPG 没有透明通道，棋盘格是画进去的，不能当素材（旧交接文件已警告）。
3. **部件整块裁剪会露馅**：嘴部若直接矩形裁剪会把肤色方块盖在脸上（颜色相近但一动就穿帮）。
   正确做法：按"比周围肤色暗"生成 alpha 蒙版（`mask_mouth()`），只留嘴线。
4. **一张图里抠眼睛（旧路线）**：四次迭代都失败（残留与横带）。
   正确做法：眼睛/嘴**单独生成或按固定框裁剪**，且**所有表情图必须用同一取景**，
   这样才能保证部件互换时位置不漂。
5. **取景不一致 = 部件对不齐**：生成表情图时必须在提示词里锁死"正面、同缩放、同位置"，
   入库前用脚本按眼睛位置做对齐归一（`tools/make_face_parts.py`）。
6. **几何拆件的手臂不能整块旋转**（2026-10-11 实测）：手臂是从单图层上竖切下来的，
   里面必然带着一条外套前襟。绕肩旋转 26° 时那条会甩到身体轮廓外，肩口还会露出锯齿切口。
   能兜住的角度 = 重叠带 ÷ 肩到手的距离 ≈ `38 ÷ 276` ≈ **8°**，挥手远不够用。
   正确做法：手臂改用**网格形变** `bend_x/bend_y` + `curve=tip`（顶边=肩 钉死，越往下位移越大），
   肩口永不开裂，和 Live2D 的手臂变形器同一个思路。真要大幅旋转，先补关节图（GAPS G4c）。
7. **关节重叠带里不能存错内容**：躯干顶端那条重叠带原本是**下巴**，头一转就露出"第二个下巴"。
   必须把它换成颈线那一行向上复制的"脖子桩"。重叠带的作用是"露出来也像那么回事"，
   所以里面装的必须是**被遮住的那层**该有的东西。

## 三、流程陷阱

2. 短发与中长发**都要**（当发型部件处理）。

## 五、表情对齐（2026-10-11 踩坑，未解决）
1. **虹膜检测不适用于闭眼/困倦/开心^^表情**：这些图没有可见虹膜，且蓝色发尾会被误认成虹膜，
   导致缩放和锚点跳变（同一批图缩放从 0.2 跳到 0.6）。
2. **肤色脸框高度不可靠**：脸框的肤色掩膜会连到脖子与肩部，高度随表情与取景变化，不能当尺子。
3. **结论**：自由生成的表情图不能靠算法事后对齐，必须在生成阶段就锁死取景（或人工给每张图标注锚点）。
   下一步候选：① 用同一张"底稿"做 img2img 只改表情（保持取景）；② 对每张图人工标注双眼中心（一次性、可复核）。

## 七、引擎与配置陷阱（2026-10-11 互动扩展中踩到）
- rig.json 动作缺省 loop 不能默认 true：`zjson_bool(obj,"loop",1)` 会让所有没写 loop 的动作（head_pat、happy…）永不结束。缺省必须是不循环，循环动作显式写 `"loop": true`。
- 帧缓冲在第一次 `zpet_tick` 之前是空的（opacity 0），测试和预览取区域前必须先 tick 一次。
- 非强制动作请求会被“循环中的高优先级动作”挡住：测试里要先 tick 到动作播完再请求，否则误判为逻辑错误。
- zjson 的 `zjson_get_*` 对缺失的可选字段会立即写一条警告到日志（zdiag_warn 直接打印），不能用“静默 diag”绕过；可选字段要先判断键是否存在再调用。
- 在 bash 工具里不要把 cwd 写进 command 参数里（会导致调用失败）；复杂的 Python 编辑请先写成临时脚本文件再执行。

## 四、构建与进程陷阱（2026-10-11 新增）
1. **`make preview` 是“编译 + 前台运行”**（Makefile 的 preview 目标最后一行直接起服务），用它“只编译”会把工具调用阻塞到超时。正确做法：只编译用 `make build/zhuochong_preview`；起服务用后台进程工具，命令 `./build/zhuochong_preview --root . --web web --port 5173 --bind 0.0.0.0`。
2. **改了 C 代码，运行中的预览进程不会自动更新**：必须先停进程、再重编（否则二进制被占用）、再起新进程。症状：接口都 200、代码也编过，但画面还是旧行为。
3. 重编前 `rm -f build/zhuochong_preview`，避免拿到被占用的旧文件。
4. **`pkill -f <关键字>` 会匹配到自己所在的 bash 命令行**（命令字符串里含同样的关键字），结果把自己的 shell 一起杀掉，后面的命令全不执行。要杀进程用精确 pid（`ps` 取 pid 后 `kill`），或用进程管理工具停。
5. **对 Python 生成器做字符串替换时，`return {` 这种片段会命中内层函数**（我把 `part()` 的 return 换掉了，结果 rig.json 里 5 个部件变成 null，而脚本不报错）。改生成器要么用唯一上下文（带上下一行的字段名）定位，要么直接改文件内容后**立刻重跑并校验产物**（部件数、关键字段非空）。
6. 单图层素材下**不要给 head 组发 rot_deg**：画上去的头不会转，只会把贴在上面的五官转走（实测眼睛相对脸部的偏移波动 3.66px → 去掉后 1.06px）。拆出 head_base.png 后再恢复，make_rig.py 已按素材自动判断。

## 2026-10-12 边缘质量：抠像不是病根，零件切口才是

- **不要再去重写 `tools/prepare_sprites.py` 的抠像。** 试过两版\"更正确\"的做法，
  实测都更差（数字见 `docs/ART_PARTS.md` 5.7 的表）：
  - 距离斜坡软 matte + **预乘 LANCZOS 缩放** → 白边光晕 61 → **1197** 像素。
    原因：LANCZOS 有负瓣，强边缘预乘值过冲，再除以小 alpha 被放大成亮斑/紫斑。
  - 换无负瓣的 BOX → 缩放比 0.89、支撑只有 1.1 像素 ≈ 最近邻，
    边界硬跳变 4% → **25%**，锯齿更重。
  - 现用做法之所以够用：塗り足し（bleed）之后**直接按通道 LANCZOS**是安全的。
- **\"切割感\"来自零件切口的二值 alpha**，不是来自抠像。凡是\"按掩码从整图切一块\"的
  地方都要做软切口：掩码两遍 3×3 平均 → `clip(x*1.35−0.18)` → 内部拉回 1.0。
  刘海实测：边界硬跳变 100% → 0%。
- **残留指标要先验证再相信**：旧的 `check_white_residue`（接近纯白 + 半透明）会把
  浅紫头发的正常软边全算成残留；`magenta_residue`（R+B−2G>90）会把角色自己的
  深紫线稿（实测 (48,2,79)）算成残留。改判据以后**新旧数字不可直接比**，
  必须用同一套判据把旧图重算一遍。
- **沙箱没有 scipy**，形态学一律用 `np.roll` 八邻域自己写。

## 2026-10-12 零件做完要\"抓帧看\"，不能只看验收数字

`check_assets` 202 项全绿、`make test` 244 项全绿的情况下，眨眼在画面上是**坏的**
（`blink=1` 眼睛里还是眼白 + 虹膜下缘）。三条教训：

1. **遮罩是按颜色 flood 出来的，必然小于美术意义上的\"眼睛\"**：
   眼白下缘的淡蓝、外眼角的白都在判据之外 → 眼皮盖不住。量化方法：
   把闭眼帧和睁眼帧在眼眶范围内逐像素比，**一模一样的像素就是没被盖住的**。
2. **\"画了\"不等于\"看得见\"**：眼皮自己画的闭眼线落在遮罩外面，被一刀切掉。
   凡是\"画在零件边缘的细节\"，都要确认它在遮罩/可视范围之内。
3. **重建脚本缺一步 = 零件静默过期**：`rebuild_parts.sh` 原来没有眼睑步骤，
   身体一重切，眼皮还是旧几何。**新增零件必须同时加进 rebuild 脚本**，
   并且在脚本里排在依赖它的步骤（rig）之前。

## 2026-10-12 动画底层：三条踩坑（淡入淡出 / 物理 / 跟随）

1. **物理的"输入"不能只读驱动组的 `dx/dy`**。这个角色 17 个动作里，头部运动
   绝大多数写在 `head.rot_deg` 上（sway/idle/happy/clicked/hammered…），只有
   `root` 带位移。按通道取值的话，头一转头发纹丝不动。
   正解：用 `group_matrix(driver)` 把**部件锚点**变换一遍，取变换前后的位移差 ——
   旋转、父链、bend 跟随全都自动算进去。
2. **物理的"输出"必须是 `位置 − 目标`，不能是位置本身**。否则静止时
   弹簧停在 `ratio × 输入` 上，等于给静止姿势加了个永久偏移（头一歪，呆毛就永远歪着）。
   输出差值才能保证"动的时候晚一拍、停下来回原位"。
3. **测"淡入淡出"时别被波形本身骗了**。`pulse` 波形在 `t=t0` 时值就是 0，
   第一次写单测断言"`fade:0` 应该一帧到位"读到 0.00，查了半天其实是波形没走完。
   测幅度必须 tick 过 `dur` 的峰值点，测淡化要选 `sine`/常量这类 t=0 就有值的波形。

另：叠加顺序定死为 **动作（含淡化）→ 指针跟随 → 物理**。
跟随写在物理前面，转头才会甩起头发；物理写在最后，惯性就不会反过来污染动作。

## 2026-10-12 ASan 第一次跑就抓到两个真内存错

**症状**：`make asan` 直接 ABORT，而普通 `make test` 323 项全绿。

1. `zdeflate.c:221` **stack-buffer-overflow（读越界 1 字节）**。
   快速跳过判据 `data[i + best_len]` 里，`i + best_len` 可能**正好等于 n**
   （上一轮匹配一直吃到缓冲区末尾），这时就读到了缓冲区外第一个字节。
   这是 PNG 压缩路径，天天在跑，只是恰好没崩。
   **正确写法**：这个判据前面必须加 `i + best_len < n`。
2. `tests/test_core.c` **global-buffer-overflow**：写坏配置时手写了长度 `90`，
   而那个字符串字面量只有 89 字节。**长度一律用 `strlen()` 算，不许手写数字。**

**教训**：普通编译 + 单测**查不出越界与泄漏**，必须定期跑消毒器。
已加 `make asan`，并进了 `make check` 与 CI。

## 2026-10-13 拆件第七件（侧发/后发）：三条可复用的硬规律

1. **"看不见的像素"照样能害人**。原画里散着几百个 `alpha=1~4`、RGB 是纯绿 `(0,255,0)`
   这类抠像垃圾像素，正常合成下完全看不见；但只要有任何一步做**颜色外扩**
   （`grow_colors`、塗り足し、解污），把它们当成颜色源，就会被重写成 `alpha=255` 的亮点。
   实测躯干多出 88 个纯绿像素，静止看不出来，侧发一摆就在下巴边上闪一颗绿点。
   → **颜色外扩的取色源一律卡 `alpha > 32`**，并且只把"本轮新填的"加进源集合。
   同理：做任何按颜色分区的判据前，先想清楚半透明像素算不算数。

2. **"静止画面 0 像素差"只是及格线，不是验收线**。拆件的真正验收是**动起来之后**：
   零件一摆，原来被它盖住的补画区、塗り足し、垃圾像素全都暴露。
   本件的四个 bug（补画边、塗り足し越界、幽灵发梢、绿点）**静止时一个都看不见**。
   → 验收必须加一步：冻结时钟（`/api/pause?on=1`）把驱动参数推到 ±1 各抓一帧，
   在 5 倍放大下看"摆开后露出来的那块"。

3. **形态学运算要挑对**。补洞用 `fill_holes`，别用"膨胀再腐蚀"的闭运算：
   闭运算会把发丝之间的缝连成片，压在脸上的发丝就被判成脸。
   连通块过滤要在**所有项都合并之后**再做一次（本件把补画区的冷色并进后发之后忘了再过滤，
   脖颈阴影被塗り足し吹成了两个大菱形）。

4. **摆动曲线的"固定边"别搞反**。`zimg_bend_factor`：`tip` = **顶边固定、底端最大**（t²），
   `root` = 底边固定、顶端最大（u²）。后发第一版写成 `root`，结果是**头顶的剪影在晃**
   （摆动集中在帧 y63~88），整个头形都在变。口诀：**哪条边钉在身上就固定哪条边** ——
   呆毛根在下沿用 `root`，侧发/后发/刘海都是从头顶长下来的，一律 `tip`。

5. **压力测试写法三件套**（这轮为"摆动不露底"调了三次才有用）：
   ① **逐像素比，不能比总数** —— 头发一挪会顺手盖住别处的缝，总数相减是个大负数，
   挖了洞照样"通过"（实测 −294 → −285）；
   ② **只数"深处"** —— 头发本来长在剪影边上，摆开露出背景是对的，
   把剪影往里腐蚀 4px 再数，清白素材 7~10 px、真缺重绘 128 px，区分度才出来；
   ③ **模拟摆动要照引擎的曲线剪切**（顶边不动、t² 递增），整件平移等于把发根也搬走，
   而且上下平移会因为整行取整在零件自己身上切出 1px 横缝（假阳性）。
   **新加的检查必须拿"负例"证明它会红**：把左侧发底下的脸挖空 2310 px → 该项立刻 128 > 20。

6. **"交叉淡化"做不出半闭眼**。两张不同的画各 50% 叠起来必然是一只**灰色幽灵眼**，
   调 ramp 斜率、换先后顺序都只能缩短窗口、消不掉（证据：`eye_blink_sheet.jpg` 上排）。
   闭合这件事得靠**擦除/位移**去演——眼眶按下沿压扁 + 眼线跟着下滑；
   两张图只在**已经几乎重合**（都只剩下眼睑上一条线）时才交接，所以曲线要**两头让开**：
   睁眼件 `clamp((1−blink)·4)`、闭眼件 `clamp((blink−0.75)·4)`。

7. **零件只是"又画了一遍"，底图没挖，等于没拆件**。眼睛拆了四件，可脸上 `seg_head`
   原封不动画着整只睁眼——眼眶一收，露出来的是**脸上那只睁着的眼**。
   拆件的完成标准是：**把被零件盖住的那块从底图里挖掉并补画**，
   然后用静态闸守住（`check_assets`「脸上无残留睁眼」直接数眼眶区里剩的暗眼线 + 蓝虹膜像素）。

8. **改 anchor 必须同步改 pos**。`zimg_make_matrix` 的语义是"把 anchor 这个像素点放到 pos 上"，
   只改 anchor 不改 pos，整件会平移一整个锚点偏移。
   另外锚点要放在**内容的边**上，不能放在图的边上：眼眶图底部有空白行，
   锚点放 `[0.5,1.0]` 压扁时整只眼被"吸"向那条空白底边（单测实测下沿跑了 23px）。

9. **挖/补皮肤的三个实战细节**（这轮眼窝）：
   ① 抹一条线要**整条带状外扩**再抹，不能只抹暗像素——线里嵌的白色高光会成为填充色源，
   把线填成一排白方块；② 填一条**横线**用"按列上下插值"，四邻域外扩只能从两头爬，留灰糊痕；
   ③ 软边遮罩要用**软权重加权替换**（`w=clamp((α−24)/72)`），卡死阈值会在斜坡那圈留下原画
   （实测 988 粒白点）。

10. **切件工具切出来的"眼线"常常夹带别的笔画**。`eye_?_lash.png` 里混着虹膜左右两道描边，
   静止时盖在虹膜上看不出来，一随眼皮下滑就拖到脸颊上像两行灰眼泪。
   凡是**要动**的零件，先问一句"它里面有没有本该不动的笔画"，有就逐列只留第一段连续的墨。

11. **动一个零件之前，先确认那块像素到底归谁。** "裙下大腿抬腿露底"第一反应是"腿画短了"，
   真相是 `seg_torso` 切到了 776、**裙摆下那截大腿是画在躯干上的静止副本**。
   补画补半天都没用——它归错件了。逐件单独渲染一遍，比盯着合成图猜快得多。

12. **关节能不能转，取决于缺口开在哪一侧，不取决于补多少画。**
   腿绕髋旋转必在**裆侧裙摆下沿之下**撕口，而补画只能长在下沿**之上**，几何上填不进去；
   改成 bend（`curve:"tip"`，顶边钉死）就构造性零缺口。
   **凡是"从上往下挂 / 被上面的件盖住根部"的零件，一律 bend + tip，不要旋转。**
   曲线写反（`root`）= 根部甩出去，±20px 就漏 700+ 像素——这个错犯过两次（hair_back 一次、腿一次），
   现在已经写成静态闸卡死。

13. **塗り足し要补在遮盖件的"下面"，不是补在它的"边上"。**
   手腕的皮肤续出贴着袖口边补，转 ±20° 就从袖侧探出一小片飘肉。
   正解：续出的部分按 `erode(遮盖件掩码, D)` **往里缩 D 像素**，并让 `L·sin(θmax) < D`
   （实测 10·sin20°≈3.4 < 4 ✓）。同理，手件要画在前臂**底下**，不是上面。

14. **验收闸门必须做负控，否则很可能是"一直绿、其实什么都没量"。** 本轮一口气抓出三个假闸：
   ① **整行横带会量错部位**——腕线正好穿过裙摆，数出来的全是裙和腿（读数与髋 band 一字不差才暴露）；
   关节带与别的部件同高时，必须按该部件自己的外接框加**列窗**。
   ② **四向 `hole_mask` 测不出"敞口缝"**——缝朝外敞开时"左右还有身体"的条件不成立，
   把塗り足し删光照样读 0；要改成**同列上下夹心**。但取样窗套太大又会去数手指缝那种
   "本来就该有的洞"（读数随姿势乱跳 135/153），窗口要卡在关节线上下十几像素。
   ③ **压力姿势里整条链一起转，会把末端零件转出取样框**，框内空白恒为 0；
   **末端关节的闸要单独只转那一级。**
   一条闸写完先问："我把零件故意改坏，它会红吗？"——不会红的闸等于没有。

15. **协议/命名这类"全局口径"要在素材堆起来之前对齐官方。**
   小寻的参数表过去少 18 个标准 ID，还把左右眼并成一个 `ParamEyeLOpen` 别名、腮红自造 `ParamBlush`。
   能力上看不出问题，但凡是写死这些名字的东西（18 个动作、6 个表情、口型、外部工具）
   都会一起错，**越晚改代价越大**。对齐的办法是去拉官方源码（`cubismdefaultparameterid.ts`）
   和官方样本（`Haru.model3.json`），不要凭印象。

16. **"跳过即通过"的检查等于没有检查。** 把 `ParamBlush` 改名成 `ParamCheek` 之后，
   冒烟脚本里的 `if "ParamBlush" in pids:` 不成立，那一项**悄悄消失**（64 → 63 项）而不是变红。
   凡是 `if 条件: check(...)` 的写法，都要先 `check(条件本身成立)`；
   总项数变少也要当成信号去查。

17. **像素级的"参数有没有生效"必须先把时间冻住。** 两个不同时刻的帧相减，
   待机动作 + 呼吸的漂移就有十几像素，足以把"死参数"盖过去。
   正解 = 用同一个时间戳再 tick 一次（dt=0）。
   但要注意 **dt=0 不会让物理衰减**：弹簧不走，可输出 `pos − target` 会随驱动立刻变 ——
   上一个参数甩出去的摆动会污染全局基准帧，所以**每个被测项都要现拍自己的基准**。

18. **先去参考项目里翻，再决定怎么做——这一步能省掉一整条错路。**
   口型音素本来打算加 `ParamMouthA/I/U/E/O` 五个参数。翻完官方标准参数表
   （嘴只有 `ParamMouthOpenY` + `ParamMouthForm`）、Animaze 的 viseme 映射表、
   以及 airi 的 `wlipsync/vowel-driver.ts` 之后才确定：**母音是两个标准参数的组合**，
   自造五个参数就等于主动脱离标准。沙箱里别克隆（3 GB 还会被重置），
   用 `gh api .../git/trees/HEAD?recursive=1` 列目录 + `Accept: application/vnd.github.raw` 取单文件。

19. **"参数能动"不等于"看得见"。** `ParamMouthForm` 以前的 bind 是 ±0.08/0.06，
   在 466px 的渲染帧上只有半个像素 —— 单测能过（值变了），人眼完全看不出。
   判据要落在**画面**上：五个母音两两像素差 > 25px、い 必须比 う 宽。
   另外**锚点错了幅度就白给**：上唇线锚点在左上角时 sx 一缩是整条线往右平移，
   改成中点（`pos` 同步 412→434）才是两边一起咧开。

20. **可选依赖会悄悄降级，必须让它变红。** `make_lipsync.py` 没装 pypinyin 就产不出音素轨，
   包络还是能用（只是退回只开合）—— 这正是"跳过即通过"的翻版。
   做法：生成时打警告 + 自检加一条"口型包络带母音音素轨"，哪天有人用裸环境重跑，
   38/38 变 0/38 会当场红掉。

21. **"谁后跑谁说了算"这种事，别自己拍脑袋定，去查官方的执行序常量。**
   表情和口型都写 `ParamMouthForm`，顺序反了就是"笑着说う 嘴变中性"。
   官方把答案写在 `icubismupdater.ts` 的 `CubismUpdateOrder_*` 里
   （Expression 300 < LipSync 700），而**不是**在 `addUpdatableList` 的调用顺序里
   —— 照着调用顺序猜会猜反。

22. **抄官方算法前先看它的前提。** 官方 LipSync 用纯加算 `addParameterValueById(id, v, 0.8)`，
   前提是它的 LipSync 组**只驱动单调开合的 `ParamMouthOpenY`**。
   我们连 `ParamMouthForm`（±1，正负是两种相反嘴形）一起驱动，加算就会抵消。
   偏离官方做法可以，但必须：① 写清前提差在哪；② 登记进合规表；③ 配一条会红的负控。

23. **自己埋的"安全兜底"会把负控废掉。** `if (vis_mix <= 0) vis_mix = 0.8;` 看着像防呆，
   实际是"把 0 当没填"——于是"权重设 0 应该失效"这个负控永远红不了，
   顺带也让用户没法真的关掉这一层。防呆要用**夹范围 + 警告**，不要**替换语义值**。

24. **分层以后，老断言读的那一层可能已经不动了。** 音素从"回写基础参数"改成"合成时叠一层"后，
   `zrig_param_get()` 恒为 0，三条老断言全失效（但它们当时是"通过"的）。
   凡是改分层结构，必须把断言改读**最终值**，并补一条"这一层不许回写下层"的反向断言。

25. **三态的字段，setter 绝不能收 bool。** `blink_forced` 用 −1/0/1 表示"自动/不闭/强制闭"，
   `zrig_blink_force(zrig*, int)` 的实现却是 `r->blink_forced = on ? 1 : 0` ——
   调用方按字段语义写 `force(-1)` 想表达"交回自动"，反而被当成真 → 醒着也永远闭眼。
   单测当年只覆盖了 `force(0)`，`-1` 这条路从没测过。**语义值和布尔值不能共用一个入口。**

26. **"关掉某个子系统"≠"冻结它的输出"。** 眨眼的 `enabled` 本意是"自动眨眼定时器别跑"，
   却被写进了绘制判断 `if (blink_enabled && blink > 0.001) { 睁眼件淡出；闭眼件淡入 }`：
   关掉以后，表情/手动/动作推出来的闭合度全都跳过淡化，闭眼件 100% 不透明盖住睁眼件 = 一上表情就全闭眼。
   官方 `CubismEyeBlink` 的做法是**只写参数**，绘制永远只看参数值。
   凡是 enable/disable 开关，先问一句：它关的是**产生者**还是**消费者**？只能关产生者。

27. **把"立即生效"的 API 改成"渐进生效"，必须同时分出两个名字。**
   `zrig_viseme_clear()` 从硬切改成平滑松口之后，所有把它当"立刻清干净"用的地方全部失真 ——
   `test_viseme()` 在冻结时钟下根本收不完，误红了「い 比 う 宽」这类毫不相干的断言。
   做法：保留 `clear()` = 平滑，新增 `reset()` = 立刻，然后 `grep` 全部调用点逐个分流。

28. **负控要对着"被改坏的那条公式"算出预期数值再定阈值。**
   这轮第一版"小声说话要透出笑意"写成 `Form > −0.95`，而退回恒定权重时算出来是 −0.25，
   照样过 —— 负控等于没做。收紧成 `0.05 < Form < 0.65`（即"必须明显偏向笑的那一侧、又没完全盖住口型"）后才判红。
   另外选基准状态也要算：原先想用 SIL 帧测力度调制，但 SIL 会自动触发 release，根本测不到。

29. **像素闸也会"跳过即通过"：被测的东西可能被别的东西盖住或顶替。**
   笑眼那一轮三条负控全没红 —— 笑眼补片本来就盖住整只眼（去掉"隐含闭眼"看不出来）、
   眼线件下滑后也在同一位置留一条线（笑眼件不画也有暗像素）、两条睫毛线叠着画差异照样"够大"。
   **真素材的画面里同一块地方有太多东西在说话。** 办法有两条，都要用：
   ① 把不可见的机制加个**只读查询**，用数值断言（`zrig_eye_close/zrig_eye_smile`）；
   ② 另起一个**合成 rig**，把要分辨的几张图摆在**互不重叠**的位置，逐块数像素 —— 这才叫结构闸。

30. **先查官方示例模型的数据文件，比查文档快也准。**
   笑眼怎么做，文档只说"+ 时变成笑眼"；而 `Haru/expressions/F05.exp3.json` 一眼就给出完整口径
   （`EyeLOpen=0 Multiply` + `EyeLSmile=1 Add` + 眉 0.32）。
   官方示例仓库里的 `.exp3.json / .model3.json / .physics3.json` 是**可直接读的真实参数**，
   以后遇到"这个标准参数到底怎么用"，先 `gh api` 把示例模型的数据文件拉下来看。

31. **测动作必须逐帧推进时间，不能一次跳过去。**
   动作切换的淡入权重是在 `zrig_tick` 内部发现"动作变了"那一刻才起算的
   （`fade_t0 = 本次 tick 的 now`）。`tick(t0); request(a); tick(t0+2.0)` 看到的是
   **权重 0 的那一帧**，也就是"动作还没开始动"。一度让我以为挥手动作坏了。
   正确写法：`request(a)` 之后以 1/60 为步长 tick 过去。
   `zrig_action_elapsed()` 返回的是对的（它用传入的绝对时间），**别拿它当"动作已经生效"的证据**。

32. **一个参数绑多条通道时，分清"主力"和"点缀"，别把同一件事绑两遍。**
   给 `ParamBodyAngleX` 同时绑了躯干网格弯曲（主力）和胸组平移（点缀）之后，
   "五官要刚性跟住身体形变"那条单测红了，偏差正好等于胸组平移量。
   还有 `chest.sy` 这种**作用在整组上的缩放**：0.4%/格看着小，满格 4% 就能把 770px 高的
   上身顶端推走 30px。组级缩放的系数要按"满格时顶端跑多远"来定，不是按直觉。

33. **"按 bind 系数反算"是迁移既有动画数据的安全办法。**
   197 条调好的几何通道要迁到参数通道，不要重写（那些数值是美术成果），
   而是 `参数振幅 = 几何振幅 ÷ bind scale`，再用逐像素回归证明等价。
   换算表同时当守门人：遇到没登记的几何目标直接报错，几何通道就长不回来了。


34. **回归比对出现的每一处差异，都要找到机制解释，"余波""抖动"之类的说法等于没解释。**
   这轮 `surprised` 的最大差异落在 t=1.4（动作早就演完了），我第一反应写的是
   "结束后余波，合理"——其实那是个真 bug：动作演完那一帧把 pulse 满值整个闪了出来。
   判据是**时刻要对得上窗口**：循环动作只该在淡入期有差、非循环动作只该在淡出窗口内有差；
   差异出现在解释不了的时刻，就是有问题。

35. **一个效果有几条代码路径，就得在几条路径上都实现它。**
   动作淡出有两条路：当前动作（`a`）和正在淡出的旧动作（`prev`）。只改前者，
   动作演完切换的那一帧立刻露馅。官方的语义能直接提示这一点——
   FadeOutTime 是 **motion 自己的属性**，不是"接替者"的属性，
   所以凡是让这个 motion 出力的地方都要乘它。

36. **"函数写对了"和"调用处用的是这个函数"是两回事，单测只能保前者。**
   `z_ease_sine()` 的数值可以单测，但没法阻止哪天有人把 `compute_group_transforms`
   里的调用换回 `z_smoothstep`。所以 selfcheck 加了一组**静态闸**：正则抠出函数体，
   断言里面有 `z_ease_sine(u)`、没有 `z_smoothstep`、淡出乘法被 `tot > 0.0` 挡着。
   凡是"口径统一"类的要求，都该配一道这样的源码闸。
