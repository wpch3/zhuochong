```bash
# 起预览（后台进程工具，名称写"Website"之类的人话）
./build/preview --root . --port 5173 --host 0.0.0.0
```

### 3.3 素材流水线（禁止手写坐标）
```
AI 生成 → prepare_sprites.py（抠图去噪） → make_anchors.py（量关节锚点）
        → make_parts.py（五官拆件） → make_body_parts.py（身体分段）
        → make_rig.py（生成 rig.json） → check_assets.py（机器验收，不过就重做） → 入库
```
三个把关工具（2026-10-11 新增）：
```bash
# 锚点：从剪影量出 头顶/眼线/嘴线/颈/肩/肘/腕/腰/髋/膝/踝/脚底
~/.imgenv/bin/python tools/make_anchors.py --character xiaoxun --form teen
#   → characters/<id>/forms/<form>/design/anchors.json
#   → logs/asset_qa/anchors_preview.png（人眼复核用，不入库）
# 身体分段：按锚点把单图层身体切成 头/躯干/两臂/两腿 六件，关节留重叠带
~/.imgenv/bin/python tools/make_body_parts.py --character xiaoxun --form teen
#   → sprites/seg_*.png + sprites/body_parts.json
#   → logs/asset_qa/segments_preview.png（人眼复核切线，不入库）
# 验收：形状 IoU / 色卡距离 / 关节对位 / 无损切分 / 关节不露底 / 键色与白边残留
~/.imgenv/bin/python tools/check_assets.py --character xiaoxun --form teen [--strict]
#   退出码非 0 = 不合格；自检第 4 步已接入
```
分段三条铁律（都是实测踩出来的）：
- **横切靠重叠带，竖切靠真实轮廓**。头/腿是横切，留 3% 身高的重叠带就不会露缝；
  手臂在"离身行"（剪影出现 手臂|身体|手臂 三段）以下按真实剪影抠，以上才竖切，
  否则会把外套前襟和裙边一起带走。
- **重叠带里不能存"错的内容"**。躯干顶端那条带原本是下巴，一转头就露出重影下巴；
  必须用颈线那一行向上复制成"脖子桩"（最便宜的关节补图）。
- **腿的切线只在躯干 x 范围内判**：垂在两侧的手也是独立剪影段，不排除就会把裙子
  从髋部劈成两半；还要求连续 8 行、每段够宽，否则 1px 的描边缝隙就能骗过去。
- 色卡是数据：`characters/<id>/design/palette.json`（改配色只改这里，验收自动跟着变）。
- 锚点是数据：拆件、补图、rig 枢轴、换装对位都以 `anchors.json` 为准，**不手写数字**。
- **坐标一律脚本量取**，手写魔法数字必然对不齐（踩过）。
- 改 rig 行为优先改 `tools/make_rig.py` 并重新生成，**不要只改 rig.json**，否则下次重生成就丢。
- 验收不过：重试最多 3 次，仍不过**记录原因、不入库、不标完成**。

## 四、交付标准（什么算"做完"）

| 关卡 | 标准 |
| --- | --- |
| 编译 | **零告警**（告警等于没做完） |
| 单测 | `make test` 全通过；新功能必须补单测 |
| 自检 | `bash scripts/selfcheck_all.sh` **八步**全绿（第 1 步是新加的仓库静态自检） |
| 保险 | `make check` = 静态自检 + 单测 + **ASan/UBSan** + 冒烟，一条命令全跑 |
| 互动 | `make smoke` 全过；改了动作/互动/区域/眨眼一定要跑 |
| 手测 | 预览 `http://localhost:5173/test.html` 测试台点一遍（动作/互动/滑杆都在这页） |
| 实测 | 沙箱内能验证的必须真跑一遍并给**数字证据**（帧差像素数、HTTP 码、基频 Hz、文件大小） |
| 文档 | 新机制要写进 `docs/` 对应文件，并在记忆区留指针 |
| 记忆 | `JOURNAL.md` 追加本轮日志；`MEMORY.md` 更新"当前状态"；要求有变更就改 `REQUIREMENTS.md` |
| 汇报 | 中文、无 emoji、带测试标签、给文件路径与任务号、给下一步 |

### 测试标签（必须标，不许含糊）
- `[测试锁]`：单元测试与构建能保证的。
- `[沙箱实测]`：我在沙箱里真跑过（给出命令与结果）。
- `[需真机]`：窗口透明、鼠标穿透、光标、动画观感、音频播放、Windows 持久化、GPU 训练 —— **只能由用户确认，代理不许宣布完成**。

## 六、汇报格式（用户要的样子）

2. 每条结论附**可查落点**：文件路径 / 任务编号 / 命令 / 实测数字。
3. 用户问了几条就答几条，**逐条对位**，不合并、不绕。
4. 不确定的说不确定，不替用户宣布完成。
5. **不用 emoji**；中文；不堆形容词。
6. 结尾固定给"下一步我打算做 A→B→C，有异议现在说"。

### 改完动作怎么验（2026-10-14 定，吃过亏）

调完动作参数，**不要靠眼睛看截图下结论，也不要自己临时写测量脚本** ——
临时脚本里几乎必然漏掉负对照，而漏了负对照的数字全是假的（LESSONS 78/79）。

```bash
# 1) 先量一遍现状
~/.imgenv/bin/python3 tools/measure_motion.py \
    --actions wave,sad,sleep --loop sleep --control nod --json /tmp/after.json

# 2) 想确认效果真来自新通道，必须做 A/B：
#    把那批通道从 rig.json 剥掉 → stop_process + start_process 重启 → 再量一次
#    两份 json 相减，差值才是你的贡献。负对照那一行的差值就是测量误差底。
```

三条硬规矩：
1. **必须有负对照** —— 一个确定不受本次改动影响的动作。它的读数是混淆底，
   没超过它就不能把效果归因到你的改动上。
2. **先看占天花板的比例** —— 超过 85% 说明指标饱和了，数字没有分辨力，
   循环动作要改用自方差（`--loop`）。
3. **循环动作的采样窗要盖得住一个周期** —— 工具会自动从 rig 读 freq 算周期并警告。

停预览进程用 `stop_process` 工具，**不要用 `pkill -f`**（同一条命令行里有同名字符串
会把自己杀掉，LESSONS 80）。

### 被打断之后的收尾动作（2026-10-14 定）

用户中途追加要求、打断当前工作时，恢复后**先做这三件事再往下走**：

1. **核对手头的活**：被打断时正在改的文件改完了没？`git status` 有没有半成品？
   本轮核对结果是三个提交全部收尾、工作树干净 —— 但这件事必须每次主动查，不能默认。
2. **找被推翻的结论**：新要求如果修正了旧理解，**旧理解写在哪些文档里**？
   断代最常见的形态不是漏做，而是文档里留着一句已经作废的话。
   处置是"加修正指引"而不是"删掉" —— 删了就看不出为什么会变。
3. **把打断本身记进 JOURNAL**：谁在什么工作中被打断、追加了什么、怎么调整的、
   手头的活收尾没有。时间线比结论更能防断代。

闸：`selfcheck_repo.py: check_no_stale_decisions()` 按节检查
"说了排除就必须说现行口径"，防的正是第 2 条。

### 四.2 自检报告分两栏读（2026-10-15 校准，A34）

`make selfcheck` 末尾现在分两栏：

```
合计 295 项，0 项不通过
  · 工程事实 243 项  ← 红了 = 软件坏了，必须拦住交付
  · 文档纪律  52 项  ← 红了 = 记账没跟上，当轮补齐
```

**为什么要分**：加了结论登记表和真机验收清单之后，一度出现 600 项里 324 项（54%）
在检查"我有没有好好填表"。项数一膨胀，"0 不通过"这个信号就变便宜了。
同一天把这两个闸从"条目 × 字段各算一项"折叠成"每条规则一项"（324 → 16），
**六次负控逐条复验，报红能力完全没变** —— 少的只是注水的计数。

**加新闸时的规矩**：一条规则一项，违例列进 `detail`。
不要为了"项数好看"把一条规则拆成 N 项。

## 十、REF-FIRST：做任何「新动作 / 新姿势 / 新部件」的标准工序

> 2026-10-22 第三十八问用户给的做法，第三十九问要求**写进规范全盘接收**。
> 一句话：**先有参考，再有活**。参考不是做完之后拿来比对的，是**开工前就要有的输入**。
> 用户的理由：「这样做起来会节省很多的功夫，就不用绕这么多弯子。」——
> 事实也确实如此：第三十八问靠这套流程，一次就把「旧挥手是交警指路手势」这件事
> 钉死了，而在这之前我已经凭空调了两轮参数。

### 10.1 七步（顺序不许换）

| # | 步骤 | 产出 | 做不到就停下 |
| --- | --- | --- | --- |
| 1 | **查资料**（铁律 4） | `docs/REFERENCE_NOTES.md` 新一批，带 URL | 没查到就继续查，别开始改 |
| 2 | **出参考图** | `characters/<id>/design/pose_ref/*.png`，**入库** | 必须用角色自己的底图当参考，画风/服装/比例要一致 |
| 3 | **看参考图** | `read_file` 逐张打开，写下看到了什么 | 不许只看缩略图 |
| 4 | **量参考图** | 网格图 `logs/asset_qa/*_grid.png` + 读数表 | 人工读点；用已知长度反推缩放校验 |
| 5 | **FK 预演** | 用骨架真值算落点，确认不越画布、不穿头 | 算出来不对就回第 4 步，别先跑重建 |
| 6 | **离线模拟** | `/tmp/armsim*.py` 直接旋转切件合成 | **比 14 分钟的全量重建快 1000 倍**，方案筛选全在这步 |
| 7 | **落 rig → 实拍 → 叠图** | 实拍序列 + 参考/现状/叠加三格 | 叠图不像就回第 4 步，不许嘴上说"已经很接近了" |

### 10.2 量图的硬规矩

* **人工读点优先**：打 50px 网格，自己把关节坐标读出来写进注释。
* **自动检测默认不可信**，用之前先想「它会把什么当成目标」：
  - 「袖子最上端＝肩」⇒ 举起来的手臂最上端是**袖口**；
  - 「蓝色区域＝虹膜」⇒ 蓝鲸发夹和蓝发梢同样是蓝的，缩放错 8%；
  - 「薄荷色＝袖子」⇒ 球鞋、发梢、滚边也是薄荷色。
  只有**限定窗口内的单条伸直肢体**适合用 PCA 求主轴。
* **缩放必须用已知量反推**：参考图上量上臂 165px ÷ rig 的 162.4px ≈ 1:1，这才敢对齐。
* **量摆动要分左右缘**：量"总宽度"会让左右反向位移互相抵消（第三十七问据此误判
  "头发几乎不动"，第三十八问翻案：左摆 18px / 右摆 21px）。

### 10.3 验收（铁律 5）

必须同时满足，缺一条都不算做完：

1. **关节角** 与参考图一致（±5°）；
2. **端点落点**一致 —— 手在头的哪个方位、高过头顶还是在眼睛高度、离头多远；
3. **与身体的相对关系**一致 —— 是"举起来贴着身体"还是"斜着伸出去"；
4. **叠图**：渲染帧和参考图按同一比例、同一肩点叠加，三格并排自己看过；
5. **动作序列**（不是单帧）实拍，至少 6 帧，首帧和末帧要回到待机。
