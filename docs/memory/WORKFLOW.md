### 3.3 素材流水线（禁止手写坐标）
```
AI 生成 → prepare_sprites.py（抠图去噪） → make_anchors.py（量关节锚点）
        → make_parts.py（五官拆件） → make_body_parts.py（身体分段）
        → make_rig.py（生成 rig.json） → check_assets.py（机器验收，不过就重做） → 入库
```
三个把关工具（2026-10-11 新增）：
```bash
# 锚点：从剪影量出 头顶/眼线/嘴线/颈/肩/肘/腕/腰/髋/膝/踝/脚底
~/.imgenv/bin/python tools/make_anchors.py --character xiaoxun --form teen
#   → characters/<id>/forms/<form>/design/anchors.json
#   → logs/asset_qa/anchors_preview.png（人眼复核用，不入库）
# 身体分段：按锚点把单图层身体切成 头/躯干/两臂/两腿 六件，关节留重叠带
~/.imgenv/bin/python tools/make_body_parts.py --character xiaoxun --form teen
#   → sprites/seg_*.png + sprites/body_parts.json
#   → logs/asset_qa/segments_preview.png（人眼复核切线，不入库）
# 验收：形状 IoU / 色卡距离 / 关节对位 / 无损切分 / 关节不露底 / 键色与白边残留
~/.imgenv/bin/python tools/check_assets.py --character xiaoxun --form teen [--strict]
#   退出码非 0 = 不合格；自检第 4 步已接入
```
分段三条铁律（都是实测踩出来的）：
- **横切靠重叠带，竖切靠真实轮廓**。头/腿是横切，留 3% 身高的重叠带就不会露缝；
  手臂在"离身行"（剪影出现 手臂|身体|手臂 三段）以下按真实剪影抠，以上才竖切，
  否则会把外套前襟和裙边一起带走。
- **重叠带里不能存"错的内容"**。躯干顶端那条带原本是下巴，一转头就露出重影下巴；
  必须用颈线那一行向上复制成"脖子桩"（最便宜的关节补图）。
- **腿的切线只在躯干 x 范围内判**：垂在两侧的手也是独立剪影段，不排除就会把裙子
  从髋部劈成两半；还要求连续 8 行、每段够宽，否则 1px 的描边缝隙就能骗过去。
- 色卡是数据：`characters/<id>/design/palette.json`（改配色只改这里，验收自动跟着变）。
- 锚点是数据：拆件、补图、rig 枢轴、换装对位都以 `anchors.json` 为准，**不手写数字**。
- **坐标一律脚本量取**，手写魔法数字必然对不齐（踩过）。
- 改 rig 行为优先改 `tools/make_rig.py` 并重新生成，**不要只改 rig.json**，否则下次重生成就丢。
- 验收不过：重试最多 3 次，仍不过**记录原因、不入库、不标完成**。

### 改完动作怎么验（2026-10-14 定，吃过亏）

调完动作参数，**不要靠眼睛看截图下结论，也不要自己临时写测量脚本** ——
临时脚本里几乎必然漏掉负对照，而漏了负对照的数字全是假的（LESSONS 78/79）。

```bash
# 1) 先量一遍现状
~/.imgenv/bin/python3 tools/measure_motion.py \
    --actions wave,sad,sleep --loop sleep --control nod --json /tmp/after.json

# 2) 想确认效果真来自新通道，必须做 A/B：
#    把那批通道从 rig.json 剥掉 → stop_process + start_process 重启 → 再量一次
#    两份 json 相减，差值才是你的贡献。负对照那一行的差值就是测量误差底。
```

三条硬规矩：
1. **必须有负对照** —— 一个确定不受本次改动影响的动作。它的读数是混淆底，
   没超过它就不能把效果归因到你的改动上。
2. **先看占天花板的比例** —— 超过 85% 说明指标饱和了，数字没有分辨力，
   循环动作要改用自方差（`--loop`）。
3. **循环动作的采样窗要盖得住一个周期** —— 工具会自动从 rig 读 freq 算周期并警告。

停预览进程用 `stop_process` 工具，**不要用 `pkill -f`**（同一条命令行里有同名字符串
会把自己杀掉，LESSONS 80）。

### 10.1 七步（顺序不许换）

### 10.2 量图的硬规矩

* **人工读点优先**：打 50px 网格，自己把关节坐标读出来写进注释。
* **自动检测默认不可信**，用之前先想「它会把什么当成目标」：
  - 「袖子最上端＝肩」⇒ 举起来的手臂最上端是**袖口**；
  - 「蓝色区域＝虹膜」⇒ 蓝鲸发夹和蓝发梢同样是蓝的，缩放错 8%；
  - 「薄荷色＝袖子」⇒ 球鞋、发梢、滚边也是薄荷色。
  只有**限定窗口内的单条伸直肢体**适合用 PCA 求主轴。
* **缩放必须用已知量反推**：参考图上量上臂 165px ÷ rig 的 162.4px ≈ 1:1，这才敢对齐。
* **量摆动要分左右缘**：量"总宽度"会让左右反向位移互相抵消（第三十七问据此误判
  "头发几乎不动"，第三十八问翻案：左摆 18px / 右摆 21px）。
* **量肢体角度不要对整块掩膜做 PCA**（第四十问血的教训）：肩根那摊"喇叭口"会把主轴
  往竖直方向拽，读出来的角是假的。正确三步：① **连通域**（洪水填充，种子点放在肢体
  中段）把袖子从身体同色区切出来；② 沿主轴每 6px 切一刀横截面，取 2~98 百分位的中点
  连成**中线**；③ **只取靠末端的 60%** 拟合直线。标定自检：命令角每差 5°，量出来的
  渲染角应当正好差 5°（线性）；不线性就说明掩膜还脏。
* **坐标能算就别用眼睛读**：第四十问我在网格图上读袖口中心 (610,205)，算出来是
  (670,174)，差 70px。眼睛是用来**判好不好看**的（铁律 2），不是用来读坐标的。

### 10.3 验收（铁律 5）

必须同时满足，缺一条都不算做完：

1. **关节角** 与参考图一致（±5°）；
2. **端点落点**一致 —— 手在头的哪个方位、高过头顶还是在眼睛高度、离头多远；
3. **与身体的相对关系**一致 —— 是"举起来贴着身体"还是"斜着伸出去"；
4. **叠图**：渲染帧和参考图按同一比例、同一肩点叠加，三格并排自己看过；
5. **动作序列**（不是单帧）实拍，至少 6 帧，首帧和末帧要回到待机；
6. ★**先看整张全身帧，再看放大块**（第四十一问用户打回才补上的一条）——
   裁剪框是用来**放大细看**的，不是用来**代替整体验收**的。
   第四十问我全程只看 `(120,10,466,420)` 这个上半身框，结论"肩/腕/腋下 3× 无破洞"，
   而用户一眼就看见**腋下挂着一块尖角布片**和**胸口压着一块青色楔形**——
   两处都在框外或框边。顺序固定为：**整帧 1× → 整帧 1.5× → 逐块 4~8×**，
   逐块至少覆盖：肩根 / 肘 / 腕 / 另一条手臂 / 腰胯 / 膝 / 脚 / 头。
7. ★**同一动作要同时看"改前/改后"两张**，而且是**同一个裁剪框**；
   只看改后那张，很容易把"本来就有的毛病"当成"背景"忽略掉。

### 10.4 参考图和成品**比例不一样**时怎么办（第四十问）

参考图是生成出来的"姿势说明书"，**不是我们的角色本人**——它的脖子、肩高、臂长
跟我们的骨架可以差很多。开工前先量两个比值，判断是不是同一套比例：

| 比值 | 参考 `wave_out.png` | 小寻 teen 骨架 |
| --- | --- | --- |
| 肩到下巴 ÷ 头高 | **0.17**（短脖子构图） | **0.48** |
| 肩到腕 ÷ 头宽 | 0.75 | 1.1（臂更长） |

不是同一套 ⇒ **绝对位置 IK 作废**。第四十问把参考的袖口按头宽配准到我们 rig 坐标，
得 (698,228)，离肩 (523,464) 有 294px，而我们臂展只有 278px——**目标在臂展之外**，
二连杆 IK 于是给出"上臂竖直 + 肘折 72°"这种鬼姿势（差点照着做了）。

这时只能二选一，**而且要明说选了哪一个**：

1. **对关节角**（保姿势语义）：手臂朝向和参考一致，手的落点随我们自己的比例走；
2. **对手的落点**（保画面观感）：手落在相对头部的同一位置，臂向差几度认了。

**怎么选 —— 看用户点名的是哪一条。** 第四十问用户说的是"手不够高"⇒ 选落点（取 −130，
臂向 34.9° vs 参考 44.8°）。**定稿用叠图，不用数字**：把参考按头宽缩放、染成半透明红，
压在实拍帧上，看哪一版的楔形空隙最小（`logs/asset_qa/q40_ghost.png` 三格并排）。

#### ★★★ 10.4a 上面这条被**第四十三问推翻了一半**：落点可以让，结构不能让

用户原话：「都说了是参考图，你给我说规格不一样？**那你连个正常人的结构都做不了吗？**」

第四十二问我按"选 2（对落点）"办事，为了把手送到眼睛高度，把上臂一路甩到
离竖直 **110°**（抬过水平）——手是到位了，**姿势散了**：肘尖飞到体侧外 60px 与肩同高，
手离头发 100px，读成"横着伸胳膊"。所以二选一的前面要加一条**不可让渡项**：

> **先抄结构，再谈落点。** 参考图里让这个动作"成立"的那几条关系
> （哪根骨头贴着身体、关节在不在轮廓内、内角多大、掌心朝哪）必须原样搬过来；
> 落点只能在**保住结构**的参数区间里尽量靠近，靠不到就认，并在汇报里写清楚。

落实到动作上，开工时先把参考图的结构写成一句话再动手。挥手这个例子：
**"上臂贴着体侧垂下、肘留在腰侧（横向不离开躯干轮廓太远）、前臂贴着身体竖起来、
肘折成窄 V、掌心正对镜头"** —— 定稿 A_u=70° 就是在这句话的约束下扫出来的最高手位。

配套两条硬规矩：

- **扫参数要实拍成图、和参考并排看**，别算完就定（`q43_sweep.png` → `q43_sweep2.png`
  → `q43_vs_ref.png` → `q43_finalists.png`，一共 12 档，每档都看过）。
- **末端件要单独回正**：前臂内倾 29° 时手跟着倾就成了"手背朝人"。参考图里掌心朝前，
  那就得在腕上补一个反向角度（本例 +21°）。父件转了，子件的"朝向语义"不会自动成立。

还有一条给闸门的：**不许只卡一头**。`ParamArmRA` 原来写的是 `> 5.0`（"越高越好"），
正是它让 110° 的横棍一路绿灯。能从两头跑飞的量，判据就要写成**区间**。

还有一条底线：**做不到就说做不到**。参考的指尖在发顶之上 +20px，我们手臂竖直也只到
−16px —— 这不是调角度能解决的，是比例决定的，**要在汇报里写清楚**，不许假装做到了。

### 13.1 三条跨领域的共性（这些才是真正通用的）
