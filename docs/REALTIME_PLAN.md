# 实时事件、对话轮次与取消协议（P0.3）

更新：2026-10-24。本文是后续实现的行为契约；目前不代表实时事件总线、麦克风链路或队列已实现。聊天/语音渠道接入前，先实现可注入假事件的本地核心并测试状态机。

## 1. 目标与非目标

**目标**：用户输入和桌宠事件能及时、可控地进入一个会话；系统能选择/合并/过期事件，明确当前轮次，支持打断、取消、去重、超时、断网恢复和成本预算；任何未经授权的来源都不得入队或外发。

**非目标**：本协议不要求接 Twitch、Discord、直播平台或常开麦克风；不定义具体 LLM 供应商；不实现直播聊天采样算法；不让 AI 自主无限发言；不改变 2D/Live2D 动画状态机或其渲染循环。平台适配器是未来独立模块。

## 2. 事件对象（概念字段）

每个输入都包装为事件，不把任意文本直接塞进模型请求：

```json
{
  "event_id": "unique-id",
  "session_id": "session-id",
  "source": "user_text | local_voice_transcript | pet_interaction | system_signal | approved_connector",
  "created_at": "local timestamp",
  "expires_at": "optional local timestamp",
  "priority": "urgent | normal | low",
  "content_ref": "text or local ephemeral payload reference",
  "sensitivity": "ordinary | personal | sensitive",
  "permission_scope": ["source-specific grant ids"],
  "dedupe_key": "optional source event key",
  "interrupt_policy": "may_interrupt | queue_only | never_interrupt",
  "cost_budget": "optional per-event limit"
}
```

实现时应避免把明文敏感内容写进通用队列日志；音频/图像使用短期引用或内存缓冲，不自动保存。时间戳使用一致的单调时钟处理过期与延迟，展示时间另用本地墙钟。

## 3. 接收与授权校验

1. 渠道适配器先验证来源、权限和载荷大小，再构造规范化事件。
2. 许可无效、来源关闭、内容超限或格式非法时，拒绝事件并给本地诊断；不进入模型队列。
3. 单个来源可关闭，不影响其它来源；默认只接收用户显式输入及应用内桌宠互动。
4. 外部连接器未来需提供来源身份、平台事件 ID、速率限制、权限 scope 和连接状态；适配器不得静默切换账号/平台。
5. 源事件中的提示词或文字视为不可信内容，不得更改系统权限、工具授权或安全策略。

## 4. 队列、优先级与公平性

- **分队列**：按会话和模态分区，避免一个连接器或生成任务堵住直接用户对话。
- **默认优先级**：用户当前发言 > 明确打断/停止 > 用户刚触发的桌宠互动 > 用户授权的外部事件 > 低优先级后台提醒。危险动作的确认请求不靠优先级跳过确认。
- **新消息合并**：仅对语义相近且仍未处理的低优先级事件允许合并；原始来源计数/引用保留；不得合并不同用户或不同会话数据。
- **过期丢弃**：按 `expires_at` 和策略丢弃迟到的事件；不把旧消息当成当前用户仍在等待；丢弃结果可见但不输出敏感内容。
- **公平性**：低优先级队列有最大等待时长与限流，不让事件无限积压；连续高优先级输入时允许低优先级过期，而不是无限延后。
- **预算**：事件数、队列容量、并发请求、每任务 tokens/成本/时间均有上限；超限后暂停并说明原因，不继续隐性消耗。

具体优先级、容量和 TTL 是产品配置决策，必须通过场景测试后确定，不在本规划中虚构数值。

## 5. 对话轮次状态机

```text
idle → accepted → queued → composing_context → generating
     → validating_output → speaking_or_displaying → completed
     → (new user input / stop) cancelling → cancelled
     → (timeout/provider/error) failed_or_degraded
```

- 一个会话只有一个“当前可听发言”轮次；并发模型请求可否存在由实现限定，绝不能并发播两段角色语音。
- 用户插话遵循明确策略：接受新事件 → 标记旧轮次取消 → 取消网络/模型生成（如果供应商支持）→ 停止 TTS 和播放队列 → 停止口型/说话状态 → 清理临时资源 → 开始新轮次。
- 用户停止/静音优先于队列；取消请求要可重复调用且幂等；取消后迟到的模型/TTS结果按 token/generation ID 丢弃。
- 取消不删除用户已输入的内容，除非用户选择清除；对已经发送到供应商的请求要如实说明本地取消无法保证供应商侧立刻停止处理。
- 普通桌宠动画（眨眼、呼吸、Live2D/2D 动作）与对话轮次解耦；对话状态可以向角色动画发事件，但不由 UI 线程阻塞渲染。

## 6. 上下文构建与输出

- 为每次模型请求显式列出输入来源：用户当前消息、选定的会话片段、经用户允许的记忆、工具结果和系统约束。
- 遵守最小披露：不把其他会话、其他代理或全局文件数据自动附加到上下文；敏感数据按权限策略排除。
- 输出先经长度/格式/安全校验，再进入显示/TTS；失败时可显示文本但不自动执行工具。
- 文本、语音、字幕和角色状态应关联同一个 `turn_id`；用户打断后所有过期输出均不得覆盖新轮次。
- TTS失败时保留文字输出；STT失败时提供文字输入回退；供应商离线时不得假装模型回复成功。

## 7. 可观测状态（面向用户）

至少提供：等待输入、排队/优先级说明、正在整理上下文、正在生成、输出校验、正在播报、被用户打断、已取消、已过期、供应商不可用/限速、预算耗尽、权限被拒绝。

状态文案只描述事实，不伪造百分比；错误要指出能否重试、是否会重复计费、用户可采取什么行动。详细诊断在本地查看且脱敏。

## 8. P0.3 验收拆分

**规划验收（本次完成到文档层）**：事件结构、来源/权限校验、队列/过期、轮次、打断/取消、上下文来源、输出失败回退和用户状态均已定义；明确平台/常开麦克风非当前前置。

**实现验收（尚未开始）**：注入假事件覆盖乱序、重复、超限、过期、权限撤销、队列洪水、延迟响应、用户插话、TTS失败、供应商断线/限速、预算耗尽；断言不重播、不双说、不串会话、不泄露、不无限重试。

**真机验收**：麦克风端点/打断延迟、音频设备切换、睡眠唤醒/断网重连及 Windows 声音设备行为；需用户本机测试，不能用沙箱测试替代。
