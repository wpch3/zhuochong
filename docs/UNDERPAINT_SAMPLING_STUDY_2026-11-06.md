# 遮挡补画与 C 引擎采样连续验证

## 问题

前一工作包的受限补画只保证原分辨率下袖手 alpha 为 255，三层 PNG 中立合成完全相同；真实 C 引擎缩放到 0.55 后中立帧仍变化 200 像素。直接把源 PNG 不变误作 C 帧不变不合适。

`src/core/zrig.c` 在需要时分别缩放各部件，`src/core/zimg.c` 的 `zimg_resize` 使用预乘 alpha 多样本缩小，绘制时再对每层采样并混合。分层分别滤波与先合成再滤波并不一般等价；需要通过实验验证而不是把推断作为既定修复。

## 工作步骤和验收

1. 对先前浏览器实际导出的同一补画，分别使用由各袖手独立 alpha=255 区域向内收缩 0/1/2/3/4/6/8 像素的掩膜，生成隔离候选。只做移除已有补画，不能改源图或创造新画稿。
2. 用两套临时 C 预览在多种缩放和中立、袖手向外/内极值进行固定步进帧对照；记录每项差异及仍可见的补画变化，明确哪些比例和状态经过测试、哪些没有。禁止据单一缩放声称普遍无差异。
3. 浅/深背景放大逐项目视中立和可动候选；即使某些中立帧为零，若动作期涂色仍不自然或没有真实底稿，也不得声称美术合格。对照与补画只作为隔离试验。
4. 如果实验表明保守范围确实有用，再为编辑器和候选生成器提供明确可选的安全边距并统一校验；保持旧补画可回放，默认策略、不可覆盖及限制均需记录。真实浏览器及 C 回归，最后提交并推送本分支。

## 执行结果

针对动态试装，使用上轮浏览器导出的旧版样例，以及覆盖所有袖手不透明区域的红色压力补画，各生成 7 种边距候选；所有候选都从未改动源 rig/PNG，独立 C 进程固定步进。表格为四种指定缩放的**中立帧变化像素**；并非通用安全证明。

| 内缩边距（源像素） | 旧版浅色样例：0.35 / 0.55 / 0.8 / 1.0 | 高对比红色压力补画：0.35 / 0.55 / 0.8 / 1.0 |
| --- | --- | --- |
| 0 | 136 / 200 / 259 / 0 | 613 / 955 / 1190 / 0 |
| 2 | 25 / 0 / 0 / 0 | 270 / 73 / 1 / 0 |
| 3 | 0 / 0 / 0 / 0 | 59 / 8 / 0 / 0 |
| 4 | 0 / 0 / 0 / 0 | 14 / 0 / 0 / 0 |
| 6 | 0 / 0 / 0 / 0 | 0 / 0 / 0 / 0 |
| 8 | 0 / 0 / 0 / 0 | 0 / 0 / 0 / 0 |

边距 3 对旧样例看起来足够，但在压力补画上仍漏色；不能仅凭旧样例结果下通用结论。边距越大，动态时真正露出的可补画区域也越小：旧样例 0.55 外摆从边距 0 的 532 像素变化降至边距 4 的 96、边距 6 的 7、边距 8 的 0。边距 6 在本次四个缩放的中立帧和红色压力补画上为零，**不保证其他比例、部件组合、动作、画布或引擎版本相同**。

## 已实现

- 浏览器工作台增加 0/2/4/6/8 像素选项，默认 6；对各袖手分别腐蚀，再合并结果，避免相邻部件相加形成错误保护区。改边距只在预览和导出时隐藏边距外的已有笔触，减小边距可恢复，手势与历史不丢；导出补画时以当前边距裁切。
- Python 候选生成器独立重算相同掩膜，默认 6 像素；超出即拒绝，不静默裁切。旧样例要显式 `--margin 0`；不同边距导出的新补画应指定对应 `--margin`。报告记录边距和来源哈希，原分辨率三层合成相等仍只是必要条件。
- 增加 JS/Python 算法跨语言对照、各袖分离腐蚀、边界和非法值测试；真实浏览器验证切换边距后收缩/恢复、取消手势、缩放、撤销与 PNG 导出，再将该导出载入真实 C。新增 C 红色压力补画测试：四个指定缩放下中立帧相等，0.55 外摆仍有差异。
- 实际查看了浅/深底 C 帧局部、较小和较大边距候选及最新浏览器画面。边距 6 几乎不影响动作接缝，故**没有修复视觉缺陷**，不能替代原创衣身、肩部和袖子隐藏画稿。旧动态试装、正式模型均未被覆盖。
