## 一、三条轴（互相正交，不要混在一条轴上讨论）

### 轴 1 · 年龄与体型 —— **已封板，四档，不再加第五档**

| id | 名字 | 头身比 | 状态 | 任务 |
| --- | --- | --- | --- | --- |
| `loli` | 萝莉 | 1:4 | planned | T2.2.1 |
| `teen` | 少女 | **1:4.65（实测）** | **ready** | T2.1 全家 |
| `adult` | 青年女性 | 1:7 | planned | T2.2.2 |
| `chibi` | Q 版 | 1:2.5 | 进行中（T2.2.5 压力测试） | T2.2.3 |

**为什么封板**：用户 2026-10-17 明确四档已覆盖全部年龄段。头身比 2.5 / 4 / 4.65 / 7
在同一条轴上已经拉满（相邻两档差 ≥ 15%，肉眼一眼能分），再插一档是**同质增量**：
成本要乘 8 个角色，收益只有"又多一个差不多的"。
⇒ 以后想加「幼女 1:3.2」「熟女 1:7.5」这类，先回来写清楚它和已有四档的区别。

### 轴 2 · 取景 —— **全身 + 半身，两个都要**

| id | 画什么 | 用在哪 | 状态 |
| --- | --- | --- | --- |
| `full` | 头顶到鞋底 | 桌宠常驻、换装展示、全身动作 | teen 已有 |
| `bust` | 头顶到腰（或胸口） | 对话窗、通话界面、表情特写、直播小窗 | 待做（T2.6） |

**半身不是"把全身裁一刀"** —— 三条理由，必须单独出素材：

1. **像素密度**。全身图里脸只占 ~15% 高度；同样的输出尺寸下，半身的脸能多拿
   2~3 倍像素。表情、眼神、口型这些最该看清的东西全在脸上。
   （现成的证据：T30 整条任务就是在和"素材上限 848×1360"较劲。）
2. **构图不同**。半身要重新安排手的位置（托腮、比耶、扶下巴），全身图里手垂在身侧，
   裁一刀之后画面下缘是两截断臂。
3. **参数集可以不同**。半身用不到腿/鞋/重心/踮脚那一组参数，但要补"更大幅度的
   上半身前倾/侧倾"。

**但契约必须一致**：参数名、动作名、挂件 id、表情名在 `full` 和 `bust` 之间**逐字相同**。
切取景 = 换一份 `rig.json`，上层（情绪表、口型、物理、挂件）一行都不用改。

### 轴 3 · 姿态 —— **全做**

| id | 姿态 | 优先级 | 说明 |
| --- | --- | --- | --- |
| `stand` | 站立 | P0（已有） | 默认姿态，全部动作的基准 |
| `sit` | 坐（椅子 / 地面） | P1 | 桌面边缘坐姿、工作陪伴态；腿部参数换一组 |
| `lie` | 趴（趴桌 / 趴地） | P1 | 摸鱼、撒娇、看屏幕；头部参数复用 |
| `sleep` | 睡（侧卧 / 趴睡） | P2 | 只要闭眼 + 呼吸 + Zzz 漫符，表情集可以最小 |

| `twin` | 双马尾 | ✅ **ready（teen + chibi）** 2026-10-18 | **T46.3** | 1 张（`design/redraw/hair_twin_bunch.png`，右束由左束**水平镜像**，锚点 x 取 1−x）⇒ 切件 teen 166×510，层 160/161 |
| `pony` | 单马尾 | ✅ **ready（teen + chibi）** 2026-10-18 | **T46.3** | 1 张（`design/redraw/hair_pony_back.png`）⇒ 切件 teen 280×640，层 57（在所有身体件之后） |
| `braid` / `bun` | 麻花辫 / 丸子头 | 候选 | T46.4 | 1~2 张 |

**技术底座（已经就位的部分）**：
- 换发型走**已有的 `poses` 互斥组机制**（猫尾三姿态、兜帽 on/off 用的就是它），
  不需要新引擎能力；
- 几何走 **T2.2.0 的相对锚点**（`ref` + `pos_rel` + `sprite_h_rel`）⇒ 一份长发素材
  自动跟着头身比走遍四个形态，不用为 chibi 单独画；
- 摆动走 **T46.1 刚补上的多段摇物**：后发已经是「根 + 梢」两段，长发只要把段数
  加到 3 段（教程口径：前髪・横髪 1 段、後ろ髪 2〜3 段、ツインテール 2 段、
  很长的后发有人做到 4 段）。

**硬成本只有一处：底图**。长发要盖住肩背，所以必须和"袖下躯干"一样
按 DC16 的规矩**把被挡住的地方画出来**，不能靠拉伸现有的短发壳
（实测它从 y116 到 y258 就没了，往下拉只会糊成一条）。

## 二、矩阵规模与"不手做 256 套"的办法

4 形态 × 2 取景 × 4 姿态 = **32 套/角色**；8 个角色 = **256 套**。
一套一套手做是不可能的，所以从一开始就按"**只有底图是新的**"来设计：

| 每一格需要什么 | 来自哪里 | 已经就位了吗 |
| --- | --- | --- |
| 底图（AI 出图，洋红底） | 人工 / AI | 每格都得新画 —— 这是唯一的硬成本 |
| `design/anchors.json` | `tools/make_anchors.py` 从剪影量 | ✅ 自动 |
| 身体拆件、眼/嘴/发/手臂/腿脚 | `tools/rebuild_parts.sh` 19 步 | ✅ 自动（chibi 正在验它够不够通用） |
| 挂件（猫耳/猫尾/兜帽/饰品）几何 | **相对锚点** `ref`+`pos_rel`+`sprite_h_rel`（T2.2.0） | ✅ 换头身比自动跟着走 |
| 挂件素材 | 角色级 `design/redraw/*.png`，按 `sprite_h_rel` 缩放 | ✅ 一份素材走遍四形态 |
| 服装（换色/换件/整套） | 角色级 `design/wardrobe.json` | ✅ 角色级共用 |
| 情绪表 / 动作 / 物理 / 参数 | `tools/make_rig.py` | ⚠️ 里面还有按 teen 量的像素常数，chibi 正在逼它们现形 |
| 表情差分件（闭眼/笑眼/张嘴/无刘海…） | 角色级 `design/redraw/*.png` + 配准 | ❌ **这些是按 teen 的脸画的**，换形态要重画 |

**结论先写在这里**：真正按格子线性增长的只有两样 —— ①底图 ②脸部差分重绘。
其余全是自动的。所以排期按"底图 + 差分"的张数算，不是按格子数算。

### 差分件的分档（不是每格都要全套脸）

* `stand/full` ：全套（闭眼/笑眼/痛苦闭眼/瞪大/张嘴/无刘海/无眉/无侧发）
* `bust/*`：**全套，而且最该有**（脸最大）
* `sit` / `lie`：脸直接复用同形态 `stand` 的差分件（取景一样、脸没变）
* `sleep`：只要闭眼 + 微张嘴

## 三、当前状态与执行顺序

```
年龄轴  loli ░░░░  teen ████  adult ░░░░  chibi ▓▓░░（进行中）
取景轴  full ████（仅 teen）   bust ░░░░
姿态轴  stand ████（仅 teen/full）  sit ░░░░  lie ░░░░  sleep ░░░░
发型轴  bob ████  long ██░░  twin ██░░  pony ██░░（四档都是 teen+chibi 已装、loli/adult 形态就绪；同属互斥组 hairstyle，默认档 none=bob）
```

**为什么第二个形态先做 chibi 而不是 loli**：loli(1:4) 和 teen(1:4.65) 只差 14%，
就算底层藏着"按 teen 量的常数"，偏 14% 也看不出来，等于白测。
chibi(1:2.5) 和 teen 差 **86%**，任何写死的像素常数都会当场错位。
**先用最毒的输入把底层打一遍**，之后 loli / adult 才是顺手的事。
