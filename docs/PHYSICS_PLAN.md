# 物理底座规划 —— 头发 / 衣服 / 兽耳 / 兽尾 的「真实摇晃」

> 2026-10-17 立。起因是用户问：「头发，衣服的真实摇晃物理效果，以及兽耳兽尾的，加在计划里没有？
> 目前还没有真实的物理效果，还有其他的物理效果需要吗？以及物理效果的底层做好没有？」
>
> 这份文档回答三件事：**① 底层到底做到哪一步了（带实测）；② 差在哪（逐条对官方口径）；
> ③ 怎么补（分阶段、每阶段都能单独验收）**。任务号落在 **T47**。

---

## 0. 一句话结论

**底层做了一半，而且做对的那一半是"难的那一半"，缺的那一半是"像不像"的那一半。**

- 已经对齐官方的：**固定步长积分 + 输入线性插值 + 帧间插值**（照搬 `CubismPhysics::Evaluate`）、
  **多段摆链**、**参数输入**（对齐官方 `Input[]`）、45 条摆的配置化、运行时开关与调试端点。
- 还没做的：**摆本身不是"摆"**。我们算的是一根 1D 弹簧，输出的是「滞后像素」；
  官方算的是**2D 粒子链**，输出的是「摆相对重力方向的角度」。
  没有重力、没有风、没有摆长、没有角度输入、没有碰撞、不能和 `physics3.json` 互通。

**所以"不真实"不是调参没调好，是模型本身少了一维和一个重力。**
这件事有一个一句话就能验的现象，下一节给出。

## 1. 现状盘点（`src/core/zrig.c`，实测，不是估计）

### 1.1 现在的摆是什么

```c
target = input * ratio;                             /* 输入 × 跟随比例 */
acc    = stiffness * (target - pos) - damping * vel;/* 1D 弹簧-阻尼 */
vel   += acc * STEP;  pos += vel * STEP;
out    = clamp(pos - target, ±max);                 /* ★ 输出 = 滞后量 */
```

| 项 | 现状 |
| --- | --- |
| 维度 | **1 轴**（`axis: 0=x / 1=y`，一条摆只看一个方向） |
| 输入 | 三选一：① 驱动组的位移 dx/dy；② 参数加权和（≤4 项，对齐官方 `Input[]`）；③ 上一条摆的输出（链式） |
| 输出 | **滞后量 `pos − target`**，写到部件通道（`dx/dy/rot/bend_x/bend_y`）或网格形变器的 `amount` |
| 积分 | 固定步长 + 输入插值 + 帧间 alpha 插值（**这一层和官方一致**，G113） |
| 规模（teen） | **physics 35 条 / 形变器 17 个 / 部件 69 个**；引擎上限 PHYS 48、DEFORMS 24 |
| 调试 | `/api/physics?on=0|1`、`/api/step?n=&dt=`、`/api/info.json` 读 `deformers` 实时值 |

### 1.2 一句话能验的毛病：**静止时它完全不动**

挂件表里（`characters/xiaoxun/design/attachments.json`）早就写死了这条注释：

> 「输入混了 `ParamBreath`，但 **本引擎的物理输出是「滞后量 pos−target」不是摆角**，
> 呼吸只有 0.28 Hz，摆锤完全跟得上 ⇒ 差值≈0。**实测只摆 0.3 px**。」

这就是用户说的"没有真实的物理效果"的**根**：

- 输出是滞后量 ⇒ **输入不动，输出必然是 0** ⇒ 人不动的时候，头发、尾巴、裙子是**死的**；
- 现在那些"自主摆动"全是 **motion 动作通道**在演（尾巴三姿态就是这么做的），
  动作是周期固定的，所以看久了就是"在循环播放"，而不是"在被物理推着动"。
- 社区那条著名配方「把呼吸混进物理输入，挂件就会一直晃」在官方引擎成立，
  **在我们这儿不成立**，因为官方输出的是**摆角**，呼吸让摆根上下走，摆角就一直在变。

### 1.3 现在这 35 条摆的参数（给改造做对照基线）

#### 1.3.2 风（T47.3 交付，2026-10-18）

风走**三路相加**，一起喂给内核的 `wind` 参数：

| 路 | 来源 | 干什么用 | 默认 |
| --- | --- | --- | --- |
| 定常风 | `forces.wind` / `/api/force?wx=&wy=` | 场景设定（室外、吹风机、剧情） | `(0,0)` |
| **常驻微风 breeze** | `forces.breeze{amp,hz}` | 角色**站着不动也有的那一点点飘** | `amp 0.03 / hz 0.11` |
| **阵风 gust** | `/api/force?gust_x=&gust_t=` 或 `zrig_phys2_gust()` | 情绪与事件（生气＝一股风掀一下，T51.1） | 无 |

两件必须记住的事：

1. **风的量纲是「几个 g」，不是像素。** 内核里 `力 = 重力单位向量 × Acceleration + 风`，
   重力本身的模是 1。所以 `wx = 0.3` 不是"三成像素"，是**重力的 30%**，
   实测已经能把长发吹到输出上限。引擎按 g 夹：`ZRIG_BREEZE_MAX 1.5`、`GUST_MAX 6.0`。
2. **微风不用随机数**，用两路不可公度的正弦（0.11Hz 与它的 2.71 倍）相加。
   理由和 DC53 同源：随机数会让"同一时刻"两次渲染结果不同，
   A/B 对照图、固定步长回放、金标准对拍全部失效。

实测（`/api/force` + 冻结时钟）：

| 场景 | 读数 |
| --- | --- |
| 风 `+0.3`（往右） | 发梢 `+40.9px`，**方向与风一致** |
| 风 `−0.3`（往左） | `−36.7px`，镜像 |
| 风归零后 2.5 秒 | 回到 `−4.4px`（静置位附近） |
| 阵风 `2.0 / 0.6s` | 峰值 `37.2px` → 3 秒后 `4.6px` |
| 常驻微风 `0.03` | 发梢 10 秒行程 `8.9px → 15.5px` |

留证 `logs/asset_qa/t47_3_wind.png`（左风 / 无风 / 右风 三连拍）。

> ★ 做这条的时候逮到一个**跨两次交付的老 bug**：摆角读数相对发梢真实偏向是反号的
> —— 像素空间 Y 轴向下，`atan2` 求的有号角相对官方（Y 轴向上）是镜像的。
> 画面表现就是"风往右吹、头发往左飘"。修法与为什么 855 条断言没拦住，
> 见 `DECISIONS.md` **DC79** 与 `LESSONS.md` **206**。

## 2. 官方到底怎么算的（第四十批查证，URL 见 `REFERENCE_NOTES.md`）

`.physics3.json` 的一条 "PhysicsSetting" 由四段组成：

```
Normalization（归一化：Position 与 Angle 各一组 -10 / 0 / 10 的三点）
  → Input[]    { Source: 参数ID, Weight(合计100), Type: X|Y|Angle, Reflect }
  → Vertices[] { Position, Mobility(揺れやすさ), Delay(反応速度),
                 Acceleration(収束の速さ), Radius(振り子の長さ) }   ← 粒子链
  → Output[]   { Destination: 参数ID, VertexIndex, Scale(倍率),
                 Weight, Type: Angle, Reflect }
Meta.EffectiveForces { Gravity: (0,-1), Wind: (0,0) }   ← 全局力，SDK 运行时可改
Meta.Fps = 60（Cubism 5 起默认 60）
```

**算法要点（和我们的差别全在这里）**：

1. **粒子是 2D 的**：每个粒子有位置向量，父粒子带着它走，`Radius` 约束它到父粒子的距离。
2. **输出是角度**：`outputValue = DirectionToRadian(parentGravity, translation)`，
   其中 `parentGravity` = 重力方向（或开"角度修正"时取前一段的方向）。
   ⇒ **摆往哪边歪、歪多少度**，不是"落后了几个像素"。
3. **重力常在**：默认 (0,−1)。所以哪怕输入完全不动，摆也有一个"被重力拉回"的平衡位置，
   任何扰动都会绕着它衰减振荡 —— 这就是"真实"的来源。
4. **输入类型三种**：`X` / `Y` / `Angle`。社区实测口径（黒猫レポート）：
   - **位置 X 输入** ⇒ 晃完**回到初始位置**；
   - **角度输入** ⇒ 晃完**停在输入对应的角度**（歪头时头发保持歪）；
   - 链式时第 1 段保持，第 2 段之后回 0。
5. **规格坑**：输入太小时振り子会**吸附到 0**（官方承认的特性）。
   官方给的回避：加大输入 / 把长度调长 / 混入 5~10% 的角度输入。
6. 编辑器那四个旋钮与物理量的对应：
   长さ=Radius（小→快、大→慢）、揺れやすさ=Mobility（**0.7~0.99**）、
   反応速度=Delay（1 为标准）、収束の速さ=Acceleration（1 为标准）。

## 4. 改造方案（T47，七步，每步独立可验收）

> 总原则沿用既有纪律：**新内核与旧内核并存一个版本**，旧配置照跑、
> 现有产物**一字节不变**；每步都要有 selfcheck 闸门 + 负向对照 + 一张 A/B 留证图。

### T47.1 粒子摆内核（`zphys2`）—— 这是整条线的地基

- 在 `zrig.c` 新增 2D 粒子链：`{pos, last_pos, vel, radius, mobility, delay, acceleration}`，
  重力/风为引擎级向量。算法照官方 `UpdateParticles`。
- `rig.json` 新增 `physics2` 段（旧 `physics` 原样保留）。
- **验收**：
  1. 先写 `tools/physics_ref.py`（同算法的 Python 参考实现），
     用同一组参数跑 600 步，和 C 实现**逐步对拍，最大误差 < 1e-6**；
  2. 旧 `physics` 全链路产物与改前**逐字节相同**（架构改造判据）；
  3. selfcheck 新闸：粒子链的 `mobility` 必须落在 0.7~0.99、`radius` 必须递减或持平。

### T47.1 已交付（2026-10-17 晚）—— 实测数字在这里

落点：`src/core/zphys2.{h,c}`（内核）、`tools/physics_ref.py`（Python 参考实现）、
`tests/data/phys2_golden.json`（600 步金标准）、`tests/test_core.c::test_phys2`（13 条断言）、
`selfcheck_repo.py::check_phys2`（6 道闸）。

**① 和参考实现逐步对拍**：同一组参数、同一份输入跑 600 步，
位置与摆角的**最大偏差 < 1e-6**（规划写死的口径）。
负向对照：把 `ZPHYS2_AIR_RESISTANCE` 从 5.0 动到 5.05（1%），
偏差立刻涨到 **1.138e-01 / 1.949e-01** —— 这道闸是有牙的。

**② "静止时还在动"——用户那句"没有真实的物理效果"的客观判据**
（4 粒子链，Radius 24/18/12，Mobility .95/.92/.88）：

| 阶段 | 输入 | 发梢摆角 |
|---|---|---|
| ① 0~3.3s | 转头 ±8px + ±6° | 峰值 **51.09°** |
| ② 3.4~4.4s | **输入彻底归零** | 峰值 **40.92°**（旧内核：恒 0） |
| ② 5.4~6.4s | 仍然归零 | 峰值 **2.62°**（在衰减，没有自激） |
| ③ 8~10s | 只剩呼吸 0.28Hz ±1.2px | 峰值 **1.00°**（旧内核：0.3px 滞后量≈不动） |

③ 段就是**旧内核最致命的地方**：输出滞后量时，0.28Hz 的慢输入摆锤完全跟得上，
差值≈0；输出摆角时，根一动角度就变 —— 社区那条"把呼吸混进物理输入，挂件就一直晃"的配方
从此在我们这儿也成立了。

**③ 重力方向**：把重力改成"右下 45°"后静置 10 秒，摆确实垂向右下
（末端相对父粒子 dx/dy 都为正），相对重力的摆角 < 2°。

**④ 固定步长不变性**（G113 的回归）：同样 2 秒，60fps 跑 120 帧 vs 15fps 跑 30 帧，
末端摆角差在同一量级且都不发散 —— 低帧率不会把惯性放大。

**本步刻意不做的事**：摆角还**没有**接到任何部件上（`rig.json` 一个字节没改，
旧 `physics` 35 条照跑），所以画面目前看不出变化。
把摆角翻译成切件 `rot` / 形变器 `amount` 是下一步 **T47.2**，
那一步做完才是"用户能看见头发自己在飘"。这样切是为了**先把地基钉死**：
内核对不对，用眼睛是看不出来的，只能靠对拍。

★ 和官方的一处有意偏离见 **DC77**（官方 `UpdateParticles` 那段旋转误用了被覆盖的
`direction.X`；本轮从 `api.github.com` 拉原文核对过，第四十四批）。

### T47.2 输出适配层（角度 → 我们的切件）

官方输出写的是"参数"，参数再驱动网格顶点。我们是**切件 + 网格形变器**，所以要一层翻译：
摆角 → ① 部件 `rot_deg`（整件旋转，适合耳朵/尾巴/呆毛）
      ② 形变器 `amount`（分段弯曲，适合长发/裙子）
      ③ `bend_x/y`（整件弯，适合兜帽这种贴头件）
带 `scale`（倍率）与 `max_output%`（对齐官方"最大输出"）。

- **验收**：长发 3 段换挂新内核后，
  ① 转头 A/B 的像素行程与旧版**同量级**（表 1.3 是基线）；
  ② **静止 10 秒时发梢仍有 ≥ 2 px 的自主摆动**（旧内核这里恒为 0）——
  这一条就是"真实物理"的客观判据，写成冒烟断言。

### T47.3 重力与风

- 引擎级 `gravity(x,y)` / `wind(x,y)`；调试端点 `/api/force?gx=&gy=&wx=&wy=`。
- 风接三个来源：① 环境微风（常驻、低频噪声）；② 情绪（生气＝阵风）；③ 场景事件（开窗/奔跑）。
- **验收**：风设为 (0.3, 0) 时长发整体偏移 ≥ 8 px 且**不抖动**；归零后 2 秒内回到静止姿态。

### T47.4 惯性输入（桌宠特有，**官方没有、BongoCat/VPet 也没有**）

拖动桌宠窗口、角色走动、被"甩"的时候，把**窗口/角色的加速度**注入重力方向（等效惯性力）。

- **验收**：模拟一次 200 px / 0.2 s 的拖动，发梢反向甩出 ≥ 12 px，松手后 1.5 s 内收敛到 < 1 px。

### T47.5 `physics3.json` 双向互通

- 导入：把官方文件翻成 `physics2` 配置（归一化、Input、粒子、Output 一一对应）。
- 导出：反向。round-trip 必须等价。
- **验收**：用一份公开样例（`VonPro/Live2D` 仓库里的 `physics.json` 等）跑解析→导出→再解析，三者等价。
  这条同时把 `LIVE2D_CONFORMANCE.md` 里"physics 参数化输出"那一行的坑填了。

### T47.6 布料（裙 / 外套 / 里布）

现在裙摆是**一条** `skirt_x` 推整块 `seg_torso` 的 bend。改成：
- 横向切 3~5 条链（左/中/右…），每条**相位差 0.05~0.12 s**、根部刚、梢部软；
- 接风；走路/转身时左右两侧反向。
- 教程口径（第三十八批）：上着は少し重い（幅度小）、裏地は腿后、裾は"のりしろ"。
- **验收**：转身 A/B 里裙摆左右两侧的峰值**不同帧**出现（证明有相位差），且里布不穿出表布。

### T47.7 碰撞 / 限位

- 给肩、胸、头顶几个软圆盘；粒子进入时按法线推出（软限位，不是硬反弹）。
- **验收**：把长发 ratio 调到 2 倍做压力测试，发梢不进入躯干剪影内部 ≥ 95% 的帧。

### 顺带要做的两件小事

- **`ParamBreath` 的幅度分档**：睡眠时慢而深、生气时快而浅（现在是一条固定正弦）。
- **摆的性能护栏**：粒子总数上限 + 低帧率自动降步（BANDORI-PET 那个 30→180 fps 的教训：
  渲染核心的开销会直接吃掉物理的步数预算）。

## 6. 不做的事（先写下来，免得被需求拖走）

1. **不做通用刚体/碰撞引擎**。只做"摆 + 软限位"，够用且可控。
2. **不做 3D**。我们的底座是 2D 切件，Live2D 官方也只做到伪 3D。
3. **不自己发明参数名**。摆的四个旋钮就叫 `radius / mobility / delay / acceleration`，
   和编辑器一一对应，这样教程里的数值可以**直接抄**（这是能不能用社区经验的分水岭）。
4. **不把旧内核立刻删掉**。两版并存一个版本周期，等所有部位迁完、A/B 全绿再删。

## 7. 验收总表（每一条都要能跑出来）

| 判据 | 口径 |
