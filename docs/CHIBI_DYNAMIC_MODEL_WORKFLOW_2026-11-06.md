# 无兽 Chibi 动态模型长工作流

## 目标及约束

在已有黑描边试装的隔离副本中制作真正由 C 运行时求值的分层动作，而不是仅显示静态图或整体旋转。保留桌宠、少女、有兽 Chibi、原无兽试装和清边试装。自研 zrig/PNG 不等于官方 Live2D Cubism 的 CMO3/MOC3；官方格式需官方编辑器与 SDK/许可。现有画稿是 AI 平面差分，不是完整分层 PSD，不能假设被遮挡画稿存在。

## 连续工作包与验收门槛

1. **资料与图层审视**：查官方素材拆分、参数关键形态及物理教程和开源项目；逐层放大看结构、缝线与底图。记录哪些操作需要未有的隐藏画稿。
2. **隔离素材与绑定**：建立单独模型目录，尝试从身体中拆左/右袖手，并添加可调肩部枢轴；所有像素可追溯且默认形态与源作像素对照，不覆盖前版。只在可验证范围内补必要底层，失败就保留为实验并写缺陷。
3. **参数和动作**：按 C 引擎真实格式制作呼吸、左右手、头部姿态、眼睑、口型和适用的摆动；不要把简单二维偏移说成三维转头，不用整眼图移动冒充独立虹膜。验证每个参数、组合与复位，提供操作界面。
4. **物理与运行**：结合引擎支持的实时物理配置，验证输入/输出真正驱动并稳定，不把静态正弦叫物理；如画稿或接口不足则明确阻塞，而不是伪造。检查头、肩、衣服、发梢连接及极值。
5. **动态视觉验收**：从真实 C 帧捕获不同参数、动作的静态、极值、中间态和循环序列，浅/深底和局部放大逐帧目视；测试、像素数字和动图不代替目视。无法接受的穿帮不进入正式模型，保留对照。
6. **工具链与回归**：提供可复现构建、控制/预览、可验证项目包和测试；校验源未变，测试真实 C 动作、参数、回零和保存恢复，记录版本、许可与已知缺陷。真实浏览器验收能做则做，不能做据实报告；不声称已经完成 PSD 编辑、纹理 atlas、双轴网格、正式 Live2D 格式或全部插件。
7. **交付与备份**：汇总成果与未完成项，运行相关回归和 `git diff --check`，提交并推送本会话分支，确认结果。

## 查阅资料

- Live2D 官方 [参数形态](https://docs.live2d.com/en/cubism-editor-manual/keyform-xydirection/)、[物理设置](https://docs.live2d.com/en/cubism-editor-manual/physical-operation-setting/)：参数关键形态与物理输入/输出分别验收；双轴组合并非旋转整张贴图。
- Inochi2D [首个模型教程](https://docs.inochi2d.com/en/latest/creator/first-model/index.html) 与 [节点布局](https://docs.inochi2d.com/en/latest/creator/first-model/tutorial02.html)：分层→节点父子结构→网格/参数/物理。参考思路，不复制素材或代码；其格式不是 Cubism 或本项目 zrig。

## 本次执行记录和结论

- **素材与隔离**：建立 `experiments/live2d_chibi_dynamic/` 和可复现生成器。人工多边形+连通域取出左右袖手；来源 rig/body 锁定 SHA-256，改变后拒绝重建。其余源贴图不变。原始平面合成逐像素一致，未动正式角色、桌宠或以前的试装。
- **目视迭代而不是掩盖失败**：第一版 ±5°、无底层时左右腋侧出现长缝、袖口和右拇指断开；修正手部连通域、缩小至 ±2°，只在原手臂遮住的完全不透明像素下，用相邻像素合成 4674 像素窄带。目视浅/深底和袖手放大图后缺陷减轻但仍有接缝及颜色拉伸，不能当作正式画稿。`qa/` 保存当前版本，不保存失败版为正式素材。
- **C 动作与物理**：新增头部倾斜/平移、左右袖手、呼吸、身体摆动、袖子物理输出参数及 6 个动作。固定步进的真实 C 帧测试了参数正负极值、中间态、归零、眨眼、嘴型和 5 个循环通道；不同时间帧的参数也实际变化。`ParamMotionDrive` 从 0 到 1 的一次测试中物理输出上冲约 0.0795、稳定约 0.05；归零后反向回摆约 -0.0186，最后归零。不是把预设正弦充当物理。
- **实测差异**：563×563 的 C 中立帧与 seam 试装仍有 301 个像素差异，集中在拆层边缘；虽然三层源 RGBA 合成完全一致，未达到中立 C 帧逐像素一致目标。参数变化和复位数值在 `qa/metrics.json`，它们不代替目视。
- **交互和浏览器**：动态专用面板在滑动时自动切换静止检查，保存快速连续输入的最终值并提供复位；用户可用动作按钮恢复循环。真实 Chromium 加载 UI、快速滑动及复位通过，截图见 `qa/browser_preview.png`。一次后续 Chromium 启动发生 SIGSEGV，重试通过；仍属于依赖沙箱环境的可选测试。
- **项目包**：通过自研 `.zproj` v1 打包、校验并解包，12 文件与 rig 内容往返；它不是 PSD、CMO3 或 MOC3，未将打包文件作为正式模型。
- **剩余阻塞**：需要原创可编辑的肩部和袖子隐藏底稿、独立眼球/眼白和合适网格；大幅度动作、真机 Windows、Cubism SDK/格式、成熟绑定器和插件体系均未完成。不要把该动态实验提升为成品。细节及复现步骤见 `experiments/live2d_chibi_dynamic/README.md`。

### 回归补充

- `make test-dynamic-chibi`：可复现构建、源与其他形态保护、模拟网络延迟下的滑块合并/复位/错误恢复、独立 C 帧和物理均通过；新增并修正了复位过程中在途请求可能丢弃复位后新输入的竞态。真实 Chromium 对最新页面复测通过。
- `make test`：2646 通过、0 失败，热加载因未构建示例模块而跳过；编辑器、项目包、黑描边和清边专项通过；Web 266/0，动作接口通过，旧正式 Chibi 有 3 条已知加载警告；`warncheck` 零告警。
- 额外运行 `scripts/selfcheck_all.sh` 时**未通过**：静态自检 772 项中，旧正式 teen/chibi rig 生成器指纹 1 项失败；正式 teen 素材机器验收 8 项失败（包括遮罩范围、白边、分段缺像素及 twin 侧发露背景），这些不是本试装产生的修复，也没有覆盖正式素材。此检查最初缺 Zig。随后隔离安装 ziglang `0.17.0.post0`，单独执行 `make win DIST_WIN=build/windows-cross` 已产生 AMD64 Windows PE；编译有 `zrig.c` 两条未使用参数警告，未做 Windows 真机运行，也未重跑整个耗时自检。
- 全量自检内部的 `make clean` 会删除旧 `build/` 与已跟踪 Windows 可执行文件：本次已恢复被删除的已跟踪文件，并重建此前各试装预览目录；后续不要把该脚本的输出重定向到会被删除的 `build/` 中。
