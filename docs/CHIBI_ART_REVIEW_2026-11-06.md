# Chibi 眼手关节继续修画与自检（未通过最终美术验收）

在 5256 的独立眼部候选基础上，针对「近闭褪色、笑眼、手指和关节」继续制作和逐帧自检。正式桌宠、少女和既有候选的画稿/rig 没有被覆盖。此轮预览为新的独立候选；下面的“改善”是实际 C 截图的观察，不等于用户认可或完整美术验收。

## 眼睛

- 去掉本候选虹膜/眼白的提前透明淡出，让颜色保留到遮罩遮住；遮罩略上移，虹膜也随闭合略上移。新增**可选** `eye_aperture_fast_close`：带 `eye_aperture` 的部件按 `min(blink / 0.9, 1)` 计算收口，0.9 达到 `aperture_min`；其他 rig 原样。半眨和近闭颜色不再像上一版那样整体漂白。
- 自检仍有问题：0.8–0.85 的虹膜只剩一条偏平的蓝色窄弧，0.85 附近还可见暗蓝细边；这不是与眼睑精确相切的完整遮挡。若单独移动遮罩、不加快收口，会在眼线上方露出蓝线，已拒绝（`qa/rejected_mask_v1_0.85.png`）。快速收口是权宜试验，会改变半眨几何，不应视为通用修复。
- 笑眼由先前的单条粗圆线换成与活动睫毛同一套细节轮廓。单独笑眼及左右单眼在 0.5、0.75、0.85、0.9、1 做了真实 C 采样；0.85 的双线较前减少。笑眼与独立眨眼叠加时，之前因两张图变形不同又产生灰影（`qa/rejected_smile_blink.png`）；现在笑眼使用同一套眼睑关键形态，0.85 笑眼 + 0.92 眨眼的对照见 `qa/smile_combo_0.85_0.92_light.png`。全闭的笑眼仍较简单，多个表情叠加和大角度尚未完成美术验收。
- `qa/auto_blink_slow.gif` 是最终候选自动眨眼逐步 C 抓取：21 个采样，GIF 合并相同帧，100ms/采样为刻意慢放，并非实际眨眼速度；原始闭合值在 `auto_blink_values.json`。图中也保留了固定阶段、视线、单眼和转头笑眼截图。

## 手指与关节

- 在两份独立可编辑手稿上，调整各指相对长度、扇开角度和拇指角度，左右略有区别；五指仍使用各自腕部子组及原来的 ±5° 小摆绑定。极值真实 C 图和手指动作段见 `qa/`。目前仍主要源于同一镜像手形：指间线偏平、极限姿态仍可能交叠；这不是两套完整的多姿态手原画，也不声称手部最终通过。
- 根据袖口切线处不透明袖幅中心，将左右肘旋转中心由 `[405,595] / [624,595]` 调到 `[400,595] / [621,595]`，补画两侧不同的袖内肘片，仍限制在中立上袖完全不透明的区域，确保静止不露补片。±4° 肘、±6° 腕及组合、小比例浅深底做了采样；大角度和完整肩袖隐藏画稿依然欠缺，切线/接缝不能判为彻底解决。
- 尝试加长腕部底稿时，手腕极值在袖口外露出一小块肤色（`qa/rejected_wrist_v6.png`），因此已撤销该尝试，保留上轮腕部素材；手腕仍需更完整的遮挡与修画。
- `finger_test_slow.gif` 和 `elbow_test_slow.gif` 各为动作的一小段 12 帧，C 每三步采一帧、以 150ms 播放，是约三倍慢放且循环处会跳回片段开头，**不是完整动作循环**。

## 复现、兼容与技术检查

依赖 Pillow、numpy、resvg-py 和新编译的 C 预览。路径必须是 `build/` 下尚不存在的新目录；预览服务无认证，不要放私人数据。

```sh
make build/zhuochong_preview
/home/user/.imgenv/bin/python tools/build_chibi_art_review.py build/my-art-review
/home/user/.imgenv/bin/python tools/capture_chibi_art_review.py build/my-art-review build/my-art-review-qa --auto
/home/user/.imgenv/bin/python tools/preview_live2d_chibi.py --dynamic --dynamic-study build/my-art-review --preview-root build/my-art-review-preview 5258
make test-chibi-art-review
```

`--auto` 会等待一次完整自动眨眼，逐 C 步采集可能耗时数分钟；省略它仍可采固定阶段和动作段。端口冲突时选其他端口。预览的眼开度/笑眼滑块可独立查看左右及组合：开度 1 睁、0 闭；拖动会固定自动眨眼，恢复自动请先点“静止并复位”，再点“自动眨眼”。新标签只影响显式启用它的 `eye_aperture`，旧 rig 的默认曲线不变；旧引擎无法识别本轮标签，因此加载试验包须使用带本轮代码的引擎。

- `make test`：2684 项通过、0 失败；新增 C 合成遮罩用例检查新旧开口、0.9 收口终点和单眼隔离。旧候选 8 个闭合度的 C 截图与变更前保留图逐像素一致。示例模块热加载和 Windows 真机未测。
- `make test-chibi-art-review`：隔离路径、上游画稿指纹、肘片遮挡、左右肘中立截图不变、十指/三关节变化、笑眼/眨眼合成表情、47 文件 `.zproj` C 帧往返通过；另有自然眼、合并候选、手口绑定回归和真实 Chromium 控件检查通过。数值只证明响应：十指从 −1 到 1 的差异为 109–198 像素，不能作为美术评分。
- 后续需按用户意见继续调整近闭遮罩与眼线的真实相切、细画独立左右手/指根遮挡、补全肩袖/腕隐藏画稿，并检查更广的动作与表情组合；任何方案都应在晋升前由人审看。
